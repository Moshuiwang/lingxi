# PRD: 飞书 Claude Code 对话体验治理

更新时间：2026-07-23

## 背景

BI Plus 飞书入口已经能把用户消息转给 Claude Code，并保持飞书话题内的 Claude session 续接。但真实试用暴露出几个产品级问题：卡片标题仍显示 Codex、结果卡片可能只展示查询范围不展示数据、用户指出问题后会出现空回复、图片和文档交付不符合飞书用户预期。

本 PRD 定义下一轮要达成的用户体验，不讨论底层 BI 指标准确率、不扩大到正式多用户权限隔离。

## 目标

让飞书里的 BI Plus 对话具备稳定的“问 -> 查 -> 看结果 -> 拿产物 -> 找回话题”闭环。

## 非目标

- 不提升模型分析能力。
- 不变更 MCP 权限隔离策略。
- 不新增 Web 端。
- 不把所有产物都做成复杂知识库；本轮只解决用户当前能看到的飞书交付体验。
- 不通过放宽用户 home、工作目录或其他用户目录权限来换取文件可读性。

## 用户故事

### US1: 看得懂当前卡片在干什么

作为飞书用户，我希望卡片标题展示业务主题和当前阶段，而不是显示错误的 Agent 名称或简单重复我的原话。

验收：

- 标题默认品牌名为 `BI Plus`。
- 标题摘要优先包含国家/公司、指标、时间范围。
- 标题不使用 `Codex:`。
- 状态不作为标题主体；状态在卡片底部显示。

### US2: 查询数据必须看到数据结果

作为飞书用户，我问“尼日利亚最近一周充值金额”时，完成态卡片必须展示金额数据、关键结论或明确追问，而不是只显示查询范围。

验收：

- 识别公司和时间范围只是中间态，不可直接完成。
- 完成态必须有非空用户可见正文。
- BI 查询完成态至少满足以下之一：
  - 展示结果表；
  - 展示摘要数字和趋势；
  - 明确告诉用户需要选择公司/指标/时间；
  - 明确说明查询失败并给出恢复入口。

### US3: 多公司匹配要有明确选择

作为飞书用户，我说“尼日利亚”时，如果系统匹配到 `Nigeria Corp.` 和 `Nigeria Solar Corp.`，我希望系统明确告诉我要选哪个，或清楚说明默认查哪个并继续给结果。

一期推荐交互：

- 默认不静默完成。
- 卡片展示：
  - `Nigeria Corp.`
  - `Nigeria Solar Corp.`
  - `两个都查`
- 如果产品为了减少打断选择“默认查主公司”，则必须继续展示主公司结果，并在结果后提示“还可继续查新能源”。

验收：

- 不允许只展示“匹配到两个公司，我先按 A 查”后完成。
- 用户说“继续”时，系统能继续未交付任务。

### US4: 空回复不能被标记为完成

作为飞书用户，我指出“你没有给我结果”时，希望系统补结果或解释失败，而不是收到“无文本回复”。

验收：

- `final_text` 为空时不能以成功完成卡片结束。
- 卡片展示统一兜底文案：
  - `刚才没有生成可见结果，我会重新补发上一次查询结果。`
  - 或 `刚才查询未完成，请重新选择公司范围。`
- 需要在日志/DB 里记录空回复原因。

### US5: 图片在飞书里可见或可打开

作为飞书用户，我让系统画图后，希望直接看到图或收到可打开文件，而不是服务器地址。

优先级：

1. 直接上传图片到飞书并在卡片展示。
2. 如果卡片展示受限，发送 PNG/SVG 文件。
3. 图文报告场景才生成飞书文档。

验收：

- 不出现 `/home/...`、服务器 IP、本地文件路径。
- 用户能在飞书里直接查看、打开或下载图片。

### US6: 文档只交付飞书文档

作为飞书用户，我让系统生成文档时，希望只收到一个飞书文档链接，并有简短说明。

验收：

- 默认不向用户发送 MD 文件。
- MD 可以作为内部中间格式，但不出现在用户云盘或消息附件中。
- 飞书消息格式：
  - 1-2 句说明；
  - 一个可点击飞书文档链接；
  - 利用飞书原生链接预览展示标题/摘要。

### US7: 话题列表预览能找回上下文

作为飞书用户，我回到话题列表时，希望预览里能看到业务主题，而不是只看到“已完成，用时 xx 秒”。

验收：

- 话题/卡片摘要优先是业务主题：
  - `BI Plus: 尼日利亚近 7 天充值`
  - `BI Plus: 乌干达收入趋势`
  - `BI Plus: 尼日利亚充值报告`
- `已完成`、`用时` 只作为正文底部状态。

### US8: 私有工作目录里的文件只发给本人

作为飞书用户，我希望系统能把我在私有工作目录中生成的文件发回当前飞书账号，同时其他用户不能读取或收到该文件。

验收：

- 用户可发送自己运行身份已经能够读取、且通过敏感文件校验的普通文件。
- 不修改用户 home 和工作目录的私有权限；文件先经受信任 helper 复制到该用户的一次性交付区，文件服务只从交付区读取。
- 文件服务根据 Unix socket 的真实 peer UID 确定执行用户，再通过数据库唯一绑定确定飞书收件人；请求不能指定或覆盖 UID、用户名、`open_id` 或其他收件人字段。
- 真实源路径仍须通过 home 边界、软链、敏感文件名、普通文件和大小校验；客户端自行复制或改名不能替代服务端校验。
- 一次性交付文件无论成功、失败或送达状态未知都不自动重发，并按清理合同移除；用户会收到明确回执。
- 交付区只允许 `bi-ai-service` 服务组列举和清理过期副本；文件服务是唯一按交付合同消费和发送副本的组件。普通业务用户仍不能进入或列举，且不得因此修改任何用户 home 或工作目录权限。
- 其他用户、未绑定用户和 disabled 用户不能消费或发送该交付区的文件。

## 优先级

| 优先级 | 问题 | 原因 |
|---|---|---|
| P0 | BI 查询无结果却完成 | 阻断核心查询体验 |
| P0 | 空回复仍显示完成 | 破坏信任，用户无法恢复 |
| P0 | 图片不可打开 | 生成物交付失败 |
| P0 | 文档重复交付 | 用户不知道哪个是最终文档 |
| P0 | 私有工作目录文件无法发送 | 用户生成了产物但拿不到，且不能以放宽目录权限修复 |
| P1 | 标题显示 Codex | 来源认知错误 |
| P1 | 标题重复原话 | 历史卡片不可读 |
| P1 | 话题列表预览不可读 | 历史上下文难找回 |

## 一期范围

一期必须完成：

1. 卡片品牌名从 `Codex` 改为 `BI Plus`。
2. completed 卡片非空结果校验。
3. BI 查询类结果交付 guardrail。
4. 多公司匹配的明确选择/默认策略。
5. 文档交付只发飞书文档。
6. 图片交付不再暴露服务器路径。
7. 话题标题/卡片标题摘要规则。
8. 私有文件通过受信任的一次性交付区发回同一用户，不开放 home 权限。
9. 对上述能力建立测试和真实飞书 smoke。

## 成功指标

- 尼日利亚近 7 天充值金额：第一次提问即可看到数据表或选择入口。
- 用户说“继续”：继续未完成任务，不说“结果已经给出来了”。
- 用户说“你没给我结果”：补结果或说明失败，不返回空卡。
- 图片和文档交付不出现服务器路径或重复文件。
- 私有工作目录文件可由原用户收到，跨用户、敏感文件和非交付区访问均被拒绝。
- 飞书话题列表能看出业务主题。

## 失败兜底

任何异常都必须有用户可读文本：

- 查询失败：`这次查询没有完成，我需要重新确认公司/指标/时间。`
- 结果为空：`没有查到数据，请确认公司和时间范围。`
- 产物上传失败或状态未知：明确告知本次未确认送达，并要求先核对飞书；不得自动重发。
- CardKit 更新失败：普通文本补发完整结果。
