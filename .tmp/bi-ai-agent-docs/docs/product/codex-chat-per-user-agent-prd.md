# PRD：Codex Chat 多 Agent 支持 + 体验优化

> 状态：历史归档。产品已决定不再提供 Codex；当前飞书查询只保留 Claude 路径（2026-07-22）。下文不是当前生产部署、验收或排障指引。

## 背景

本次迭代包含三个方向：

1. **多 Agent 支持**：不同飞书账号可对接不同 AI Agent（Codex CLI / Claude Code），在各自的 Linux 工作目录下运行
2. **状态行下沉**：对话卡片"正在思考/已完成"状态信息固定显示在卡片内容最下方，解决用户滚屏后看不到状态的问题
3. **审批/权限流程消息合并**：审批通过、开户、权限撤销等流程的多条独立飞书消息，改为单张动态更新的进度卡片

---

## 需求一：多 Agent 支持

### 背景
当前 Codex Chat 的 CLI 路径和工作目录是全局环境变量，所有用户共用一套配置。不同用户需要在各自的 Linux 家目录下运行不同的 AI Agent。

### 核心需求

| 编号 | 需求 | 优先级 |
|------|------|--------|
| R1 | 每个授权用户可独立配置 AI Agent 类型（provider） | P0 |
| R2 | 每个用户可独立配置 AI Agent 启动工作目录（cwd） | P0 |
| R3 | 支持 Codex CLI 和 Claude Code 两种 Agent | P0 |
| R4 | 现有用户行为不变（向后兼容） | P0 |
| R5 | 管理员通过直接写 DB 完成用户配置（无需 UI） | P1 |

### 验收标准
1. 飞书账号「四达文档会议助手」发消息 → 触发 Codex CLI，cwd 为 `/home/wangzhipeng/projects/bi-ai-agent`
2. 飞书账号「王志鹏」（wangzp Linux 账号）发消息 → 触发 Claude Code，cwd 为 `/home/biai-agent/users/wangzp/bi-agent-work`
3. 未授权用户仍走申请权限流程，不受影响
4. 两个账号同时活跃时，各自的会话数据互相隔离（隔离粒度：数据库 user_id + cwd 隔离；不做 OS 用户级进程隔离）

### 不在范围内
- 用户自助修改 Agent 配置的 UI
- 第三方 AI Agent（非 Codex CLI / Claude Code）
- Agent 进程资源限制与并发控制
- OS 用户级进程隔离（cwd 隔离已满足当前需求）

## 需求二：状态行下沉

### 背景
当前流式对话卡片的"正在思考…"/"已完成·用时X秒"状态文字显示在卡片**标题区**（顶部）。用户在阅读长回答时会滚屏到底部，此时标题区已不可见，看不到完成状态和 token 消耗。

### 需求
- 将状态行从卡片标题区移动到卡片**内容区最底部**
- 状态行内容不变：思考中显示"正在思考…"，完成后显示"已完成·用时X秒（输入: N tokens，输出: M tokens）"
- 标题区恢复为用户提问的摘要（不含状态前缀）

### 验收标准
1. 用户发送一条消息后，卡片底部持续显示"正在思考…"
2. 回答完成后，卡片底部更新为"已完成·用时X秒"及 token 数
3. 回答内容在状态行上方，不会随回答增长而推走状态行

---

## 需求三：审批/权限流程消息合并

### 背景
当前审批通过后，Bot 会依次发送多条独立飞书消息（如"正在创建账号…""SSH 已配置""MCP 已写入""邮件已发送"），每条独立推送，体验零散，且用户无法知晓整体进度。

### 需求
- 审批通过后，发送**一张进度卡片**，随流程推进逐步更新内容（步骤完成 → 追加 ✓ + 状态文字）
- 全部完成后，卡片显示最终完成状态
- 权限撤销流程同样适用
- 出错时，卡片显示失败步骤和错误原因

### 验收标准
1. 管理员点击"通过"后，用户收到一张进度卡片（不是多条文字消息）
2. 卡片随开户步骤推进逐步更新，最后显示"开通完成"
3. 权限撤销时，同样只发一张更新式卡片
