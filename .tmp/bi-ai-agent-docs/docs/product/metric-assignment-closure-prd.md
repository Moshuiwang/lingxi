# BI Agent 指标分配闭环 PRD

## 1. 背景

准入巡检已经能发现 MCP 新指标、未分配职责指标，并把结果推送到飞书审批群。后台也已经具备维护入口，可以把指标绑定到某个职能并触发权限发布。

当前缺口是：管理员看到巡检结果后，仍需要离开飞书，让运维用脚本处理。后续指标会持续新增，这个动作必须沉淀成审批群内可查询、可分配、可审计的闭环。

## 2. 成功标准

- 管理员在审批群可以查询全部指标分配状态。
- 管理员能一眼看到哪些指标还没有分配到任何普通职能。
- 管理员可以通过飞书卡片把未分配指标分配给某个职能。
- 分配提交后立即触发权限发布，让已获批用户无需重新申请即可看到新指标。
- 分配动作必须有审计记录，能回答“谁在什么时候把哪些指标分给了哪个职能”。
- 下一轮准入巡检不再重复提醒已完成分配的指标。

## 3. 用户角色

| 角色 | 需要完成的事 |
|------|--------------|
| 审批群管理员 | 查询指标状态、发起指标分配、确认发布结果 |
| 业务负责人 | 决定指标应该给运营、财务、技术等哪个职能 |
| 已获批用户 | 不重新申请，也能在权限更新后看到自己职能新增的指标 |
| 运维/开发 | 排查发布失败、追溯审计记录、处理异常状态 |

## 4. 功能范围

本期做：

1. 指标查询命令
   - 审批群命令直接返回一条可读性强的文字消息。
   - 文字消息列出所有 MCP 当前暴露指标。
   - 每个指标展示已绑定的职能。
   - 单独展示尚未分配到普通职能的指标。

2. 指标分配命令
   - 审批群命令生成一张分配卡片。
   - 先选择职能。
   - 再从当前未分配指标中多选指标。
   - 点击提交后写入 `function_metrics`，并立即发布权限。

3. 审计与结果反馈
   - 成功、失败、部分成功都必须给管理员明确反馈。
   - 每次分配动作记录操作者、目标职能、指标列表、发布结果。
   - 权限发布失败时，分配结果已落库，但管理员必须看到“发布失败，可执行既有命令 `@Bot 重试权限发布`”的状态。

本期不做：

- 不让普通用户发起指标分配。
- 不自动决定指标归属。
- 不把指标分配结果推给所有用户，只在他们查询指标列表时自然生效。
- 不替代独立审计项目的查询行为审计；这里只记录准入配置变更。

## 5. 指标查询功能

### 5.1 命令

审批群内：

```text
@Bot 查看指标分配
```

可接受别名：

```text
@Bot 查看指标
@Bot 指标分配状态
```

命令必须只在审批群或显式测试群生效。私聊或普通群不返回内部指标状态。

### 5.2 文字回复内容

查询使用文字回复，不使用卡片。原因是管理员只需要快速看状态，卡片会增加实现和维护成本。

文字标题：

```text
BI 指标分配状态
```

内容分三段，优先突出待处理项。

第一段：摘要。

```text
BI 指标分配状态

当前 MCP 指标：4 个
未分配指标：0 个
快照时间：2026-06-12 10:00
```

第二段：未分配指标。

```text
未分配指标
暂无
```

如果存在未分配指标：

```text
未分配指标 2 个
1. sub_arpu / ARPU
2. sub_refund_money / 退款金额
```

第三段：所有指标与已绑定职能。

```text
全部指标

1. sub_recharge_count / 充值用户数
   已绑定：运营

2. sub_recharge_money / 充值金额
   已绑定：运营

3. sub_deduction_count / 扣费用户数
   已绑定：运营

4. sub_deduction_money / 扣费金额
   已绑定：运营
```

底部给出下一步命令：

```text
如需处理未分配指标，请发送：@Bot 分配指标
```

### 5.3 展示口径

- 指标来源：最新 MCP 指标快照。
- 职能来源：`function_metrics`。
- “未分配”定义：指标存在于 MCP 快照，但没有绑定到任何普通职能。
- `全部` 职能不算普通职能；只绑定到 `全部` 时仍应提醒业务确认普通职能归属。
- 如果指标快照过期，文字回复必须显示“指标快照过期，暂不可判断”，不能展示旧结果当作当前状态。

## 6. 指标分配功能

### 6.1 命令

审批群内：

```text
@Bot 分配指标
```

可接受别名：

```text
@Bot 绑定指标
```

命令返回一张交互卡片。

### 6.2 卡片第一步：选择职能

卡片标题：

```text
分配 BI 指标
```

字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| 职能 | 单选下拉 | 运营、财务、技术、销售、商务、广告、市场 |

不提供 `全部` 作为默认选项。`全部` 权限影响面太大，后续如需支持必须单独加二次确认。

管理员在同一张卡片里先选择职能，再选择指标。前端展示顺序是“先职能、后指标”，不需要拆成两张卡片。

### 6.3 卡片第二步：选择未分配指标

字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| 指标 | 多选下拉 | 仅展示当前未分配指标 |

指标选项展示：

```text
sub_recharge_money / 充值金额
sub_deduction_count / 扣费用户数
sub_deduction_money / 扣费金额
```

如果没有未分配指标：

```text
当前没有未分配指标
```

提交按钮禁用或隐藏。

### 6.4 提交确认

提交前，卡片内展示当前选择摘要：

```text
确认分配

职能：运营
指标：
- sub_recharge_money / 充值金额
- sub_deduction_count / 扣费用户数

影响：所有已登记公司下持有“运营”职能的用户，权限发布后可看到这些指标。
```

按钮：

| 按钮 | 行为 |
|------|------|
| 提交分配 | 写入映射并发布权限 |
| 取消 | 关闭流程 |

### 6.5 提交后的用户体验

成功：

```text
已完成指标分配

职能：运营
新增指标：2 个
影响公司：45 个
权限发布：已完成，updated=4

下一轮巡检不会再提醒这些指标未分配。
```

幂等成功：

```text
无需重复分配

所选指标已经绑定到运营，未产生新变更。
权限发布未触发。
```

发布失败：

```text
指标分配已记录，但权限发布失败

用户暂时可能还看不到新指标。
系统会由 timer 重试，也可在审批群执行 @Bot 重试权限发布。
```

`@Bot 重试权限发布` 是现有审批群命令，不属于本功能新增命令；本功能只在失败提示里复用它作为兜底入口。

失败：

```text
指标分配失败

原因：指标快照已过期 / 指标已不在 MCP 返回中 / 职能不支持
```

## 7. 权限生效规则

分配动作写入的是“公司 + 职能 + 指标”映射。

默认作用范围：

- 对所有已登记公司生效。
- 对北京/总部这类 `access_all` 公司也生效。
- 对已获批且持有该职能的用户立即参与下一次权限发布。
- 用户无需重新申请。
- 巡检消项以 `function_metrics` 实时重算为准；写入映射后，下一轮巡检不再依赖额外人工状态标记。

后续如果需要更细粒度，可以扩展为：

- 只分配给指定公司。
- 指标分配时选择公司范围。
- 对敏感指标增加二次确认或审批人双确认。

## 8. 审计要求

### 8.1 审计事件

每次分配提交必须记录一条准入配置审计事件。

建议事件名：

```text
metric_assignment
```

字段：

| 字段 | 说明 |
|------|------|
| actor_open_id | 操作者飞书 open_id |
| actor_name | 操作者名称，如可取到 |
| chat_id | 操作发生的审批群 |
| action | `assign_metric_to_function` |
| function | 目标职能 |
| metric_keys | 本次提交的指标列表 |
| companies_count | 本次影响的公司数量 |
| created_count | 新增映射数量 |
| existing_count | 已存在映射数量 |
| publish_status | `success` / `failed` / `skipped` |
| publish_result | `created / updated / deleted` 或失败原因 |
| source | `feishu_card` / `feishu_command` / `cli` |
| request_id | 本次卡片/命令请求 ID，用于幂等 |
| created_at | 操作时间 |

### 8.2 审计边界

- 本仓库只记录准入配置变更。
- 用户后续查询这些指标的行为，由独立审计项目负责。
- 审计记录不得保存 MCP token、飞书密钥或任何用户私钥。
- 审计详情可以记录指标 key 和职能，因为这是权限配置事实，不是查询结果数据。

### 8.3 幂等与重复点击

同一张卡片重复提交时：

- 不重复插入 `function_metrics`。
- 不重复制造多条“新增映射”。
- 审计中可以记录重复提交，但结果应标记为 `idempotent` 或 `existing_only`。
- 卡片最终状态只保留最新一次结果。

## 9. 模块边界

| 模块 | 职责 |
|------|------|
| `app/services/admission_health.py` | 继续负责巡检和未分配指标识别 |
| `app/services/metric_assignment.py` | 负责指标分配的 owner 逻辑，CLI、命令、卡片都复用它 |
| `app/services/permission_publish.py` | 分配后立即发布权限 |
| `app/services/admin_command_flow.py` | 审批群中文命令入口 |
| `app/feishu/v2_handlers.py` | 飞书事件分发和卡片回调接线 |
| `app/feishu/cards.py` | 生成分配卡片；查询状态使用文字回复 |
| `scripts/assign_metric_to_function.py` | 运维兜底 CLI，不作为长期主入口 |

`scripts/start_bot.py` 不承载指标分配业务规则，只做入口编排和分发。

## 10. 异常处理

| 场景 | 处理 |
|------|------|
| 指标快照过期 | 查询文字提示不可判断；分配卡片不允许提交 |
| 未分配指标为空 | 查询文字展示“暂无”；分配卡片不展示提交按钮 |
| 提交时指标已被别人分配 | 幂等处理，提示已存在 |
| 权限发布锁被占用 | 告诉管理员“发布任务正在执行，请稍后或等待 timer” |
| 权限发布失败 | 显示分配已落库、发布失败；保留审计，等待重试 |
| 飞书卡片更新失败 | 后台结果不回滚；在群里补发文字结果 |
| 非管理员操作 | 拒绝，并提示仅审批群管理员可操作 |

## 11. 验收标准

1. 审批群发送 `@Bot 查看指标分配`，收到文字回复，能看到所有指标、已绑定职能和未分配指标列表。
2. 存在未分配指标时，审批群发送 `@Bot 分配指标` 能打开分配卡片。
3. 选择“运营”并多选未分配指标后提交，后台新增映射并立即发布权限。
4. 同一张卡片重复提交，不重复新增映射。
5. 分配完成后再次查询，未分配列表减少或清空。
6. 下一轮准入巡检不再推送这些指标的未分配提醒。
7. 用一个已获批运营用户执行 `list_metrics`，能看到新指标。
8. 审计记录能查到操作者、职能、指标、影响公司数和发布结果。
9. 权限发布失败时，管理员看到明确失败原因和重试入口。

## 12. 分阶段实施

### Phase 1：命令 + 文字查询

- 增加 `@Bot 查看指标分配`。
- 输出指标状态文字回复。
- 不修改权限。

### Phase 2：卡片分配

- 增加 `@Bot 分配指标`。
- 同一卡片内选择职能、多选未分配指标、确认摘要并提交。
- 复用 `metric_assignment` 服务写入映射。
- 提交后立即发布权限。

### Phase 3：审计与验收

- 记录完整准入配置审计。
- 补自动化测试和测试群 live run。
- 用真实审批群做一次人工验收。

### Phase 4：敏感指标增强

- 对金额、扣费、利润等敏感指标增加二次确认。
- 支持按公司范围分配。
- 支持“暂不开放 / 忽略本轮提醒”状态。
