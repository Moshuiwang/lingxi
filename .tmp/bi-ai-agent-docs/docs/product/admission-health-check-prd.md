# BI Agent 每小时准入巡检 PRD

## 1. 背景

当前用户申请的是“公司 + 职能”，MCP 真正执行的是 `company_id + metric_key`。当 MCP 新增指标后，如果没有人把新指标绑定到对应职能，已经获批的运营、财务等用户不会自动获得该指标。

这不是用户重新申请的问题，而是“新指标上线后缺少归属确认和权限重发闭环”。短期需要把这个缺口变成审批群可见、可处理的准入巡检。

## 2. 成功标准

- 北京时间工作时段内，每小时检查一次准入健康。
- 发现新指标、删除指标、指标描述变化、未分配职责指标时，只在有变化或待处理项达到提醒间隔时推送审批群。
- 发现账号准入异常时，推送审批群，管理员能一眼知道哪个用户为什么“已批准但用不了”或“已禁用但仍残留风险”。
- 指标待分配和账号健康异常属于同一个巡检任务，但用不同卡片/消息表达，不混进独立 audit 小时报告。
- 巡检只读检查，不自动放权；只有管理员/业务明确把指标绑定到职能后，才触发权限重发。

## 3. 用户角色

| 角色 | 关心的问题 |
|------|------------|
| 审批群管理员 | 有没有新指标需要分配职责；有没有账号批准后不可用 |
| 业务负责人 | 新指标应该给运营、财务、全部，还是暂不开放 |
| 已获批用户 | 自己被批准后能正常查到应有指标，不因为后台缺配置而查不到 |
| 开发/运维 | 巡检失败可定位，不误判为 audit 安全事件 |

## 4. 范围

本期做：

1. 指标准入巡检
   - 用全量权限账号的 MCP `list_metrics` / `describe_metric` 结果作为当前可暴露指标快照。
   - 识别新增指标、删除指标、指标描述变化。
   - 识别“已存在于 MCP，但没有绑定任何普通职能”的指标。
   - 推送审批群，提醒业务确认指标归属。

2. 账号准入巡检
   - 已批准用户缺 MCP token。
   - 已批准用户有公司/职能，但展开后没有任何可查指标。
   - 已批准用户未出现在权限发布副本中。
   - disabled 用户仍有权限发布残留。
   - 用户持有“全部”或“北京/总部”高权限，作为复核提醒。

3. 通知策略
   - 北京时间工作日工作时段每小时执行。
   - 无变化且无待处理项时不推送。
   - 指标问题和账号问题分两类消息推审批群。
   - 同一指标、同一种指标问题持续存在时，每 24 小时最多提醒一次，避免审批群被刷屏。

本期不做：

- 不自动把新指标分配给运营/财务。
- 不替代 audit 项目的异常行为审计。
- 不做复杂管理后台。
- 不在飞书卡片上直接修改权限，第一版可以先给出处理建议和 CLI/脚本入口。

## 5. 用户体验

### 5.1 新指标待分配

审批群收到一条独立消息：

```text
发现 3 个 BI 指标待分配职责

1. sub_recharge_money / 充值金额
   当前状态：未绑定任何职责
   建议动作：确认开放给运营、财务、全部，或暂不开放

2. sub_deduction_money / 扣费金额
   当前状态：未绑定任何职责
   建议动作：确认开放职责
```

管理员看到这条消息后，应该知道这是“指标归属待确认”，不是用户权限申请，也不是安全告警。

### 5.2 账号健康异常

审批群收到另一类消息：

```text
BI Agent 账号准入异常 2 项

1. user@example.com 已批准但没有 MCP token
   用户体验：用户登录后无法通过 MCP 鉴权查数
   建议动作：重新发布/补签 token

2. ops@example.com 已批准 Rwanda / 财务，但没有展开出任何指标
   用户体验：用户以为有权限，但 list_metrics 为空
   建议动作：确认 Rwanda / 财务 是否应绑定指标
```

### 5.3 高权限复核

高权限不是错误，但应该定期提醒：

```text
高权限复核提醒

- hq@example.com：北京/总部 + 全部
- admin@example.com：Uganda + 全部

这类用户会自动获得对应范围内的新指标，请确认仍符合审批预期。
```

## 6. 巡检与 audit 的关系

准入巡检和 audit 不合并。

| 项目 | 准入巡检 | audit |
|------|----------|-------|
| 目标 | 用户获批后能正常、合规使用 | 发现异常行为、越权尝试、敏感操作 |
| 消息对象 | 审批群管理员/业务负责人 | 安全/审计负责人 |
| 典型消息 | 新指标未分配职责、账号缺 token | 某用户异常查询、导出、SSH 行为 |
| 处理动作 | 补配置、补映射、重发权限 | 排查、阻断、追溯 |

它们可以都按小时跑，但消息、状态和处理动作必须分开。

## 7. 调度

默认北京时间工作日工作时段：

- `09:00-19:00`
- 每小时一次
- 周一到周五自动执行
- 非工作时段或周末不主动推送，除非手工执行

后续可通过环境变量调整：

- `ADMISSION_HEALTH_ENABLED`
- `ADMISSION_HEALTH_METRIC_SNAPSHOT`
- `ADMISSION_HEALTH_APPROVAL_CHAT_ID`
- `ADMISSION_HEALTH_TZ`
- `ADMISSION_HEALTH_START_HOUR`
- `ADMISSION_HEALTH_END_HOUR`
- `ADMISSION_HEALTH_REMINDER_HOURS`
- `ADMISSION_HEALTH_MAX_SNAPSHOT_AGE_HOURS`

## 8. 验收标准

- 构造 MCP 指标快照新增 `sub_test_metric`，巡检能识别“新指标 + 未绑定职责”。
- 将 `sub_test_metric` 绑定到 `运营` 后，下一次巡检不再报未绑定，权限发布后已有运营用户能看到该指标。
- 构造 approved 用户缺 token，巡检能推账号异常。
- 构造 approved 用户有职能但展开为空，巡检能推账号异常。
- 无变化、无异常时不推送审批群。
- 指标快照超过 2 小时时，不允许静默输出“无变化”，必须提示巡检不可用。
- 巡检失败不影响 bot 主流程和权限发布主流程，只记录失败并下次重试。
