# 用户机器人私聊路由表数据库方案

> 日期：2026-06-10
> 状态：方案
> 关联产品文档：`docs/product/private-chat-routing-prd.md`

## 一、结论

本期不新增数据库表、不新增字段、不做数据迁移。

原因：私聊路由表只是入口分发规则，命中后复用已有申请权限流程；未命中只发送提示文案，不产生业务状态。

## 二、现有数据使用

命中 `申请权限` 后，仍由现有申请流程读取和写入数据：

| 数据对象 | 用途 | 本次是否改变 |
|---|---|---|
| 用户记录 | 判断用户身份、已有授权状态 | 不改变 |
| 审批申请记录 | 提交申请后生成或更新审批状态 | 不改变 |
| 权限记录 | 判断当前已有公司/职能权限 | 不改变 |
| 审计/日志记录 | 继续沿用已有流程的记录方式 | 不改变 |

未命中私聊不写入这些业务数据。

## 三、不落库的内容

本期不记录：

- 用户说错了什么。
- 路由命中次数。
- 未命中次数。
- 推荐文案曝光次数。

这是为了让本次改动保持轻量，避免为了一个入口提示引入新的隐私和数据治理问题。

## 四、未来可选数据

如果后续要优化入口体验，可以另立小需求收集匿名统计：

| 可选数据 | 价值 | 前置条件 |
|---|---|---|
| 未命中文本分类 | 判断是否要支持更多入口说法 | 明确隐私边界和脱敏规则 |
| 路由命中次数 | 看申请入口使用频率 | 有统一事件埋点方案 |
| 未命中后是否再次说 `申请权限` | 衡量引导文案是否有效 | 有用户行为统计口径 |

这些都不是本期上线条件。

## 五、验收口径

数据库验收只确认两点：

1. 私聊未命中不会产生申请记录。
2. 私聊命中 `申请权限` 后，数据变化与原 `申请权限` 流程一致。
