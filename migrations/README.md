# 迁移目录约定

> 2026-08-05 随 #16 正式化整理（PR #48 独立复查的阻塞项修复）。

## 生产迁移链（`migrations/*.sql`）

顶层编号 SQL 是**正式表结构的唯一来源**，必须能在一个空库上按编号顺序整体前滚；
`scripts/ci/verify_repository.sh` 在有测试容器时会实际执行这条链（空库 → 逐个应用 →
失败即门禁红），防止再次出现「目录里混着互相冲突的建表脚本但 CI 全绿」。

当前链：`006`（专用授权主体登记；凭据本体按 2026-08-05 选项 A 决策存宿主机文件，不入库）→ `007`（组织快照）→ `008`（统一用户记录，依赖 006，
文件内有硬依赖断言）。#17 的 S3 切片合并后追加 `010`–`012`（银河权限落库）。
编号有意留洞：`009` 预留给身份切片的补充迁移，`004` 历史上未使用。

Alembic 按开发计划属 S11；届时本目录按[数据库设计「十一、迁移约定」](../docs/技术设计/数据库设计.md)
转换，本 README 随之替换。

## 测试资产（`migrations/testing/*.sql`）

`001` / `002` / `003` / `005` 服务于 Bot-Test 受控验证与既有测试
（[代码框架第五节](../docs/技术设计/代码框架.md)），其中 `001`/`003`/`005` 已分别被
`008`/`006`/`007` 取代，`002` 所属的浏览器 OAuth 路径已被 2026-07-28 决策排除。
它们**不属于生产链**、不参与顺序前滚检查，仅供 `tests/test_identity_postgres.sh`、
`tests/test_refresh_token_postgres.py` 与 `scripts/sync_feishu_org_snapshot.py` 使用；
何时整体废弃随对应测试资产的清退一起决定。
