# 技术设计

本目录记录 Lingxi 的实现方案：架构如何组织、接口长什么样、数据怎么存。

## 与产品合同的分工

| | 产品合同 | 技术设计 |
|---|---|---|
| 回答 | 用户体验是什么、边界在哪、承诺什么 | 用什么架构、接口、数据结构实现它 |
| 变更触发 | 产品承诺或边界改变 | 实现方案改变 |
| 冲突时 | **以产品合同为准** | 按合同修正设计 |

技术设计**不重复合同正文**。需要引用某条规则时给出链接和章节名，不复制条文——同一段规则维护在两处，迟早会改一处漏一处。

技术设计也**不是能力证明**。文档写完不代表能力可用；实际可用能力以[当前能力](../当前能力.md)为准。

## 文档

| 文档 | 内容 |
|---|---|
| [架构设计](架构设计.md) | 约束前提、架构风格、技术栈选型、执行层、核心机制、参考实现、部署与容量 |
| [接口设计](接口设计.md) | 信任边界、通用约定、飞书出入站、问数 MCP、管理 MCP 工具定义、内部交付接口 |
| [数据库设计](数据库设计.md) | 表结构与约束、状态机、分区与保留、数据库角色权限、迁移约定 |
| [验证与门禁](验证与门禁.md) | 证据层级、四道关口、关键机制验收矩阵、否定测试、AI 开发的前置动作 |

前三份共享同一组[约束前提](架构设计.md#一约束前提)。**前提变化时一起复审**，不要只改其中一份。

[验证与门禁](验证与门禁.md)是横向的：它为前三份里的每个机制指定"什么算验证通过、由哪道关口强制"。新增机制时同步补充其验收断言，否则该机制默认无人把关。
