## 一、接口全景与信任边界

| # | 接口 | 方向 | 信任级别 | 承载 |
|---|---|---|---|---|
| 1 | 飞书事件与卡片回调 | 入站 | **不可信**，必须验签 | 长连接 |
| 2 | 飞书开放平台 API | 出站 | 可信外部 | HTTPS |
| 3 | 问数 MCP | 出站 | 可信外部，但**不承担其正确性** | MCP 客户端 |
| 4 | 管理 MCP（**目标形态，尚未实现**，触发式未来入口，见「六」） | 提供方 | **按管理员个人身份鉴权** | Streamable HTTP |
| 5 | 内部交付接口 | 入站 | **半可信**：调用者是用户环境内的 Agent | Unix domain socket |
| 6 | ~~内部问数 MCP 代理~~ | — | **不实现**（2026-08-17 裁定：令牌改落用户环境 `.mcp.json`，见 7.2） | — |
| 7 | 领域服务 | 进程内 | 可信 | Python 函数调用 |

**关键判断**：#5 只信任**连接来源的操作系统身份**（见[七、用户环境的接口](#七用户环境的接口)）。#6 已取消，判断变成一条**落盘纪律**，见 7.2。

## 二、通用约定

### 标识符

| 前缀 | 含义 | 示例 |
|---|---|---|
| `usr_` | Lingxi 内部用户标识 | `usr_01HXYZ...` |
| `cnv_` | 对话（私聊主窗口或话题） | `cnv_01HXYZ...` |
| `tsk_` | 任务 | `tsk_01HXYZ...` |
| `pac_` | 待确认操作 | `pac_01HXYZ...` |
| `rev_` | 开通运行异常记录 | `rev_01HXYZ...` |

统一使用 ULID（时间有序、可排序、无需协调）。**飞书侧标识（`open_id` / `user_id` / `union_id` / `chat_id`）永不作为内部主键**，只作为关联字段——它们属于外部系统，语义可能变化。

### 时间

全部使用 `TIMESTAMPTZ`，存储与传输一律 UTC，仅在面向用户的文案里转换为本地时区。

### 错误模型

所有内部接口与管理 MCP 工具返回统一信封：

```json
{
  "ok": false,
  "error": {
    "code": "target_state_changed",
    "message": "目标用户的权限版本已经变化，请重新查询后再操作。",
    "retryable": false
  },
  "trace_id": "01HXYZ..."
}
```

`message` 面向管理员或最终用户，**必须是可直接展示的中文**，不含内部标识、堆栈或表名。`code` 面向程序判断。

统一错误码：

| code | 语义 | 后续动作 |
|---|---|---|
| `not_found` | 目标不存在。**明确的终态，不做相似匹配** | 不重试 |
| `not_authorized` | 当前身份或角色无权 | 不重试 |
| `target_state_changed` | 目标状态或权限版本已变化 | 重新查询后再决定 |
| `action_expired` | 待确认操作已过期 | 不重试 |
| `already_executed` | 已执行，返回既有结果 | 返回首次结果，不重复执行 |
| `target_has_pending_action` | 同一目标已有一条在途（`pending`）待确认操作，`prepare` 被拒绝（迁移 `0068` 部分唯一索引强制，防 ABA 交错） | 先处理（确认或取消）既有那一条，再重新发起 |
| `audit_write_failed` | 审计写入失败，状态未改变 | 调用方可重试 |
| `external_unavailable` | 外部系统暂不可用 | 调用方可重试 |
| `conflict` | 并发冲突 | 调用方按最新状态重试 |
| `LX-QUEUE-001` | 消息已收到，但任务没有成功进入队列 | 用户可稍后重试；同一事件不重复提示 |
| `LX-ONBOARD-001` | 自动开通暂时无法完成，已转交管理员处理，正文带这一次事件的追溯号 | 系统或管理员继续处理；用户也可以稍后重新发送消息重试（2026-08-21 裁定改口，见产品合同） |

### 幂等

所有产生副作用的接口必须携带幂等键：飞书入站用 `event_id`，内部接口用调用方生成的 `idempotency_key`。服务端以唯一索引落库，冲突即返回首次结果。

### 追踪

每个入站事件生成一个 `trace_id`，贯穿任务、Agent 会话、MCP 调用、交付和审计。单机部署下不引入分布式追踪，用结构化日志中的同一 `trace_id` 串联即可。

## 三、飞书入站

**3.1 消费的事件**：`im.message.receive_v1`（私聊消息立刻加表情——合同：**任何消息**都加，含未开通用户、忙碌期消息、`/stop`/`/new`）、`card.action.trigger`（卡片按钮，专用组织授权与管理确认）、`im.chat.member.bot.deleted_v1`（移除机器人记审计不自动停用）。

处理次序本身是合同要求，不能重排：

通道级认证 → `event_id` 幂等去重 → 加表情（失败只记审计）→ 查用户状态（未开通只登记意图，业务内容一律丢弃；已停用回复说明；已开通继续）→ 解析命令（`/stop`/`/new`；以 `/` 开头但不被认识的文本直接回绝、不入队，且不受下一步忙碌判定影响——执行层会把 `/` 开头文本解析成系统命令而不是用户文本，Trace #304 批次 5 直修）→ 话题忙碌判定 → `NOTIFY task_queued`。第 1 步是通道级认证而非逐事件验签（`V-接入-10`）；已开通用户第 2–7 步同一事务（`V-队列-01`）；加表情不可回滚，"已受理"回复不得在入队成功前发出（`V-队列-03`）；入队失败发 `LX-QUEUE-001`，其持久幂等事实是设计目标（`V-队列-07`）。

**3.3 卡片回调的校验**：必须校验点击人解析出的 `app_user.id` 等于 `initiated_by`、角色仍有权、`status=='pending'`、未过期、状态版本未变，分别对应 `not_authorized`/`already_executed`/`action_expired`/`target_state_changed`；不通过则不执行，原卡片转不可再操作的终态。

## 四、飞书出站

具体 API 以飞书开放平台文档为准，本文只固化**我们的调用约束**：加表情失败不阻断后续；创建卡片用 CardKit JSON 2.0，只有权威 API 明确受理才记 `platform_received`；流式更新序列号严格递增，首次失败永久切文本兜底；发送文本只发一个经可信输出检查的终态，响应不明记 `uncertain` 不自动重发；正式产物只走 #140/#97 批准路径；多维表格写入结果落 `publish_outbox`，逐字段比对。

**凭据边界**：飞书出站只由 Gateway 或受控交付服务持有机器人凭据，Worker、用户环境中**不存在**任何飞书凭据。Worker 不直接调用飞书，只提交事件到数据库；Gateway 消费事件，`platform_received` 不等于 `user_read`。

## 五、问数 MCP（消费方）

Lingxi 是问数 MCP 的**客户端**。合同规定 Lingxi 不复制其权限过滤、不验收其正确性，只做两件事：把它接给 Agent，以及在开通前确认同步。

**接入方式**：作为 MCP server 注册进 Agent SDK 的 `mcp_servers`；每个用户的连接以**该用户的身份凭据**建立，这是数据范围隔离的实际发生点。

**同步确认判定（探针法，2026-08-17 改写）**：五路互斥结论——**就绪**（该用户令牌 `list_metrics` 成功且指标 > 0）、**等待中**、**技术失败**、**明确无权限**（权限聚合为空，不发探针）、**超时**（十五分钟预算耗尽）。原「回读版本比对」判定已被取代（多维表格无版本字段）；**明确空结果只证明查询没报错，不能证明权限已同步**（`V-权限-06`）；两种执行形态（阻塞式/tick 驱动式，#156 S-C-03b）共享同一套判定。

**结果处理约束**：MCP 返回数据最新时间则展示、未返回则省略；不推断为权限不足；只有明确给出"不存在/延迟/不完整"才向用户说明，由 `execution` 模块做输出检查。

## 七、用户环境的接口

**7.1 交付接口**：用户环境内的交付 Skill 调用本机交付服务（`/run/lingxi/deliver.sock`）。**选 Unix domain socket，不选回环 TCP**：内核 `SO_PEERCRED` 给出调用方真实 uid。请求体里的用户标识不可信，服务端用 `SO_PEERCRED` 映射交付归属（合同列为阻断问题）；`source_path` 须解析后仍在调用方家目录内，拒绝 `..` 与符号链接逃逸。

`authorized` 为 `true` 才代表交付完成。授权未确认时返回 `delivered: false` 与说明，由 Agent 按合同措辞告知用户核对，**不自动重发**。

**7.2 问数 MCP：用户环境 Bearer**（2026-08-17 裁定改写）：本节此前是"本机 MCP 代理"方案，产品负责人裁定取代——worker → 问数 MCP 的逐用户令牌沿用 biai-agent 老路，**把 Bearer 写进用户环境配置**（见[决策记录](../决策记录/2026-08-18-用户环境持有问数MCP令牌.md)与[架构设计 6.9](架构设计.md)）。签发令牌后、排发布意图前写进用户家目录 `.mcp.json`（`440`），幂等、原子写入、日志脱敏，不创建账号或 `chown`。**这一条只放这一个令牌**：其余飞书凭据、MCP 主密钥都不进用户环境。

## 八、领域服务接口

进程内模块边界，列出的是**跨模块调用点**，模块内部结构不在本文约束。

| 接口 | 职责 | 模块 |
|---|---|---|
| `provision` | 写侧建档，按 `feishu_open_id` 幂等，自带事务 | `core/identity` |
| `ensure_conversation`/`should_resume_session` | 解析或创建会话 / 两小时规则判断 | `core/conversation` |
| `claim_conversation`/`discard_stale_agent_session` | 同话题串行的抢占（条件更新）；跨两小时阈值放弃旧会话，不带 `resume` | `core/conversation` |
| `clear_agent_session`/`request_stop` | `/new`/`/stop` | `core/conversation` |
| `enqueue_publish` | 权限发布入队（与业务变更同事务） | `core/permission` 接口；`adapters/postgres_permission_publish.py` 实现 |
| `issue_token` | 签发问数 MCP 令牌，幂等，只落密文 | `core/permission` |
| `confirm` | 探针法同步确认，五路分流，超时内部收口为 `timed_out` | `core/permission` |
| `decide_prepare`/`decide_confirm`/`decide_cancel` | 待确认操作生成、确认（幂等，最多成功一次）、取消 | `core/admin`（`pending_action.py`） |
| `remember_user_memory`/`list_user_memory`/`forget_user_memory`/`clear_user_memory` | 记忆登记/查询/删除/清空（Issue #357，D1 显式登记范围） | `core/conversation`（CRUD 契约，`ports.py`） |
| `render_user_memory_prompt` | 按用户记忆渲染 worker 注入提示词 | `core/user_memory` |
| `record` | 写审计 | 各消费模块各自声明的 `AuditSink` 协议（无独立 `core/audit` 模块）；结构化日志实现见[代码框架](代码框架.md) |

**约定**：`enqueue_publish` 与 `audit.record` 在写路径上**必须接收调用方的事务对象**，由类型签名强制"审计与状态变更同事务"——这是合同要求，不能靠代码评审保证。

**函数名以代码为准**：本表列出的是跨模块调用点的当前实现名，随重构可能漂移；发现与代码不一致时，以调用点的真实签名为准并回来更新本表（2026-08-29 维护批已订正一批漂移，见 Issue #413）。

### 8.1 写侧建档服务（`identity.provision`）

把身份、花名册与银河权限确认后的人写进 `app_user` 的唯一调用面，详细合同见 `src/lingxi/core/identity/provisioning.py`。输出三态：`created`、`already_provisioned`（幂等返回既有档）、`rejected`（零行残留）。**本接口刻意不接收调用方事务对象**，与 `enqueue_publish`/`audit.record` 的"必须传 tx"相反——建档是编排第一步，挂在调用方事务里会占住连接与行锁。

## 九、尚未确定的契约

下列接口形态依赖尚未验证的外部能力，实现时先撞、撞不通即回 Issue 重设计，**不得先向用户承诺**：

| 契约 | 依赖 | 不成立时的影响 |
|---|---|---|
| 专用关联组织 OAuth 授权 | 取得可轮换用户 token | 暂停资料同步并提示重新授权 |
| 授权后可读字段范围 | 花名册工号/邮箱覆盖率与唯一性（[#35](https://github.com/Moshuiwang/lingxi/issues/35)） | 匹配键工号主、邮箱辅，见[匹配决策](../决策记录/2026-08-05-花名册身份链与工号邮箱匹配.md) |
| 管理卡片回调走长连接 | SDK 版本的事件注册与重复回调 | 不成立则改为受控 HTTP 端点 |
| 正式产物承载、跨租户与生命周期 | #97 验证清理；#140 决定责任主体 | 维持失败关闭，不阻塞普通问数正文 |
| 问数 MCP 的按用户就绪判定 | 上游能否返回可比对的版本 | 未提供时不得以空结果宣告就绪 |
| 管理 MCP 的个人授权绑定 | Agent 客户端能否稳定传递个人身份 | 管理入口形态重设计 |
| Agent 客户端支持 MCP `2026-07-28` | 该版本移除握手与协议级会话 | 若只支持旧版本需兼容路径或改选客户端 |

对应记录以 [`docs/当前能力.md`](../当前能力.md) 的未验证依赖表为唯一事实源。
