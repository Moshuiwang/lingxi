### 文件体量棘轮

`src/lingxi/` 下超过 1500 行的文件只许变小不许变大，未超过的不得新超过。基线登记在 `scripts/ci/size_ratchet_baseline.txt`（`--refresh` 生成，须与实测精确相等，手改判红）；`scripts/ci/` 整目录默认触碰即升级为 `Epic Full`，但登记文件本身按 Issue #298 显式豁免——只改这一个文件按 `Story / code fast` 处理，不再整目录提级；`scripts/ci/` 下其余文件仍按整目录规则升级。已知边界（Issue #238）：只核对单次快照，不核对历史净增；登记不存在的路径静默跳过。

## 二、三层之间的 import 规则

架构设计的「模块化单体」靠这三条规则成立，违反任何一条都是审查阻塞项：

1. **`core/` 不 import `adapters/`、`apps/`、任何外部 SDK，也不做网络或文件 I/O。** 外部数据由调用方作为参数传入（接口设计[「八、领域服务接口」](接口设计.md#八领域服务接口)）。`check_core_layering.py` 自动守住，覆盖直接 import 与传递闭包。
2. **`adapters/` 是外部 SDK 与协议细节的唯一落点。** 每个外部系统一个模块；SDK 类型不得泄漏进 `core/` 函数签名。`apps/` 不得绕过它直接 import 外部 SDK，暂无自动检查。
3. **`apps/` 只做组装。** 读配置、建连接、注入 core、处理信号与退出；不写业务规则，以 `python -m lingxi.apps.<name>` 启动。

跨模块调用只走「八、领域服务接口」列出的函数，不读其他模块的表。写路径上 `enqueue_publish`、`audit.record` 须接收调用方事务对象，强制「审计与状态变更同事务」。

**在案例外**（2026-08-28 裁定，#371；复议前不重启）：

- `apps/worker/turn.py` 直接 import `claude_agent_sdk`（违规 2）：刻意延迟导入控 worker 依赖装载成本，不迁移 `adapters/`。复议条件：出现第二处外部 SDK import，或规则 2 补自动检查。
- `apps/trace/__init__.py` 内联 4 条业务 SELECT（违规 2、跨模块不读表）：比照 `apps/healthcheck`、`apps/reauthorize` 的「受控只读 CLI」先例，不迁移。复议条件：该 CLI 新增写操作，或查询被其他 apps 复用。

## 三、横切约定

- **标识/配置**：标识、时间、错误信封、幂等、trace_id 遵循接口设计[「二、通用约定」](接口设计.md#二通用约定)，ULID/错误信封类型/`redact()` 出口放 `core/` 公共小模块；配置全部来自 `LINGXI_` 前缀环境变量，`apps/` 入口一次读取，`core/`/`adapters/` 不直接读 `os.environ`，不硬编码主机/端口/路径/密钥（V-部署-01）。
- **凭据**：不进代码、日志、数据库。日志、数据库不存凭据明文是产品合同明令（[产品合同与外部边界](../产品合同与外部边界.md)「统一用户记录与权限变化」："飞书短期令牌、数据库认证材料、MCP 令牌明文及其他凭据不得进入用户表、日志、Issue、文档或用户交付物"）；不进代码、不进用户环境是架构设计自身的从紧要求，合同正文未规定这两处（2026-08-19 更正，#238）。**「不进用户环境」这条架构自设要求已于 2026-08-17 由产品负责人裁定收窄**：飞书机器人凭据、专用授权凭据与 MCP 加密主密钥仍然一律不进用户环境；**唯一的例外是逐用户的问数 MCP 令牌**，它按裁定明文落进该用户自己家目录的 `.mcp.json`（`440`），正文见[架构设计 6.9](架构设计.md)与[决策记录](../决策记录/2026-08-18-用户环境持有问数MCP令牌.md)。长期凭据放操作系统级密钥管理；测试只用固定假凭据探针。
- **日志/进程生命周期**：结构化输出到 stdout/stderr，带 `trace_id`，不写日志文件、不自行轮转（V-部署-04）；`SIGTERM` 后停止领新任务、完成或安全中断在途任务、超时内退出（V-部署-03），除用户环境目录外不写持久化本地状态（V-部署-02）。
- **注释与文档字符串**：中文说明「为什么」，不复述代码行为；归属为产品合同本身的断言须在[产品合同与外部边界](../产品合同与外部边界.md)找到对应，由 `check_contract_attribution.py` 自动核对。

**归属核对的匹配机制**：触发词是一条正则族，不是固定短语清单；登记表按整行原文逐字相等 + 出现次数核对。

### PostgreSQL 连接与超时

正式连接只能通过 `lingxi.adapters.postgres.connect` 建立，固定写入 `connect_timeout=5s`、`statement_timeout=3s`、`lock_timeout=2s`；覆盖须经 `PostgresTimeouts` 校验（`1–5` 秒），不得自传 `connect_timeout`/`options`。Alembic 工具链用独立配置（`migrations/alembic/migration_dsn.py`）：建连 `5s`、语句 `60s`、锁等待 `10s`。

## 四、测试约定

- 测试框架为标准库 `unittest`，`PYTHONPATH=src python3 -m unittest discover -s tests` 须可在无外部依赖的机器上运行，与 CI 执行方式一致。
- 真实 PostgreSQL 测试通过 `LINGXI_POSTGRES_DSN` / `LINGXI_POSTGRES_CONTAINER` 启用，缺省时明确跳过并输出原因；数据库约束类断言必须在真库上验证，不用 mock（验证与门禁第五节）。
- 每个实现切片认领[验证与门禁](验证与门禁.md#七关键机制验收矩阵)中的断言编号；合同「不得 / 不允许」类规则须有对应否定测试（第八节）。
- 涉及真实外部系统的行为不在 CI 里 mock 成证据；留给 `biai-stage` L4a 受控链路。

## 五、测试资产与正式代码的边界

仓库中曾有一批 **Bot-Test 测试资产**支撑关联组织受控验证，**不是正式员工路径，也不是生产入口**（[当前能力](../当前能力.md)已声明；清退与保留裁定见 #146、#67，本节只记现存终态）。

规则：文件头须保留「测试资产 / 不属于正式用户路径」声明；正式实现进入同名领域时先在 Issue 写明替代关系，不允许两套同职责代码长期并存；已验证模式（如加密轮换 `refresh_token`、`open_id` 定位共享范围成员）可作参考输入，但正式代码按合同与技术设计重写，不直接改名上线。

现存件：`adapters/oauth_bridge_client.py` 与 `workers/oauth-bridge/`（`apps/reauthorize` 的 E1 授权基础设施，保留）、`core/identity/onboarding.py`（`IdentityProfile` 等被 scheduler 多处消费，长期保留）、`adapters/feishu_bitable_association.py`（Bot-Test 读取模式参考，不进正式调用链）。`adapters/oauth_bridge.py` 已清退（2026-08-24）。

## 六、依赖与迁移

- 依赖声明只在 `pyproject.toml`，**按进程拆 optional extras**，组名与 `python -m lingxi.apps.<name>` 及 Compose 服务对齐，镜像只装该进程真正用到的依赖。不使用 uv 锁文件。现有分组：

  | extra | 对应进程 / 用途 | 内容 |
  | --- | --- | --- |
  | `scheduler` | 专用授权凭据续期；同镜像承载 reauthorize job 与追溯号查询 | `cryptography`、`psycopg[binary]`、`websockets` |
  | `reauthorize` | scheduler 镜像内的一次性重授权 job | `cryptography`、`psycopg[binary]`、`websockets` |
  | `worker` | 受控执行器 | `claude-agent-sdk==0.2.128`、`psycopg[binary]>=3.2,<4` |
  | `gateway` | 飞书长连接接入与任务入队 | `lark-oapi`、`psycopg[binary]`、`websockets` |
  | `migrate` | 部署时跑一次的迁移作业，**不是常驻进程** | `alembic>=1.19,<1.20`、`psycopg[binary]` |

  `admin` 进程待建立（第一节）。`bot-test` extra 已随 #146 清退（2026-08-23）：三项依赖唯一消费者已清退。

- `src/lingxi/` 无模块级第三方 import，全部函数内延迟导入，「import 成功」不证明依赖装上了。extras 正确性由 `Epic Full / extras` 矩阵把守：每组干净虚拟环境跑 `check_installed_package.py --process <extra>`。新增 extra 须同步矩阵与 `PROCESS_RUNTIME_IMPORTS`，对不上直接失败。
- 外部 SDK 锁精确版本或窄区间；纯库依赖用兼容区间，升级单独成提交并说明验证。
- **迁移权威来源是 Alembic 的 revision 链**（Issue #53）。约定见[数据库设计「十一、迁移约定」](数据库设计.md#十一迁移约定)：可前滚、破坏性变更拆两次发布、不写业务数据：

  | 项 | 事实 |
  | --- | --- |
  | 配置 | 仓库根目录 `alembic.ini`（**不含默认连接串**） |
  | revision | `migrations/alembic/versions/`；head 现为 `0080_task_failure_signature`，基线 `20260806_baseline_006_012.py` 承接历史 SQL（006–012） |
  | 连接串 | 环境变量 `LINGXI_MIGRATION_DSN`，缺失即失败，不回落业务的 DSN |
  | 依赖 | `migrate` extra（见上表） |
  | 门禁 | `check_alembic_revisions.py`（无需数据库）+ `check_migration_chain.sh`（真库两条链对比） |
  | 进部署制品 | 镜像构建 `COPY migrations/ alembic.ini`（#62） |

  顶层 `migrations/*.sql`（`006`–`012`）是生产链历史正文，已冻结但过渡期保留；`migrations/testing/` 是测试资产，按第五节处理。

- **迁移工具链不进运行时**：`src/lingxi/` 不得出现 `sqlalchemy`/`alembic` 字样（`check_alembic_revisions.py` 扫描），生产镜像因此不装 SQLAlchemy。

## 七、门禁入口

- 本机与 CI 的唯一门禁入口是 `scripts/ci/verify_repository.sh`；该脚本正文即检查项权威清单（约 24 项，逐项带注释说明把关断言），本文不重复列举。新增检查加进该脚本，不另起入口。`scripts/dev/check.sh`（详见[验证与门禁第十一节](验证与门禁.md#十一本机与-ci-同构)与 `scripts/dev/README.md`）架在它之上，按改动分层调用。
- 缺依赖时应报告「哪几项被跳过」而不是整体失败。

### 内容目录的版本纪律

改动 `src/lingxi/config/content.toml` 里用户可见文案（`[texts]`/`[cards]`），须同一提交内递增 `[meta] version`（惯例当天日期）、跑 `check_content_version.py --refresh` 刷新 `content.lock.toml`、两文件一起提交；只调整排版/注释/键顺序不需要递增。理由：`version` 是唯一的用户可见文案版本追溯依据（[决策记录 2026-08-17](../决策记录/2026-08-17-content-toml-版本纪律.md)）。
