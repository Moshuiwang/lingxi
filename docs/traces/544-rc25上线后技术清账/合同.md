## 4. 验收标准

- **每项发现的关卡** = 报告该条「最小修法」的可观察标准（细则见 [验收.md](验收.md)）：`修` → 单测/真库用例 + 变异红 + （有探针者）stage 受控复验；`登记` → 可指出的文件:行；`D` → PM 单字留痕。#538 关卡 = 卡面「定位四层证据（prod 与 stage 对照）+ 修正后 prod 同一问题复现出现标题/列表结构（截图 + 文档块 API 回读）」；#539 关卡 = 对比稿落决策记录草案 + PM 裁定；**#541 关卡（D-20「纳」后升级）= 设计稿五个裁定点各有 PM 答复 ＋ 一份 PM 名单（≥2 人：1 存量 + 1 新用户）在 stage 预开通后 `app_user` active、令牌就绪、正式表行含合成权限、MCP 就绪探针通过、用户零消息；随后该用户首聊无等待并问数成功（双通道）；同名单重跑零变化 ＋ 预开通后再走一次真实首聊零重复写入**。
- **生产关卡**：全局 5（已部署 + `RepoDigests` 回读与固定值逐字节一致 + 迁移头前进）+ 一次 PM 本人真问数（全局 6，只证明升级未破坏主路径）+ #538 复现（全局 6）；X-1 迁移前 prod 库 precheck SELECT 必须 0 行。
- **批终链**：本机 `check.sh full` 绿 → 冻结候选 → **唯一独立审核者（Opus 5/max）批量审查（第 1 轮）** → 统一修复包 → **同一审核者定向复核（第 2 轮）** → **codex 外部审核 1 次**（`gpt-5.6-sol`/xhigh，只读，证据内嵌 stdin，姿势见 §现场事实）→ 外审修复包（若有）→ `Image-Candidate: true` → Epic Full → 合 main → Main Publish（**private 下，验证 CI 推送**）→ stage 令牌拉取升级回读 → stage 受控复验（每个有探针的修复项一次；**≤2 轮，第二轮仍失败即归 blocker 上报，不堆 harness**）→ **生产升级前 runbook 独立走查（第 3 轮，D-2「加」）**。
- **审核独立性与同源性代价**：三轮内部审核由**同一位**独立审核者做（未参与实现、只读固定候选、独立 worktree）；codex 外审是本批**唯一的跨模型交叉**。同源性风险见 §5。

- **证据只认 GitHub/仓库留痕**：探针结果、审核结论、失败事件当天落对应 Issue 评论或 PR；任务表随执行 commit 勾选（第一恢复点）。
