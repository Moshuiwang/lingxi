# Trace 执行载体（docs/traces/）

长期执行计划（Execution Trace）的**合同与执行状态**以本目录下受版本控制的文件为唯一正文；对应的 GitHub `[tracking]` Issue 降级为瘦指针与产品负责人裁定界面。本目录只承载按现行方法生成的具体 Trace，不复制方法正文。

## 准入

满足任一条件的工作需要建 Trace 目录：多 Epic / 多批次 / 顺序依赖 / 多编排者接力 / 高风险（部署、权限、数据）。单 Issue 可完成的工作不建 Trace，照常走 Issue。历史 Trace（#46～#304）不迁移，其留痕仍在原 Issue。

## 结构（每 Trace 一个子目录：`<issue号>-<中文短名>/`）

| 文件 | 是否必需 | 内容与维护 |
| --- | --- | --- |
| `合同.md` | 必需 | 本次结果、范围、唯一授权终点、步骤、Gate 与命中的例外。建立或改变范围、授权、验收标准时走 PR；**PR 合并即产品负责人批准**。未写进合同的授权不存在 |
| `任务表.md` | 必需 | Step 状态与 `当前 / 下一步 / 等待或占用` 三行恢复点；只在状态变化、批次收口或交接时更新，不复制合同。更新仍走 PR，纯状态回写只跑文档门禁 |
| `验收.md` | 按需 | 仅在有 Trace 级新增断言、跨 Epic 总验收或需要集中证据索引时创建；否则直接链接成员 Issue / PR 的验收。证据等级见[验证与门禁](../技术设计/验证与门禁.md) |
| 其他文件 | 按需 | 只有内容无法用权威链接表达时才建立来源索引或决策清单；不得成为默认空表 |

新 `合同.md` 以 24KB 为目标；超过 32KB 时先去重、改用权威链接或拆来源索引，再说明必须保留的内容。授权和验收门槛不能移出合同来绕过批准。已有 Trace 不强制迁移。

## 与 Issue / 评论的分工

- `[tracking]` Issue 正文 = 瘦指针：目标一句话 + 实际存在的执行文件链接 + 当前阶段一行。
- 产品负责人裁定、编排者交接和批次收口评论**仍发在该 Issue**；日常过程不重复记录，只在状态变化、决策、收口或交接时更新。
- 缺陷、工作项、决策留痕照常走各自 Issue；产品事实照常写 `docs/` 正文。

## 看板配置

`board.toml` 只保留历史 Trace 使用过的证据源配置，不代表当前实施代理具备对应看板工具。具体 Trace 要使用看板时，须先验证当前工具入口并在合同中选定；本文件不维护代理或插件操作方法。
