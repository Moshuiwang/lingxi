## 1. 目标

- **用户结果一句话**：正式代码变成人类同事读得懂的样子——随机抽读任一模块，不问人就能说出模块职责与主函数在做什么；以后新写的代码只要函数超 60 行、注释带来历、docstring 不成结构、import 乱序或格式不一致，CI 与本机门禁直接变红。**用户与管理员可见行为零变化。**
- **里程碑**：
  - **M1 门禁到位**：门禁四件套（lint 清理、ruff 接线、全仓格式化、两条棘轮＋`代码规范.md`）在 `refactor/readability` 上落地，Draft PR 的 Epic Full 首次全绿，Fable 审过门禁脚本。
  - **M2 存量清完**：七批清理全部合入分支；函数棘轮与注释棘轮基线归零；ruff `D` 的 per-file-ignores 与 format exclude 清空；文件棘轮阈值降到 1000；`代码规范.md` 定稿；`readability_report.py` 读数三项相对起点下降。
  - **M3 stage 验证**：stage（Bot-Test ＋ 生产备份恢复的独立库）一轮真实旅程与上线前行为一致；人类同事抽读 2 个文件通过。
  - **M4 收口**：Draft 转 Ready，产品负责人放行后合入 main；docs 回写核对、#147 修订候选登记、环境零残留、收口评论、#591 关闭。
- **完成定义（Delivered）**：M1–M4 全部达成，#591「可观察的完成标准」逐条有 GitHub 留痕；生产升级**不属于本 Trace**（另立 `[ops]`）。

## 2. 授权终点

- **编排者可自动执行到**：从 `origin/main` 开 `refactor/readability` 并提交、推送；开出并维护**唯一一个** Draft PR `refactor/readability → main`（全程 Draft，每次推送自动跑 Epic Full）；为七批施工建立与清理独立 worktree；本机 `scripts/dev/check.sh`（含临时真库容器，跑完即清）；部署 stage（用 Draft PR Epic Full 产出的镜像制品，按现行 stage 姿势）；**把生产每日备份恢复到 stage 自己的 PostgreSQL**（产品负责人 2026-09-04 裁定「数据库不共用，用备份恢复到 stage」；备份文件如何到达 stage 见 K-2）；stage 受控真实旅程（受控测试身份，用后清场回读）；Draft 转 Ready（`gh pr ready` 常设授权）；建立本 Trace 的 Story/Task Issue（仅当需独立跟踪）；派发与回收子代理。
- **显式除外（每次单独请示）**：合入 main（须产品负责人在 #592 单字「批」，见 K-3）；生产任何写入与部署（另立 `[ops]`）；与生产共用数据库（已裁定不做）；权限变更；删除任何用户数据；修改 GitHub ruleset / 分支保护；修改 #147 正文（只登记候选）；对上游（ruff / SDK）提 issue 或 PR。
- **执行通路**：本机 tmux session `TZ-server` 编排；stage = `ssh biai-stage`（常设全权限，prod 除外）；**生产侧只有一个动作——把最新备份文件读出来**，属生产只读：代理不得自扩规则，通路按 K-2 由产品负责人定。
- **常设授权引用**：`git-claude-tz push`、gh 机器身份、`gh pr ready/merge`（PM 2026-08-06「以后不要再问」，单独成条执行）、stage 全权限（PM 2026-08-30，留痕 #469）、P2 豁免（PM 2026-08-14）。
- **中途裁定**：攒清单一次提交（[决策清单.md](决策清单.md)）；单字裁决（批/守/缓/不发）有效并留痕 #592；临时授权带失效时点（默认本 Trace 收口）。

## 3. 不做清单

- **本 Trace 明确不做**：`tests/` 的长度与注释清理（只做 lint 与格式化，收官后可另立小 Trace）；mypy / pyright 类型检查；pre-commit 本地钩子；任何新功能或产品语义、权限边界变更；生产部署；与生产共用任何环境；把文件阈值降到 1300 以下；采纳 Google 的 80 列、英文注释、import 全部置顶；修改 #147 正文。
- **登记不做**：`__init__` 参数个数的独立棘轮（用 ruff `PLR0913 max-args=10` 对新代码生效即可，存量 12 个文件走 per-file-ignores）；ruff `UP042`（`StrEnum` 会改 `str()` 结果，37 处另开 Issue 逐处评估）；PEP 695 语法（`UP040/UP046`，各 1 处）。
- **新发现默认只登记不立项**。主线灯塔两问：「不做它，同事抽读能不能过？」「不做它，新代码越线能不能红？」两问都答「能」的，默认登记不做。**清理过程中发现的行为缺陷一律只登记 `[bug]`，不在本 Trace 修**——本 Trace 的每一步都以「行为不变」为验收前提，修缺陷会污染这个前提。
- 疑问句只答不动手；产品品味类修订（如注释上限数值）夜间只出草案不落地。

## 4. 验收标准

- **逐步关卡**见 [验收.md](验收.md)；总关卡 = #591「可观察的完成标准」六条。

## 6. 主线声明与批次纪律

- **主线**：同事抽读能过 ＋ 新代码越线即红。任何派发前先问「不做它主线是否受阻」；行为缺陷、新功能、tests 清理都不在主线上。
- **`execution_adapter`**：`claude_tmux_named_session`——常驻 session `TZ-server`：`rd-b1`（门禁四件套 ＋ 集成 ＋ stage 验证，Opus 5 / max，持 `refactor/readability` 写入权与 Draft PR）；七批施工为子代理，各自 `isolation: worktree`；`rd-close`（收口，可由 b1 兼）。拉起姿势见记忆 `tmux-orchestrator-spawn`。
- **单一写入者**：`refactor/readability` 与共享文件（`pyproject.toml` 的 per-file-ignores 与 format exclude、三份棘轮基线、`docs/技术设计/代码规范.md`）只由集成者收口；施工者只改本批文件，**搬家留转发**（原模块保留 `from .new import X`，收官批统一清）；基线是生成文件，冲突用重跑 `--refresh` 解决。
- **派发卡固定条款**：读 `docs/技术设计/代码规范.md`；新函数目标 40 行、硬限 60；不得改动棘轮基线数字、per-file-ignores、format exclude；既有测试不改断言；改完先 commit 再汇报；长命令显式传超时；独立真库容器名与端口；进等待必须上报。
- **批次纪律**：攒批进分支，每合入一批本机 `check.sh full`，**每 2–3 批推送一次**消费 Epic Full；批次收口固定序列按 #147 v16 §6.8（收口评论 → 交接评论 → 继任 window → 接管登记 → 租约转移 → 退场）。
- **收尾必含**：环境清理与残留盘点（七个 worktree、临时真库容器、stage 备份库与受控测试身份留痕、远端分支——谁建谁清）；任务表勾选回写；收口评论（UTC＋北京双标注、预算消耗、Epic Full 次数 / commit 数、`readability_report.py` 读数）；#147 修订候选（派发卡与审查清单的「可读性」条款）。
