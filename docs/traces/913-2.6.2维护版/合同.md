- **用户结果一句话**：一次正式发布 **v2.6.2** 到生产：①委托凭据三条锁外竞态收进锁内（#903）；②宿主维护安装遇来历不明的在位文件先停下、不再静默覆盖生产手工修补（#908）；③管理群主动消息标题带 `[lingxi]`（#909）；④运行告警与宿主监控卡时间 UTC + 北京双标注（#911）；⑤拉取代理部署成功后按名单自动清理旧镜像（#910 第二步）；上线收尾做一次生产旧镜像一次性清理（#910 第一步）。

- **完成定义**：里程碑 2.6.2 关闭 #903 #908 #909 #910 #911；里程碑 open 只剩本 Trace 或为 0。
- **里程碑分诊表**：见 `开工快照.md`；五张单均 `pre-ready`，分诊结论已写回各单正文（2026-09-29）。

## 5. 成本预算

> 每项写「预估 / 上限」；收口对账分「可测」与「估算」两行。估算基准 = #898 实测（16.5 小时交付 13 单；sonnet / opus medium 实施单卡 30–60 分；远程完整门禁 13 分；CI 完整门禁 12–17 分）；首次真机 Step（预发宿主维护新安装器、预发代理镜像清理）按 **3 倍**估时。

- **云端完整门禁**：预估 **5** / 上限 **8**。**远程串行完整门禁（tx-sg）**：预估 **2** / 上限 **4**。**Release Candidate**：预估 **1** / 上限 **3**。**Promotion** 1 / 1；**生产部署** 1 / 1（回滚不计）。
- **PR 数**：预估 **6** / 上限 **9**（合同 1；W1 批次 1；同步 1；验收记录 1；任务表记录 1；收口 docs 1）。
- **产品负责人触点**：预估 **5** / 上限 **7**——①本合同 PR 合并（顺带过目方法 v24）；②`release/2.6` 同步 PR 批准（CODEOWNERS：差异含 v2.6.1 验收记录）；③预发手机确认 + 验收记录 PR 批准（同段）；④生产段：Promotion → 宿主维护 `!` → 一次 Bot-Prod 问数（同段）；⑤旧镜像清理名单确认 + `!`（与④同段或观察 1 小时后）；余量 2。国庆（10-01 周四—10-07 周三）只排 PR 批准类触点，真人验证与生产段排工作日或产品负责人另行指定。
