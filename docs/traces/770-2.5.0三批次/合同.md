## 4. 验收标准

- **可观察完成标准**：逐 Epic 细则见 `验收.md`（E-1 … E-16）。Trace 级硬判据：
  1. **门禁不再自证**（E-1）：`Epic Verdict` 由独立 App 身份产出；同名伪造被拒；撤属主整行后普通工作流 PR 无需人工批准；恢复路径演练过一次。
  2. **拉式部署链在预发跑通**（E-8）：拉取代理只出网；九处中断接续、并发拒绝、篡改拒绝、15 分钟观察、首触冒烟、三路否定各有实测；**权限发布表共用前提下**，预发写表前备份、写入行可识别、整批撤回演示一次。
  3. **生产由拉式部署器完成**（E-14）：digest 三方一致（候选清单 = 正式版 = 生产 env）；迁移头 = 链头；15 分钟 healthy；既有业务行数不变；**产品负责人 Bot-Prod 真实问数 `succeeded`，L5 只认真人**；部署代理的失败告警在预发触发过一次。
  4. **产品裁定逐条可观察**：#604 缺配置即不接单；#715 差集补齐与回执提示；#675 一条真实运营旅程；#664 合同修订先行、表开始写入、读取有审计；#716 受限通道 Agent 一次查询一次写动作准备且普通用户不可达；#735 同一次运行里同时出现送达与不送达。
  5. **候选变化即旧结论失效**：预发验的是 rc 四镜像，正式版必须是同一组 digest。
- **证据等级要求**（`验证与门禁.md` L 口径）：生产关键路径 **L5** 只认产品负责人真人问数；代理在生产的回读写作「真实链路 · 生产 · 代理 · 只读」；预发 L4a / L4b；纯代码改动 L2；探针与本机实测 L3。**判定字段只认系统写出的值，前置状态允许人工构造。**
- **真人验证块只放三处**：批次 2 末（预发：受限通道 + 拉式部署演练后一次 15 分钟真人抽查）、批次 3 末（预发：#715 / #675 / #716 / #735 各一次动作，一张清单）、生产（E-14）。每块先出示就绪自检（前提核对 + 日志回读 + 预判断点），一次只给一条指令；中途不请产品负责人试错。
- **真人验收是缺陷发现口**（v20 §三）：候选预算预留 **2 轮打回**，收口对账写「因打回重做的轮次：预估 / 实际」。
- **假证据六型每个固定候选必查**（`#678` §四）；本批最易命中：⑤ 断言里的无证据陈述（分诊结论全是「已分析」，实现里不得写成「已实测」）；② 守卫按路径扫源码而实现已搬走（#658 平移必查）。
- **既定条款**：双通道观测；证据只认仓库 / GitHub 留痕；批次终点一次完整门禁 + 一次批量审查 + 唯一合并人合并。

## 6. 主线声明

- **本 Trace 的主线是**：让 v2.5.0 经**拉式部署器**到达生产真实用户；批次 1 的门禁立稳（#748）是它的前置，批次 3 的产品功能是它装载的货。任何派发前先问「不做它主线是否受阻」——受阻的先做，不受阻的按批次顺序。
- `execution_adapter`：`claude_tmux_named_session`——常驻 tmux session `TZ-server` + 每批次一个 window（`250-w1` / `250-w2` / `250-w3` / `250-w4` 发布 / `250-w5` 收口）。**守望者 = 规划者会话转任**（裁定 L-4，窗口 `250-plan`）。**守望者必须同时挂两类值守机制**（v20 §四）：事件型（本地证据：窗口输出与工作树提交，查询失败显式重试）+ 定时型（周期完整回合查外部留痕并对照任务表，自带收尾条件）；**机制上线前先对机制本身跑一遍有效性判据**；不得声称任何未被机制支撑的巡检频率，声称时给出机制标识与启动证据。守望者窗口关闭即两类机制失效，由产品负责人重新拉起。
- **会话与工作树纪律（产品负责人 2026-09-13）**：编排者、守望者会话一律在主检出 `~/project/lingxi` 拉起；实施 / 审核 / 编排的隔离工作树一律放主检出的 `.claude/worktrees/`，**不放系统临时目录**；主检出同一时刻只有一个写入者。
- **编排者只派不写**（`#678` §一）：不写产品代码、不写迁移、不跑本机完整门禁以外的实施动作；例外只有 `docs/traces/` 记录、任务表勾选、预发 / 生产的只读回读与按 runbook 逐条执行的安装命令。
- **转达与留痕**：守望者、编排者与继任者之间的转达一律走运行时会话间消息（有投递回执），注入按键不构成已转达；会话消息不是留痕，裁定与交接照旧落 Trace Issue（v20 §四）。产品负责人直接键入代理窗口的裁定以 Issue 回执为准。
- **阶段分支不叠**：一段合完再开下一段的分支；批次分支用 `trace/770-w<n>-<短名>`，纯记录 PR 用 `record/770-…` 前缀走 docs 路由。**候选冻结后的纯记录提交不推回该 PR**；收口时 PR 头 SHA 仍逐字等于验收单里的候选 SHA。
- **单一写入者**：当任编排者持主工作树与合并权；实施子代理各用独立工作树，改完先 commit 再汇报；审核子代理只读固定候选；面向 `main` 的 PR 串行合并；`management_cards.py` 等热点文件同批只允许一个写入者（#658 与 #716 错开）。
- **既定条款**：默认攒批进批次分支（子改动只跑快检），批次终点一次完整门禁 + 一次批量审查 + 唯一合并人合并；批次收口固定序列（收口评论 → 交接评论 → 继任 window → 接管登记 → 租约转移 → 退场，`#678` §五）。收尾必含环境清理与残留盘点（工作树 / 远端分支 / 临时目录 / 容器 / 预发实例谁建谁清）、任务表勾选回写、批次收口评论（UTC + 北京双标注 + 预算对账两行 + 外审台账 + 门禁余量）。
