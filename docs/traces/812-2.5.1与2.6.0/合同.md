## 1. 目标

- **用户结果一句话**：两个正式版本按先后由**拉式部署器**发到生产并各经产品负责人一次真人问数验收——**v2.5.1** 修掉 2.5.0 上线后暴露的四处稳定性缺口（人工改公开配置不再卡死下一次发布 #804、失败的部署计划不再占着主机 #805、离职再入职的同邮箱同事能被正确开通 #807、两条部署测试本机与 CI 结论一致 #739；#756 补两项运维证据），**v2.6.0** 收掉 3.0 前的内部欠账（#748 裁决层剩余验收、#735 「申请使用」核实与验收对账、#742 偶发失败先复现再定修法、#745 多公司欢迎示例只用共有指标）。
- **里程碑（何谓「到了」）**：生产三服务先后跑 v2.5.1、v2.6.0 正式版四镜像（digest 与正式版清单逐一相同），两次升级都由**生产主机的拉取代理 + 部署器**完成；每次 15 分钟观察窗口全 healthy；**产品负责人各用 Bot-Prod 完成一次真实问数（L5）**；#807 受影响的 4 人在 v2.5.1 上线后按新规则重处理并逐人留有审计终态。
- **完成定义**：里程碑 2.5.1 关闭 #804 / #805 / #807 / #739，#756 关闭或余项写去向；里程碑 2.6.0 关闭 #748 / #735 / #742（含「当前未能复现」的如实收口）/ #745；两个里程碑 open = 0 或余项各有去向评论。
- **既定条款**：交付终点按 `#678` §一逐项声明——PR 合并、组件存在、CI 通过、Release 存在都不自动升级实际终点；**正式版发布 ≠ 生产部署 ≠ 真实用户拿到**，三者分别取证。

## 4. 验收标准

- **可观察完成标准**：逐 Epic 细则见 `验收.md`（E-1 … E-12）。Trace 级硬判据：
  1. **#804 真实链路**（E-1）：预发版本 A（配置指纹 X）→ 人工改 `public-config.json` 为 Y → 版本 B 计划以 X 核 old、以 Y 描述 new → `verified`；篡改旧容器标签仍被拒；old / new 在 plan / audit / 错误码可区分。
  2. **#805 只收敛 prepare-only**（E-2）：预发注入一次 prepare 失败 → 自动归档失败计划、在途标记复位到上次 `verified`、下一计划正常部署；`stop` 之后失败、意图已记录、旧执行者仍在、标记属他人四情形不清理（本机假世界用例逐条）；不伪造新的 `verified`。
  3. **#807 唯一在职身份**（E-4）：五个按邮箱定位的入口共用同一 resolver；五态稳定；不可用快照不折算 0 在职、不自动授权；邮箱复用不静默转移旧凭据 / 会话 / 本地授权；预发两个真实失败入口回归通过；生产 4 人逐人审计终态。
  4. **两版都由拉式部署器到生产**（E-6 / E-11）：digest 三方一致（候选清单 = 正式版 = 生产运行容器）；迁移头 = 链头；15 分钟 healthy；既有业务行数不变；**产品负责人 Bot-Prod 真实问数 `succeeded`，L5 只认真人**。
  5. **2.6.0 四单各有可观察收口**：#748 E-4 后半 + E-1 ④ 有实测、⑤ 演练留痕或明确去向；#735 「申请使用」有产品负责人一句话 + 验收文档对账；#742 有固定提交与样本量的分布记录，修或如实「未能复现」；#745 单公司 / 有交集 / 无交集 / 部分独有四类样本用例 + 预发欢迎卡受控真人核对。
  6. **候选变化即旧结论失效**：预发验的是 rc 四镜像，正式版必须是同一组 digest；候选 SHA 变化后旧审核结论按影响失效。
- **证据等级要求**（`验证与门禁.md` L 口径）：生产关键路径 **L5** 只认产品负责人真人问数；代理在生产的回读写作「真实链路 · 生产 · 代理 · 只读」；预发 L4a / L4b；纯代码 L2；本机探针 L3。**每条判据写明被判的值由谁写入**：部署器状态账、拉取代理日志、`operation_audit`、`app_user` 由系统写出；花名册样本、预发配置改动、注入的 prepare 失败是允许人工构造的前置状态。
- **真人验证块只放三处**：v2.5.1 生产（E-6）、v2.6.0 预发欢迎卡核对（E-10，默认 Codex，裁定 7）、v2.6.0 生产（E-11）。每块先出示就绪自检、一次只给一条指令；中途不请产品负责人试错。**真人验收是缺陷发现口**：每版预留 **1 轮打回**，收口对账写「因打回重做的轮次：预估 / 实际」。
- **假证据六型每个固定候选必查**（`#678` §四）；本批最易命中：#805 崩溃注入若在替身里直接写「已收敛」而不经真实阶段账（①）；#807 测试名写「已实测预发」而预发未跑（⑤）；#739 只在一种 umask 跑过就宣称两种一致（⑥）。**碰主机候选（#804 / #805）审查卡另附真机语义清单**：权限位、属主、子进程字节码缓存、`host.active.json` 与状态目录真实路径、docker 标签真值。
- **审查卡威胁模型写死**（v21 §四）：#807 = 自报邮箱冒领、邮箱复用继承旧 token、快照缺字段折算「全员离职」、多在职自动选人；#804 / #805 = 读被核容器标签再与自身比较、把 desired 当历史值、清别人的在途标记、伪造 `verified`。同类绕过第二个变体即停止补丁、上提「信任来源」裁定。
- **既定条款**：双通道观测；证据只认仓库 / GitHub 留痕；批次终点一次完整门禁 + 一次批量审查 + 唯一合并人合并。
