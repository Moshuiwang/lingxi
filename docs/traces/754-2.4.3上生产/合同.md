## 4. 验收标准

- **可观察完成标准**（逐 E 细则见 `验收.md`）。Trace 级硬判据：
  1. **候选身份三方一致**：`release-manifest.json` 的 `commit` / `tree` / `run_id` 与 `release/2.4` 合并提交逐字对上；四镜像 digest 在 GHCR 可解析；正式版四 digest 与候选逐一相同；生产 `.env.prod` 四 digest 与正式版清单逐一相同（E-7 / E-10 / E-12）。
  2. **版本验收单**（`验收.md` §二）固定项 6 条 + 随版本项逐条有证据指针，在预发（rc 四镜像）执行一次、在生产执行固定项一次；**判定字段只认系统写出的值**，前置状态允许人工构造，答不出「这个值是谁写的」即无效判据。
  3. **生产**：迁移头回读 = 候选链头；三服务 healthy 且 15 分钟窗口内无非预期重启；既有业务行数不变；产品负责人一次真实问数 `succeeded`（**L5 只认真人**）；管理群在部署窗口收到一组「容器不存在 → 已恢复」属预期现象（runbook 本批补一句）。
  4. **#673 回填**：`--dry-run` 计数 → 产品负责人过目 → `--apply` → 四列人数回读 → 再跑一次零变化（幂等）。
  5. **恢复演练（#693）**：预发库 `pg_dump -Fc` → 预发主机隔离 `postgres:17` 容器 `pg_restore` → `migrate` 到链头 → 进程内补跑保留清理 → 回读 → 销毁；记录回写 runbook §八。
  6. **里程碑**：2.4.1 / 2.4.2 GitHub 回读 open = 0 并关闭；2.4.3 只剩 #748（若 W4 未做）。
- **证据等级要求**（用仓库 `验证与门禁.md` 的 L 口径）：生产关键路径 **L5（真实交付 · 生产 · 真实用户）**，只认产品负责人的真人问数；代理在生产的回读写作「真实链路 · 生产 · 代理 · 只读」，不借 L4a / L5 之名；预发 L4a / L4b；W1 代码改动 L2 + 变异验红；未验证层级收口时如实列明。

- **假证据六型每个固定候选必查**（`#678` §四）。本批最易命中：⑤ 断言里的无证据陈述（分诊结论全是「已分析」，实现里不得写成「已实测」）；「取不到证据时的反向结论」（#732 陷阱清单末条）——生产回读拿不到值一律写「未知」。

## 5. 成本预算

> 每项写「预估 / 上限」两个数；收口对账分「**可测**」与「**估算**」两行，不合成一个数（#732 §三教训）。**无头 CLI 审核者（Fable / codex）每次调用当场在任务表或阶段评论登记一行：时间、模型与档位、审的候选 SHA、哪张卡**——未登记即为「未知」，未知不是零，必须给上下界。

- **云端完整门禁（严格口径：`trace/**` / `sync/**` / `accept/**` 上真实执行的 run）**：预估 **7** / 上限 **12**——W1 PR 1 + 修复复推 1 + 同步 PR 1 + 验收记录 PR 1（#687 实测跑了 gate + extras + image）+ W4 工作流 PR 1 + W4 造 PR 2；**预留 2 次给「候选被真人验收打回后重做」**（#709 三个候选两个被打回）。docs 路由 run 不计。每次登记 `gate` 最长单步耗时 / 15 分钟上限，余量低于两成先调上限。
- **Release Candidate 构建**：预估 1 / 上限 3。**Release Promotion**：1 / 2。
- **本机完整门禁**：无硬上限，预估 ≥ 4，逐次对账。
- **预发部署**：预估 1 / 上限 2（W2 清场重装 rc 四镜像；重做 1 次余量）。**恢复演练**：1 / 2。
- **生产部署**：1 / 1（回滚不计）。**生产窗口**：目标 **2026-09-18 前**（一周内）；硬期限只有 #673 回填 2026-12-01。含跨夜；生产窗口挑静默时段，由产品负责人在 G-2 放行时指定。
- **PR 数**：预估 **7** / 上限 **9**：合同、W1、`release/2.4` 同步、验收记录、W4 工作流、收口（+ 可选：W4 造 PR 2 个用完即关不计、合同修订 1）。
- **子代理**：预估 **16** / 上限 **26**——实施 4 + 复修 3 + 内审 3 + 二审 1 + 把关 4 + 外审 2 + 只读 2；**规划期已用 6（分诊，单列）**。每次派发自挂兜底观察；不得再派子代理；单体预计超 60 分钟必须切分；预计时长写进派发卡。
- **外审配额 ≤ 3 人次**：W1 必一路（codex `gpt-6-astra` high），W4 一路，机动 1。外审不作为独立审核者，发现逐条回源裁定；按外部证据判活，退出码不作判据。
- **token**：规划期**可测** 6 分诊子代理约 91 万；执行期**估算** 300–600 万（对照 #732 可测约 1013 万）；上限 **800 万**；主会话自身用量无实测出处不写数。剩余额度低于 5% 即停止派发。
- **模型配比**（比照 #732 §5）：编排者 **opus max**；实施 / 复修 **sonnet xhigh**，**唯 S-1-2（#661 迁移与加固）实施用 opus xhigh**；常规内审 **opus xhigh**（未参与实现，审固定候选）；**Fable 5.1 xhigh 三个位置**——规划审核（已由本合同 PR 前一次性消费，登记在 Trace Issue）、W1 第二内审（迁移与安全加固，与 opus 并行看同一固定候选，结论分别记录）、每个 PR 合并前把关（W1 / 同步 / 验收记录 / W4）；外审 codex `gpt-6-astra` high；守望者 = `lingxi-242-plan` 窗口（现任，由产品负责人授权裁预算）；规划者会话只读待命。三个 Fable 位置不得由同一次调用兼任。

## 6. 主线声明

- **本 Trace 的主线是**：让 v2.4.3 到达生产真实用户，并在同一窗口完成 #673 回填。任何派发前先问「不做它主线是否受阻」——#661 / #693 因产品负责人 2026-09-09 裁定为生产前置而在主线上；#748 不在主线上，放生产之后。
- `execution_adapter`：`claude_tmux_named_session`——常驻 tmux session `TZ-server` + 每阶段一个 window（`243-w0` … `243-w5`）。**守望者 = `lingxi-242-plan` 窗口**（#732 的守望者延任，产品负责人已授权其裁预算；预算不足向它请示）。**守望者必须同时挂两类值守机制**：事件型（管「死没死」，只用本地证据，查询失败显式重试）与定时型（管「做到哪」，按周期查 GitHub 留痕）；两类都是会话级，窗口关闭即失效；**不得声称任何未被机制支撑的巡检频率**；告警前先自问「这个信号在一切正常时会不会照样返回真」。
- **编排者只派不写**（`#678` §一；#732 两任都违反过，代价是自证闭环与上下文耗尽换人）：编排者不写产品代码、不写迁移、不跑本机完整门禁以外的实施动作；例外只有 `docs/traces/` 记录、任务表勾选、预发 / 生产的只读回读与按 runbook 逐条执行的部署命令（部署是编排者亲自执行的高风险动作，不下派）。
- **阶段分支不叠**：一段合完再开下一段的分支（`strict_required_status_checks_policy` 会让叠着的 PR 全部落后、逼出额外门禁与无效点击）。`trace/**` 分支一旦用 GitHub「Update branch」，必检项必然判红（合并提交不带镜像标记），须再补一个带 `Image-Candidate: true` 的提交——这是 #733 路由的必然后果，不是故障。
- **候选冻结后的纯记录提交不推回该 PR**：合并后从新 `main` 另开 docs PR（实测全 skipping 约 13 秒）。判据：收口时 PR 头 SHA 仍逐字等于验收单里的候选 SHA。
- **单一写入者**：当任编排者持主工作树与合并权；实施子代理各用独立 worktree，改完先 commit 再汇报；审核子代理只读固定候选；面向 `main` 的 PR 串行合并。
- **既定条款**：默认攒批进阶段分支，阶段终点一次完整门禁 + 一次批量审查 + 唯一合并人合并；收口按 `#678` §五固定序列。收尾必含环境清理与残留盘点、任务表勾选回写、阶段收口评论（UTC + 北京双标注 + 预算对账两行 + 无头 CLI 台账）。
