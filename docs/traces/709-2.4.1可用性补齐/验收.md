## 三、必须真人的项（转交接清单，本 Trace 不认领等级）

管理员**本人在飞书点确认卡**无法由代理替代，其下游全部挂在它后面：一次事务新增资格并登记逐人持久任务、逐人真实就绪检查、**未通过就不发「可以使用」**、欢迎卡按守卫停止发送。由 S-5-9 写成一张可直接照做的清单落 #704，每条写明**做什么 / 看到什么算过 / 看到什么算不过 / 不可达时的原因与去向**，并附现场入口（怎么连、在哪看、出错找哪条日志）。

**结果（2026-09-10 第三轮，候选 `93daa3bac7be`，编排者逐条[回源核查](https://github.com/Moshuiwang/lingxi/issues/704#issuecomment-5615432610)后认领）：**

| 真人项 | 结果 | 系统写出的值 |
| --- | --- | --- |
| 正常问数端到端 | **通过** | `tsk_01M2557X3CGFN7K0DWNQ7JG59C` = `succeeded` |
| 本人点确认卡入组 | **通过** | 网关 `decision: confirm, status: executed`；后台阶段 `completed` → `check_passed`；成员行与名单版本同刻落库 |
| 未就绪不发「可以使用」 | **不可达，未认领** | 现场四人全部启用且活跃，造不出合法的未通过对照；`outreach_message` 全表 0 行，该现象在「拦住了」与「根本没跑」两种情况下完全相同，不构成证据 |
| 授权变化后点确认（#734） | **通过** | 网关 `decision: confirm, status: failed`；落 `failed` / `role_revoked`；卡片改写为「本次未执行；请重新发起」；零资格写入 |

经办与判据的界限：前置状态（临时管理员、绑定版本、成员行增删）由现场人工构造，**判定字段全部由系统写出**并有网关日志佐证。上一轮不成立正是因为判定字段是人手填的。

## 五、未验证层级（收口时如实列）
