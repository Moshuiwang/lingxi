## 双跑（新旧验证路径的比对与废弃条件；自 `合同.md` 移入）

产品负责人 2026-09-10 裁定：#712 放最前，但后续阶段**新旧两条通路并行得到结果之后，再把旧的验证方法废掉**。落成四条可执行约束：

1. **两条通路串行跑，绝不同时跑。** 同机并行跑两个完整门禁，正是 #709 实测出 `Ran 6458 tests / failures=2, errors=1161` 的原因——失败签名清一色是环境性的。影子期每次双跑的阶段门禁时间约 **1.5–2 倍**，这是已知代价。
2. **「一致」的判据是四项同时成立**，缺一即判不一致：
   - **执行到的测试 ID 集合逐条相同**（不是 `Ran N` 的数字相同——数字一样但跑的不是同一批测试，比对就白做了）；
   - 每条用例的通过 / 失败结论相同；
   - 失败用例的失败签名相同；
   - 静态门禁项的集合与结论相同。
3. **双跑两次**（W2 与 W4 各一次）。**两次全部逐条一致，才允许执行 S-5-2 废弃旧路径。**
4. **任何一次不一致 → 立即停止废弃**：差异登记为 #712 的未闭合项，旧路径保留，诊断来源；**不许靠重跑到一致再收口**。
5. **影子期一律以旧路径结论放行**。S-5-2 之前新路径**只做比对、不为任何门禁背书**——旧绿新红、旧红新绿都按旧路径走，差异进比对记录。
