## 4. 验收标准

- **可观察完成标准**：逐 Epic 细则见 `验收.md`。Trace 级的四条硬判据：
  1. **W0–W4 五个阶段的 PR 与 S-5-2 的 PR**（若走废弃分支）各自经**一次完整门禁绿 + 一次内部批量审查 + 一次 Fable 5.1 xhigh 合并前把关**后合并进 `main`。W5 的收口 PR 只改 `docs/traces/`，走 docs 路由不跑 gate，不适用本条。
  2. 17 张单逐张有去向，且**去向写在各单自己的评论里**，不只写在收口评论。
  3. 按 `check_docs_size_budget.py:13-14` 的原规则：**上限调整必须与实际瘦身或扩容发生在同一次改动里、留下可审阅的 diff**，不接受「先抬上限再慢慢写」。`当前能力.md` 在 W3 后须有可读余量；`产品合同与外部边界.md` 在 W3 后仍是零余量，W4 的回写**允许抬 `:68`**，但必须同批并写明理由。
  4. **新旧门禁双跑两次全部逐条一致**，才允许废弃旧的串行验证路径（判据见 §双跑）。
- **证据等级要求**（**用仓库 `验证与门禁.md` 的 L0–L6 口径，不与产品负责人的全局 1–7 混写**）：**关键路径至少 L4a（真实链路 · 预发 · 代理）**——三个 P1 缺陷、#673 的状态留存与 #718 的恢复语义都要在预发拿到代理回读证据。其余至少 **L2（CI 通过）**。三个 P1 缺陷另要求**变异验红**（删掉被验证的那一行，用例必须转红）。**L4b（预发真人）只出现在 S-5-3 的清单上；L5（真实交付 · 生产 · 真实用户）与 L6 一律不认领**，未验证层级在收口时如实列明。
- **既定条款**（`#678` 原文，不重抄）：双通道观测；**证据只认仓库 / GitHub 留痕**。
- **产品负责人真人验证块只放一处**：Trace 最后（S-5-3），形态同 2.4.1 的 #704。**中途不请产品负责人试错。**
- **判定字段与前置状态必须分开**（#709 复盘候选 2，本批通则）：每条判据要能回答**「被判的那个值是谁写的」**——**判定字段只认系统写出的值**（手填即该判据无效），**前置状态允许人工构造**（如 D-16 调开通状态）。答不出「谁写的」即无效判据。实测：2.4.1 第二轮真人验收报 PASS，回源发现被判的原因串**在候选代码里根本不存在**，整轮作废。
- **不得用已被取代的候选的证据关闭 Issue**（该批真实发生过）。候选 SHA 变化后旧结论失效，重新取证再关。
- **假证据六型每个固定候选必查**（`#678` §四）。本批最易命中三型：⑤ 断言里的无证据陈述（准备批结论都是「已分析」，**不得在实现里写成「已实测」**）；⑥ 断言与实现相反（#719 与 #684 都是「代理指标代替真判据」的修复，改完要反过来验）；**新增高危：分片验证的「Ran N 相同」不构成覆盖面证据**（见 §双跑）。

## 5. 成本预算

- **CI 路由核准事实**：`ci.yml` 的三个重作业**不区分 `fast` 与 `full`**，面向 `main` 的 PR 无论改什么成本相同；唯一省 build 的是 `image` 对 `epic/**` 的默认跳过，而 `epic/**` 的规则集让 Trace 分支吃不到。**W0 先把豁免扩到 `trace/**`。**
- **完整门禁次数上限：≤ 12 次**（W0–W4 各 1 次 + S-5-2 的 PR 1 次 + E-1 ③ 的对照 PR 1 次 + 5 次修复复推余量），仅阶段终点消费。**预估 8 次**。
- **其中至少 2 次预留给「候选被打回后重做」**（#709 复盘候选 1）。实测：2.4.1 **三个候选有两个被真人验收打回，而它们都通过了全部自动检查**，按 1 次估、实际追加到 6 次。本批打回来源是 Fable 把关与 S-5-3 真人清单。
- **门禁耗时余量当作可观察量登记**（#709 复盘候选 4）：每次完整门禁记录**最长单步耗时 / 超时上限**，**余量低于两成先调上限**，不等它撞线。实测：2.4.1 第 3 次 CI 被 `gate` 的 10 分钟超时掐断、**零产出白烧一次额度**，前两次是 9 分 54 秒与 9 分 50 秒——**整批贴着 6–10 秒余量在过、每次判绿，余量从没被看见**。上限已放到 15 分钟；**真修法是 W1 的 #706**，W1 合并后该比值应明显回落，这是 W1 的一个可观察产物。
- **本机完整门禁**：无硬上限但须对账。**预估 ≥ 20 次**——E-3 的「连续跑五次零环境性失败」与「改造前后各跑三次取中位数」在 W1 就要 11 次，加 W2 / W4 双跑各两次（#709 实测单次约 913 秒，串行不可并行）。
- **预发部署：2 次**（W2 后、W4 后）。
- **PR 数：9 个**（合同 + W0 + W1 + W2 + W3 + W4 + **S-5-2** + **E-1 ③ 的对照 PR** + 收口）。对照 PR 以**未登记前缀**开向 `main`，用完即关并删分支（谁建谁清，计入 S-5-5）。
- **候选冻结后的纯记录提交不推回该 PR**（#709 复盘候选 3）：推了 PR 头就离开被验收的候选，且按整体差异重跑完整门禁。**合并后从新 `main` 另开文档 PR**——实测 #736 全 skipping、**13 秒**。**判据**：收口时 PR 头 SHA 仍逐字等于验收单里的候选 SHA。合同 PR 与收口 PR 只改 `docs/traces/`，路由 `docs`/`l0`，**不消费 gate / extras / image**（W0 落地后其余五个 PR 的 `image` 亦跳过，仅冻结候选那一次带 trailer 构建）。
- **时间窗**：不设硬截止；含跨夜。**唯一时间约束有确切日期**：生产 2026-09-02 上线，入站事件按 90 天整行删除（`V-保留-27` 已验证），**最早一批在 2026-12-01 前后开始逐行消失**；越晚做能回填的历史越少。**W4 建议不晚于 2026-10-31 完成。**
- **模型配比**：编排者 opus max；实施 / 复修 sonnet xhigh；**常规内审** opus xhigh（未参与实现，审固定候选）；外审 codex 的 astra medium 与 gemini flash 3.8；规划者 / 守望者 fable。
- **Fable 5.1 xhigh 占三个位置**（产品负责人 2026-09-10 裁定「加两个位置，不替掉 opus」，命令形态 `claude --model fable --effort xhigh`）：
  1. **规划审核**——审本三件套，规划阶段一次性消费，已执行。
  2. **高风险阶段第二内审**——W1（改验证机制本身）与 W4（迁移与恢复语义）各一路，**与 opus 并行看同一份固定候选**，两人结论分别记录、不互相转述。
  3. **最终 PR 把关**——六个阶段 PR 各一次，审**即将合并的那个 PR**。

- **外审配额 ≤ 4 人次**：W1 / W2 / W4 各**必须**一路，第 4 路机动，W3 可省。**外审不作为独立审核者**，发现由编排者逐条回源裁定，不采信结论本身。**派出后按外部证据判活，退出码不作判据**——2.4.1 有一路外审连续静默失败，且 `agy` 在权限被拒时**退出码 0 但输出 0 字节**，按退出码判成功必得反向结论。
- **子代理 ≤ 35 人次**（预估 **28**：实施 13、内审 6、二审 2、外审 3、只读 2、预发取证助手 2；预发部署与自验由编排者亲自执行，那 2 人次可选）。每次派发自挂兜底观察；**子代理不得再派子代理**；单体预计超 60 分钟必须切分。
- **token 量级预估：500 万–900 万**（对照：#711 的 18 人次只读批实测 244 万）。收口逐项对账。
- **既定条款**：开跑前查配额余量；对抗验证分批派。**剩余额度低于 5% 即停止派发**。

## 6. 主线声明

- **本 Trace 的主线是**：把三个 P1 缺陷、#673 的状态留存与四张零余量 / 工具账目送进 `main` 并在预发验到。任何派发前先问「不做它主线是否受阻」。
- `execution_adapter`：`claude_tmux_named_session`——常驻 tmux session `lingxi` + 每阶段一个 window（`242-w0` … `242-w5`）。**守望者 = 现有守望者会话继续担任，编排者由它拉起**（角色名按产品负责人 2026-09-09 裁定，「守望者」已更名「守望者」）。**本 Trace 的规划者不转任守望者**——Trace #709 的反向审计实测「规划者登记权限退出后转只读监护者」这条机制**零引用**，不沿用。
- **守望者的值守节奏必须落成机制，机制本身要能被查**。交互式会话没有自己的计时器，「每 N 分钟查一次」写进合同不产生任何行为。须同时挂两类、缺一即欠覆盖：**事件型**（管「死没死」，只用本地证据；查询失败须显式重试，不得把「查不到」读成「没事」）与**定时型**（管「做到哪」，按周期给一个完整回合查 GitHub 留痕）。两类都是会话级，窗口关闭即失效。**不得声称任何未被机制支撑的巡检频率。**
- **单一写入者**：当任编排者持主工作树与合并权；实施子代理各用独立 worktree，改完先 commit 再汇报；审核子代理只读固定候选；面向 `main` 的 PR **串行合并**。
- **既定条款**：默认攒批进阶段分支（子改动只跑快检），阶段终点一次完整门禁 + 一次批量审查 + 唯一合并人合并；收口按 `#678` §五固定序列。收尾必含环境清理与残留盘点、任务表勾选回写、阶段收口评论（UTC + 北京双标注 + 预算对账）。

## 双跑（新旧验证路径的比对与废弃条件）
