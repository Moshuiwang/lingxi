## P2 硬切与用户路径

### 写入方与入口唯一性

- [ ] 切前正式表逐行脱敏快照、旧部署版本 / 写入键 / 触发频率 / 全部事件路径重新读回。
- [ ] 旧定时、旧 Bot、旧 API、旧文件发送等全部写路径停止并屏蔽；主机重启后仍保持屏蔽。
- [ ] 跨满 15 分钟旧写周期，无旧任务执行；正式表行集合、键、状态与令牌形状不变。
- [ ] 只有一个操作者持有生产 Compose 租约；只有一个 `Bot-Prod` 长连接；无新旧容器并存窗口。

### 数据与服务

- [ ] 主机资源回读达到 8 vCPU / 32 GiB；生产并发与 worker 16 GiB 限额同档。
- [ ] #441 正式差集导入 dry-run 可解释，执行后管理员授权逐行可审计；幂等复跑零重复。
- [ ] 固定四 digest 启动；scheduler、gateway、worker-queue 与其依赖按 runbook healthy，数据库与队列无积压异常。
- [ ] 启动后连续 15 分钟无容器重启、错误风暴、重复发送或正式表异常删除 / 权限扩大。

### Bot-Prod 真实用户结果

- [ ] 存量用户：按邮箱命中正式表既有令牌，adopt-or-issue 复用成功，不覆盖、不重签；最终看到“开通完成”。
- [ ] 新用户：无存量令牌时签发新令牌并写入正式表，MCP 同步就绪；最终看到“开通完成”。
- [ ] 至少一名验收用户从 Bot-Prod 发起真实问数并收到可用业务结果，不以任务内部 `succeeded` 代替用户收到。
- [ ] 每条用户可见断言都有消息 / 卡片回读 + 平台 API 或结构化日志第二通道。
- [ ] 失败路径可理解且不错误宣告成功；存量解密失败时响亮停，不回退签新造成令牌错位。
- [ ] 样本只用于验收；正式流量已整体切到新系统，没有灰度或双系统。

## 立即否决条件

以下任一成立时，不能宣告上线或最终收口：候选 / digest 漂移；第二写入方或第二 Bot 连接；正式表出现意外删除、令牌覆盖或权限扩大；恢复演练失败；生产低于批准容量；用户不能到成功或可理解失败终态；观察时长未走满；需要生产现场改代码。
