- **指标 MCP 返回 502 时的语义（[#496](https://github.com/Moshuiwang/lingxi/issues/496)，2026-09-02 补登记，此前本文件零记载）**：问数 MCP 的 HTTP 502 是一个**稳定失败签名**（`mcp.query.http_502`），**不进入恢复重试**——不把它当成可以重跑一遍就好的抖动。用户为此收到的是**一条诚实的失败告知**，不是静默重试后的空结果或超长等待；管理员侧有对应的可见文案。**未验证**：stage 上没有真实制造过 502 的那个环节，这条语义的证据来自代码与单测，不是真实故障注入。

### 已验证的 Claude 执行链路事实

以下包含前身项目生产复现及 [Issue #23](https://github.com/Moshuiwang/lingxi/issues/23) 受控验证，是执行层选型输入，不代表用户问数能力已上线。背景详见[Claude 执行链路的已验证事实与管道投递风险](参考证据/Claude执行链路的已验证事实与管道投递风险.md)。

- 百炼兼容端点可承载 Agent 会话（L4a），前身项目「运行完成但用户侧空结果」根因**不是百炼**，是 `claude` CLI 非 TTY 管道下可能不写出终止事件（已由生产复现确认）。Agent SDK `0.2.128`+真实百炼+只读 MCP：40/40 回合非空正文与唯一终止结果，39/39 正式回合哈希一致，未见空结果或截断。**双向流式非 TTY 路径的投递在该固定组合下成立。**受控 Skill 可加载，`PreToolUse`/`PostToolUse`/`Stop` 可采集。
- **`allowed_tools`+`dontAsk` 不是严格白名单**（未禁用的 `CronCreate` 被实际执行），但**`PreToolUse` 拒绝是执行前真阻止**：非白名单调用全部被拒且无副作用，只读边界**可以做成强制的**。**权限拒绝没有 hook 回调**，但消息流仍可采集（`is_error=True` 块）；`PostToolUseFailure` 语义是「工具抛错」而非「用户没拿到结果」，被 MCP 包成正常响应的业务失败不会触发它。
- **只读工具边界已进入可执行 worker 并通过 L4a**（Issue #37/#51）：越权 `Write` 执行前被拒无副作用，业务失败记为 `not_obtained`，正常结果记为 `obtained`，审计保留两条知情接受的脱敏缺口（`V-审计-03`）；仅证明单回合 worker 接缝，不代表飞书入口已接入。**`disallowed_tools` 拒绝完全静默，制造审计盲区**，只能作纵深防御外层；**子代理启用会产生 2 个终止结果**，与「恰好一次」冲突，首期对 `Agent`/`Task` 保持默认拒绝。
- **身份链路与银河权限正式组件已合并并完成已认领范围 L4a**（2026-08-06，Issue #51）：加密凭据可轮换且不进业务库，目录适配器完整遍历，花名册以人员 ID 唯一关联 710 人，银河五表完整导入，1 条真实私聊样本可定位并得「准备建档」判定（仅验 1 人）。**仍未接线**：正式首聊入口、持续同步、建档、权限发布、用户通知。
- **银河权限输入来源当前是可替换的临时导入**（[决策记录](决策记录/2026-07-26-自动准入与数据库权限发布边界.md)）：仅作落库副本输入，运行时只认数据库当前有效记录；刷新为每日花名册之后执行，导入代码不得写死文件格式。

### 已验证的 Bot-Test 已开通用户问数闭环事实

以下是 2026-08-16 在 `biai-stage` + Bot-Test 完成的 Epic A / S-A-07 真实受控验收（[Issue #154](https://github.com/Moshuiwang/lingxi/issues/154)），证据层级 **L4a**，部署对象为 PR #174 冻结候选 `38790f5` 不可变镜像，每轮均用一次性隔离验收库并已删除回读，逐条 r 编号见 Issue #154 评论区。**这些事实只覆盖已开通状态的 Bot-Test 测试身份**；首次开通、生产环境和真实员工入口不在其中，边界见本节末尾。

- 正常问数（r14）、忙碌期普通消息只提示不入队（r4）、`/stop` 唯一停止终态（r4）、`/new` 空闲态固定成功文案与上下文清空、忙碌态只回忙碌提示（r15）均得到干净终态；加表情在真实飞书可见，无 `reaction.failed` 告警。
- 重复入站事件幂等：受控脚本重放同一事件，第二轮判重，隔离库仅 1 任务 1 终态（r19，**这是受控重放，不是平台真实重投**）。墙钟超时（`running_timeout`，r11）与最大 Agent 轮数超限（`max_turns_exceeded`，r16）是两个可区分的独立终态，后者此前会被压平为 `session_failed`（[#90](https://github.com/Moshuiwang/lingxi/issues/90) 修复对象）。
- 在途消费者重启不丢结果不重复交付（r9）；卡片故障降级为同话题文本终态不重复交付，仅关闭失败不产生第二条文本（r18）；两条投递路径都失败时不误报送达、不自动重发，停在 `awaiting_delivery`；`delivery_expired` 到期后收敛，用户仅收到一次固定过期提示（r20）。**边界**：24 小时为硬编码值，验证的是到期后收敛，**不是真实等满 24 小时**。
- 会话内结果依赖型追问 `resumed_session=true`（r4，**边界**：白名单只放行 `list_metrics`，验证的是**指标列表**追问，**数值结果追问未验证**）；会话空闲满两小时由系统到点清除正文与会话 JSONL，不依赖下一次任务入队（r12）；输出安全两档：`withheld` 档拦截提示无业务结果，`masked` 档幸存正文加占位符（r17，**边界**：该 canary 是**确定性注入夹具**，只证明「对已登记内容命中处理正确」，**不证明**能识别未登记的敏感内容）。

**这些结论明确不覆盖的范围，不得写成能力**：生产环境（`biplus-prod`/`Bot-Prod` 仍未接入）；**真实员工首次自动开通**（`OnboardingRunner` 仍是失败关闭桩，已开通身份为单独授权登记，**不构成 #65 任何证据**）；花名册与银河匹配、权限发布链、云盘目录产物、管理员链路（本次一条都没有真实验证）；上游状态变化感知（无可安全切换的账号状态，按「不适用」处理）；**`user_read` 仍是未知**（`platform_received` 只表示平台接收，**窗口外一律记为未知**）；仍打开的跟踪项 [#142](https://github.com/Moshuiwang/lingxi/issues/142)、#175、#185 不随 S-A-07 关闭。

- **九十天擦除之后不再把「没变的权限」误判成「变了」**（rc25 S-3a P-3，迁移 `0086_publish_outbox_digest`）：发布意图新增两列 SHA-256 摘要，「这一版和上一版一样吗」不再依赖会被九十天擦除的 `payload`；此前擦除之后判据读到空对象，一份内容完全没变的权限被判成变了，于是重排一条发布并把该用户的记忆与全部会话已送达正文清空——用户侧表现为「什么也没发生，记忆和历史答案却没了」。**两列不参与九十天擦除**；已擦过的历史行保持 `NULL`、读侧退回原 `payload` 比较，行为逐字不变。
- **会话转录清理改用文件名白名单与逐字相等的路径比对**（rc25 S-3b）：不再用可被会话 id 里的元字符撑开的模式匹配，归档路径也先校验再拼。**残余如实**：能写数据库的人仍可用另一个用户的**真实**会话 id 把那份转录搬进自己的归档目录（转录树按工作目录分、不按用户分，本模块拿不到归属判据）。
- **载体到期清理四面已接线**（Trace [#643](https://github.com/Moshuiwang/lingxi/issues/643) IN-04，迁移 `0089`）：任务问题原文（`task.prompt`）、入站事件、待确认操作、队列失败通知四个内容载体分别到期脱敏或删除，四面各自独立事务、一面失败不拖累其余三面。**截至 `main@f78aa17`（2026-09-06 合并）已改并经 CI 全绿；生产未部署、预发未验证**。此前「触发器只是组件里程碑、四角色未连库」（截至 2026-08-06/08，[Issue #64](https://github.com/Moshuiwang/lingxi/issues/64)，L2）的状态已被本条取代；保留规则其余未验证项见[尚待实现和验收 · 保留、审计与验收](#保留审计与验收)。
