# 当前能力

> 能力证据最后核对：2026-07-23。产品规则最后核对：2026-07-26。这里只记录已经确认、仍有效且会影响用户预期的事实；目标体验见[产品合同与外部边界](产品合同与外部边界.md)，计划、讨论和进度不在此维护。

## 当前状态

- 产品名称已确定为 Lingxi。首期面向所有内部用户，三名真实用户仅用于首期试用验收；飞书私聊和 JumpServer 高级工作台均纳入首期，只有 JumpServer 受公司内部局域网限制。自动准入、权限变化、话题并发、可信结果、交付、数据保留和真实验收规则已经形成产品合同与长期决策。
- 本项目已建立跨设备、跨代理的协作入口：GitHub Project、中文 Issue 标签、Issue 表单、PR 模板及仓库级 AI 规则。
- 业务产品能力尚未经过实际接入与验收；不得向用户承诺自动建档、数据库权限匹配、飞书多维表格权限发布、用户环境创建、MCP 查询、Claude 对话、飞书文档或电子表格交付，或 JumpServer 高级工作台已经可用。
- 产品合同中的自动处理规则是后续实现和验收依据，不是上线证明。

## 已验证的飞书关联组织边界

以下为 2026-07-23 使用 `StarTimes` 自建应用与关联免费租户进行的接口验证；它们是身份方案的输入，不代表 Lingxi 用户准入、问数或文档交付能力已经上线。

- 中心应用可用应用身份遍历关联组织共享范围，获得共享成员的 Bot `open_id`，并已验证可向该 ID 发起跨租户 Bot 单聊。
- 中心应用不能用工作邮箱直接在关联组织中检索成员，也不能以应用身份通过标准通讯录资料接口读取关联组织成员邮箱。
- 用户完成飞书授权后，可用用户身份从关联组织接口获得该用户的 `user_id`、`open_id` 与 `union_user_id`；已验证的响应不含标准邮箱字段。
- 用户身份令牌是短期凭据；无论后续通过何种有效方式取得必要信息，都不得把该令牌作为持久用户资料、日志字段或交付物保存。
- 详细证据、接口与历史探索过程见[飞书关联组织身份与注册鉴权参考证据](参考证据/飞书关联组织身份与注册鉴权-handoff.md)。

## 尚待实现和验收

- 首次对话能否自动、完整取得中文姓名、`open_id`、`user_id`、`union_id`、部门和租户信息。
- 生产数据库的具体产品、托管方式、备份恢复和 `biai-stage` 测试数据库隔离方案；这些实现选择尚未确定，但不改变“生产数据库是正式用户权限唯一权威来源”的产品规则。
- 数据库权限记录的字段、变更责任和有效性，以及按中文姓名首次唯一匹配的正常、未查到、重名和异常流程。
- 未开通用户始终收到产品介绍和确认提示、精确回复“确认”才触发数据库匹配、开通成功时展示当前公司和职能范围、开通前内容不保存且开通后由用户重新提问的完整体验。
- 产品负责人提供银河用户数据后，“确认”即时触发数据库匹配且不做逐人预核对的完整体验；异常用户才进入人工核对。
- 统一 `user` 用户表，以及飞书身份、数据库权限和 Lingxi 状态的最小化保存、停用与审计规则。
- 自动准入、用户环境创建、数据库到飞书多维表格再到 MCP 的权限发布与生效确认完整链路。
- 新增权限确认后生效、权限收回立即停止相关查询和交付、调岗精确收回及用户通知的完整链路。
- 同一对话的多轮上下文、`/new` 重置当前所在私聊或话题且不影响其他话题，以及超过两小时自动新对话。
- 收到消息立即添加表情、不同飞书话题并发、同一话题运行中消息只提示且不入历史，以及 `/stop` 只停止当前话题后续处理、不撤回既有产物并说明停止阶段的完整体验。
- 飞书问数是否满足公司、指标、时间、数据最新时间和关键结果均可核对，以及三轮内收敛和阻断错误门槛。
- 业务标题、短状态、逐步回答、完成耗时和同话题普通文本兜底的飞书交付样式。
- 仅向当前用户交付飞书文档、电子表格、图片和其他允许文件的真实结果，以及送达不确定时不重复发送的体验。
- 在有效公司和职能范围内由 MCP 决定数据源、数据粒度和下钻程度，Lingxi 不增加独立限制的真实查询边界。
- Lingxi 后台聊天和结果三十天、飞书聊天按飞书及公司规则保留、最小审计九十天、公司内部审计可按授权复核完整聊天及敏感业务内容、正式飞书产物由用户管理及中间文件及时清理的保留规则。
- Lingxi 与独立审计治理能力的长期边界：后者可接收审计事实用于风险复核和持续优化，但不接管开通、权限或问数主链路；该集成尚待实现和验收。
- 用户通过飞书之外的方式单独申请 JumpServer、管理员在链路外通知、飞书与 JumpServer 不共享上下文，以及正式产物仍通过飞书交付的完整体验。
- 三名真实业务用户覆盖至少两种职能、两种公司权限范围并连续试用七个工作日的首期真实验收。

本文件不以文档完成、Issue 关闭、代码存在或 CI 通过作为能力上线证据；只有在真实用户路径上完成可复验的接入和验收后，才能把对应条目改为当前能力。
