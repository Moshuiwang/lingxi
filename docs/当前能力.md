### 已验证的 Claude 执行链路事实

以下包含前身项目生产复现及 [Issue #23](https://github.com/Moshuiwang/lingxi/issues/23) 受控验证，是执行层选型输入，不代表用户问数能力已上线。背景详见[Claude 执行链路的已验证事实与管道投递风险](参考证据/Claude执行链路的已验证事实与管道投递风险.md)。

- 百炼兼容端点可承载 Agent 会话（L4a）；前身项目「运行完成但用户侧空结果」根因**不是百炼**，是 `claude` CLI 非 TTY 管道下可能不写出终止事件（已由生产复现确认）。真实百炼+只读 MCP：40/40 回合非空正文与唯一终止结果。
- **`allowed_tools`+`dontAsk` 不是严格白名单**（未禁用的 `CronCreate` 被实际执行），但**`PreToolUse` 拒绝是执行前真阻止**，只读边界**可以做成强制的**；`PostToolUseFailure` 语义是「工具抛错」而非「用户没拿到结果」。
- **只读工具边界已进入可执行 worker 并通过 L4a**（Issue #37/#51）：越权 `Write` 执行前被拒无副作用。**`disallowed_tools` 拒绝完全静默，制造审计盲区**；子代理启用会产生 2 个终止结果，首期对 `Agent`/`Task` 保持默认拒绝。
- **身份链路与银河权限正式组件已合并并完成已认领范围 L4a**（2026-08-06，Issue #51）：加密凭据可轮换且不进业务库，目录适配器完整遍历，花名册以人员 ID 唯一关联 710 人。**仍未接线**：正式首聊入口、持续同步、建档、权限发布、用户通知。
- **银河权限输入来源当前是可替换的临时导入**（[决策记录](决策记录/2026-07-26-自动准入与数据库权限发布边界.md)）：仅作落库副本输入，运行时只认数据库当前有效记录。

### 已验证的 Bot-Test 已开通用户问数闭环事实

以下是 2026-08-16 在 `biai-stage` + Bot-Test 完成的 Epic A / S-A-07 真实受控验收（[Issue #154](https://github.com/Moshuiwang/lingxi/issues/154)），证据层级 **L4a**，部署对象为 PR #174 冻结候选 `38790f5` 不可变镜像，逐条 r 编号见 Issue #154 评论区。**只覆盖已开通状态的 Bot-Test 测试身份**；首次开通、生产环境和真实员工入口不在其中。

- 正常问数（r14）、忙碌期普通消息只提示不入队（r4）、`/stop` 唯一停止终态（r4）、`/new` 空闲/忙碌两态文案与清空（r15）均得干净终态；加表情在真实飞书可见。
- 重复入站事件幂等（r19，受控重放）；墙钟超时（`running_timeout`，r11）与最大轮数超限（`max_turns_exceeded`，r16）是可区分的独立终态。
- 在途消费者重启不丢结果不重复交付（r9）；卡片故障降级为文本终态不重复交付（r18）；两条投递路径都失败时停在 `awaiting_delivery`；`delivery_expired` 到期后收敛（r20，**验证的是到期后收敛，非真实等满 24 小时**）。
- 结果依赖型追问 `resumed_session=true`（r4，**数值结果追问未验证**）；两小时空闲清正文与 JSONL（r12）；输出安全两档 `withheld`/`masked`（r17，**确定性注入夹具，不证明能识别未登记的敏感内容**）。

**明确不覆盖、不得写成能力**：生产环境；**真实员工首次自动开通**（`OnboardingRunner` 仍是失败关闭桩，**不构成 #65 任何证据**）；上游状态变化感知（无可安全切换的账号状态，按「不适用」处理）；花名册与银河匹配、权限发布链、云盘目录产物、管理员链路；**`user_read` 仍是未知**；跟踪项 [#142](https://github.com/Moshuiwang/lingxi/issues/142)、#175、#185 不随 S-A-07 关闭。

- **飞书文档（docx）交付改用飞书服务端一次建档写全文**（rc25 S-7c，[Issue #538](https://github.com/Moshuiwang/lingxi/issues/538)）：含表格答案不再整篇降级成纯文本，四步检查点与幂等机制不变。**证据等级：全局 6**（2026-09-04 生产真人问数：文档块 API 回读 624 块、3 张表格 301 单元格，结构齐全无降级）。
- **docx 降级与失败语义有三个原因码**：正文超 20 000 字符（`body_too_long`）与标题含尖括号（`title_not_embeddable`）两道**前置守卫**改走纯文本段落并明示降级；`server_simplified_body`（服务端自陈简化）时不改路不重试、只如实告知；建档超时一律判「结果不明」、绝不重试。**已知缺口**：三个原因码未登记进管理台显示名词表，`/admin trace` 只显示机器码。
- **⚠️ 已知边界：服务端静默丢块，我们察觉不到**：原始 HTML 块被丢弃、不产生 warning、`result` 仍 `success`，**不得声称「所有降级都会被如实告知」**；该接口无官方文档，20 000 字符守卫是实测安全带、非官方数字。
- **飞书电子表格交付**（[Issue #354](https://github.com/Moshuiwang/lingxi/issues/354)）：真实建表、「可管理」授权、内容逐格正确，`=`/`+` 开头单元格按文本存储。**证据等级：全局 6**。
- **随对话在线文档的交付与授权**（**全局证据 6 级**）：私聊要求文档 15 秒内收到带预览卡的链接、「可管理」权限、正文完整。**跨租户「可管理」授予与角色未降级已 L6 验证；完整处置动作清单（改权限/转移/删除）未实测**。
- **文档投递检查点幂等**：崩溃窗口已封死，真端点三前提坐实，已部署 stage。
- **等待卡片状态文案语义化**（**L4a**）：`querying:N` 在真实长查询中出场。
- **超大结果不再让会话崩溃**：9.3MiB 回执曾撞穿默认 1MiB 缓冲——上限抬至 32MiB，新增 `result_too_large` 分类。模型侧预判已在真实验收规避超限，结构改写兜底层仍待自然触发。

- **发布只在变化时回写**：既有行内容字段相同且密文仍在时判发布完成、零外部写入。
- **权限差集导入两道前置闸**（rc25 S-2d）：①值不干净（`*` 混入指标名/空白/不可见字符）→整份拒绝零写入；②导入工具 `--initiated-by` 须为有效管理员，否则退出码 2、零写入。**生产旧行是否真有这类字符：未知**（尚未回源）。
- **公司职能→指标外置映射覆盖每日重算与管理动作两侧**（`gateway` 的 `runtime-config` 挂载已由 [#585](https://github.com/Moshuiwang/lingxi/issues/585) 于 2026-09-05 补齐，与 `deploy/compose.prod.yaml` 现状一致）：变量要配就两侧同值同在，**生产当前两边都不配，是合法状态**。
