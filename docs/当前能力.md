# 当前能力

> 最后核对：产品规则 2026-07-26；外部平台能力证据 2026-07-23。这里只记录已经确认、仍有效且会影响用户预期的事实；目标体验见[产品合同与外部边界](产品合同与外部边界.md)，计划、讨论和进度不在此维护。

## 当前状态

- 产品名称已确定为 Lingxi。首期面向所有内部用户；三名真实用户仅用于首期试用验收。飞书私聊和 JumpServer 高级工作台均纳入首期，只有 JumpServer 受公司内部局域网限制。自动准入、管理员通过 AI Agent 与管理 MCP 处理异常、本人飞书私聊卡片确认高风险动作、权限变化、话题并发、可信结果、交付、数据保留和真实验收规则已经形成产品合同与长期决策。
- 本项目已建立跨设备、跨代理的协作入口：GitHub Project、中文 Issue 标签、Issue 表单、PR 模板及仓库级 AI 规则。
- **业务产品能力尚未经过实际接入与验收。**不得向用户或管理员承诺自动建档、数据库权限匹配、飞书多维表格权限发布、用户环境创建、专属云盘目录、问数 MCP 查询、Claude 对话、管理 MCP、管理员飞书确认卡片、飞书文档或电子表格交付，或 JumpServer 高级工作台已经可用。
- 产品合同中的自动处理规则是后续实现和验收依据，不是上线证明。

## 已验证的飞书关联组织事实

以下为 2026-07-23 使用 `StarTimes` 自建应用与关联免费租户进行的接口验证；它们是身份方案的输入，不代表 Lingxi 用户准入、问数或文档交付能力已经上线。

- 中心应用可用应用身份遍历关联组织共享范围，获得共享成员的 Bot `open_id`，并已验证可向该 ID 发起跨租户 Bot 单聊。
- 用户完成飞书授权后，可用用户身份从关联组织接口取得该用户的 `user_id`、`open_id` 与 `union_user_id`。这是产品合同中开通流程取得三类 ID 的有效路径。
- 中心应用不能用应用身份取得同样信息：`trust_party` 系列接口以应用身份调用返回 `1971007 App not visible to target tenant`。因此开通流程必须包含一次用户授权，不能设计成纯后台无感开通。
- 中心应用不能用工作邮箱直接在关联组织中检索成员，也不能以应用身份通过标准通讯录资料接口读取关联组织成员邮箱；已验证的用户身份响应也不含标准邮箱字段。
- 关联组织共享范围接口返回的成员名称是多语言对象，应读取 `name.default_value`；该默认值的语言取决于来源租户配置，不保证一定是中文姓名。
- 用户身份令牌是短期凭据；无论后续通过何种有效方式取得必要信息，都不得把该令牌作为持久用户资料、日志字段或交付物保存。
- 详细证据、接口与历史探索过程见[飞书关联组织身份与注册鉴权参考证据](参考证据/飞书关联组织身份与注册鉴权-handoff.md)。

## 尚待实现和验收

以下全部**尚未实现**，按用户旅程分组，用于后续逐项转正为当前能力。

**开通**

- 未开通用户始终收到开通引导卡片、点击「开始使用」或文本确认才触发开通、点击「暂不需要」后不再重复完整卡片的完整体验。
- 引导用户完成飞书授权，并自动、完整取得姓名、`open_id`、`user_id`、`union_id`、部门和租户信息。
- 开通过程在同一张卡片上流式展示进行到哪一步、每一步是否成功，且不暴露内部标识。
- 产品负责人提供银河用户数据后，用户确认即时触发数据库匹配且不做逐人预核对。
- 三种匹配结果分别得到正确处理：唯一命中自动开通；查不到时直接给出“联系 BI 同事开通银河权限”的终态且不生成人工待办；重名或记录不完整时才转人工核对。
- 权限发布后立即校验当前用户的 MCP 权限，之后每三分钟一次、最多十五分钟；同步期间不宣告成功，超时转人工，明确确认当前用户可以问数后才通知开通成功并展示当前公司和职能范围。
- 开通前发送的内容被丢弃；成功卡片不提供固定业务示例或可点击建议，只提示用户可以自然语言询问“你能查什么”。
- 统一 `user` 用户表，以及飞书身份、数据库权限、专属云盘目录和 Lingxi 状态的最小化保存、停用与审计规则。
- 自动准入、用户环境创建、数据库到飞书多维表格的权限发布链路，以及当前用户 MCP 权限同步与问数就绪确认；Lingxi 不复制 MCP 的逐条数据过滤。
- 生产数据库的具体产品、托管方式、备份恢复和 `biai-stage` 测试数据库隔离方案；这些实现选择尚未确定，但不改变“生产数据库是 Lingxi 准入、权限记录和发布内容唯一权威来源”的产品规则，实际问数范围仍由外部 MCP 决定。
- 数据库权限记录的字段、变更责任和有效性。

**管理员处理**

- 为重名、必要信息缺失、状态不可判定、环境创建异常和 Lingxi 侧权限发布异常建立可恢复、可追踪的管理待办。
- 管理员以个人身份通过经批准的 AI Agent 连接 Lingxi 管理 MCP；管理 MCP 身份绑定唯一的本人飞书身份，共享身份和普通业务用户不能查询或准备管理动作。
- 管理 MCP 按权限管理员、运维管理员和超级管理员三类角色分别提供能力：权限管理员处理用户准入和问数权限，运维管理员处理环境和同步异常，超级管理员新增或移除三类管理员；没有超级管理员时由持有服务器 Root 权限的 Ops 运维工程师通过受控流程恢复一个身份已经核实并绑定飞书的现有用户。
- 选择正确数据库记录并继续开通、终止开通、收回权限、停用、恢复、删除用户、安全重试和管理员角色变化等写操作先形成待确认动作，不由 AI Agent 或 MCP 直接执行。
- 待确认动作发送到管理 MCP 身份所绑定的本人飞书私聊；卡片发送失败、过期、重复、角色被收回、目标状态变化、回调不明或审计失败均不执行。
- 受控管理群只接收待办和结果通知，不提供审批卡片、管理命令或群内执行入口。
- 管理查询、准备动作、卡片确认或取消、执行结果和拒绝结果形成可关联的审计记录，并在真实管理 Agent、真实管理 MCP 和真实飞书卡片链路上完成验收。

**问数与会话**

- 每次查询前读取当前有效的 Lingxi 用户与服务状态、权限变化发布到飞书多维表格并确认 MCP 同步、账号停用后阻止新问数但允许已开始任务正常完成、调岗记录更新及用户通知的完整链路。
- 同一对话的多轮上下文、`/new` 重置当前所在私聊或话题且不影响其他话题。
- 按“上一条任务结束到下一条新任务开始超过两小时”开启新会话，且任务执行时长本身不触发新会话。
- 收到消息立即添加表情、不同飞书话题并发、同一话题运行中消息（含 `/new`）只提示且不入历史不排队，以及 `/stop` 只停止当前话题后续处理、不撤回既有产物并说明停止阶段的完整体验。
- 飞书问数是否满足公司、指标、时间和关键结果均可核对，MCP 返回数据最新时间时展示、未返回时直接省略，MCP 未返回数据时不推断权限原因，以及三轮内收敛和阻断错误门槛。
- 用户自然语言询问“你能做什么”或“我能查哪些指标”时，Agent 根据 MCP 当前指标列表和说明回答；不实现 `/help` 命令或由 Lingxi 维护的固定能力清单。

**交付**

- 业务标题、正文底部当前动作与低频耗时、逐步回答、完成总耗时和同话题普通文本兜底的飞书交付样式；不展示预计剩余时间或内部过程日志。
- 为每个用户创建机器人名下的专属云盘目录，仅授予本人读写，并把全部正式产物创建在该目录内。
- 仅向当前用户交付飞书文档、电子表格、图片和其他允许文件的真实结果，交付前确认授权成功，以及送达不确定时不重复发送的体验。
- 只有已经完成当前权限同步验证的用户才能通过问数 MCP 查询；实际可见的数据范围、数据源、数据粒度和下钻程度由 MCP 按该用户生效权限决定，Lingxi 不增加逐条数据过滤。

**高级工作台**

- 用户通过飞书之外的方式单独申请 JumpServer、管理员在链路外通知、飞书与 JumpServer 不共享上下文的完整体验。
- 用户在浏览器终端中进入本人环境并运行 Claude CLI。
- 统一的交付 Skill：复用飞书通道转换文档、写入该用户的同一专属云盘目录、把链接发送给用户本人。

**保留、审计与验收**

- 原始聊天、用户可见结果和技术审计记录统一保留九十天、飞书聊天按飞书及公司规则保留、公司内部审计可按授权复核完整聊天及敏感业务内容、正式产物由用户管理及中间文件及时清理的保留规则。
- Lingxi 与独立审计治理能力的长期边界：后者可接收业务问数和管理员处理审计事实用于风险复核和持续优化，但不接管开通、管理授权、权限或问数主链路；该集成尚待实现和验收。
- 三名真实业务用户覆盖至少两种职能、两种公司权限范围并连续试用七个工作日的首期真实验收。

本文件不以文档完成、Issue 关闭、代码存在或 CI 通过作为能力上线证据；只有在真实用户路径上完成可复验的接入和验收后，才能把对应条目改为当前能力。
