## 已验证的 Claude 执行链路事实

以下包含前身项目生产复现及 [Issue #23](https://github.com/Moshuiwang/lingxi/issues/23) 受控验证，是执行层选型输入，不代表用户问数能力已上线。背景详见[Claude 执行链路的已验证事实与管道投递风险](参考证据/Claude执行链路的已验证事实与管道投递风险.md)。

- 百炼兼容端点可承载 Agent 会话（L4a），前身项目「运行完成但用户侧空结果」根因**不是百炼**，是 `claude` CLI 非 TTY 管道下可能不写出终止事件（已由生产复现确认）。Agent SDK `0.2.128`+真实百炼+只读 MCP：40/40 回合非空正文与唯一终止结果，39/39 正式回合哈希一致，未见空结果或截断。**双向流式非 TTY 路径的投递在该固定组合下成立。**受控 Skill 可加载，`PreToolUse`/`PostToolUse`/`Stop` 可采集。
- **`allowed_tools`+`dontAsk` 不是严格白名单**（未禁用的 `CronCreate` 被实际执行），但**`PreToolUse` 拒绝是执行前真阻止**：非白名单调用全部被拒且无副作用，只读边界**可以做成强制的**。**权限拒绝没有 hook 回调**，但消息流仍可采集（`is_error=True` 块）；`PostToolUseFailure` 语义是「工具抛错」而非「用户没拿到结果」，被 MCP 包成正常响应的业务失败不会触发它。
- **只读工具边界已进入可执行 worker 并通过 L4a**（Issue #37/#51）：越权 `Write` 执行前被拒无副作用，业务失败记为 `not_obtained`，正常结果记为 `obtained`，审计保留两条知情接受的脱敏缺口（`V-审计-03`）；仅证明单回合 worker 接缝，不代表飞书入口已接入。**`disallowed_tools` 拒绝完全静默，制造审计盲区**，只能作纵深防御外层；**子代理启用会产生 2 个终止结果**，与「恰好一次」冲突，首期对 `Agent`/`Task` 保持默认拒绝。

## 已验证的 Bot-Test 已开通用户问数闭环事实

以下是 2026-08-16 在 `biai-stage` + Bot-Test 完成的 Epic A / S-A-07 真实受控验收（[Issue #154](https://github.com/Moshuiwang/lingxi/issues/154)），证据层级 **L4a**，部署对象为 PR #174 冻结候选 `38790f5` 不可变镜像，每轮均用一次性隔离验收库并已删除回读，逐条 r 编号见 Issue #154 评论区。**这些事实只覆盖已开通状态的 Bot-Test 测试身份**；首次开通、生产环境和真实员工入口不在其中，边界见本节末尾。

- 在途消费者重启不丢结果不重复交付（r9）；卡片故障降级为同话题文本终态不重复交付，仅关闭失败不产生第二条文本（r18）；两条投递路径都失败时不误报送达、不自动重发，停在 `awaiting_delivery`；`delivery_expired` 到期后收敛，用户仅收到一次固定过期提示（r20）。**边界**：24 小时为硬编码值，验证的是到期后收敛，**不是真实等满 24 小时**。
