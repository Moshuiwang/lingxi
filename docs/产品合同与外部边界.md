# 产品合同与外部边界

> 状态：草案。本文是本项目长期、稳定的产品事实；需求讨论、优先级、待决策事项和进度以 GitHub Issue / Project 为准。完整分工见[产品文档索引](README.md)。

## 产品是什么

Lingxi 是企业内部受控 AI 业务分析服务的入口。用户可在飞书中申请、提问、通过 Bot 聊天建立所需的飞书文档或飞书电子表格并接收交付，也可通过企业已搭建的 JumpServer 使用 SSH 登录服务器、进入自己的用户目录后运行 Claude，自动加载 MCP 进行数据查询；管理员在受控流程中处理权限与异常。

产品不替代数据平台、模型平台、协作平台或访问管理平台，而是在 MCP、Claude Code + 百炼、飞书和 JumpServer 提供的有效能力之上，提供清晰、安全、可追溯的用户体验。

## 用户体验承诺

- 用户以业务问题而非技术指令完成申请、提问和获取结果。
- 飞书与 JumpServer SSH 是可用的产品入口；用户可按自己的工作方式选择入口，且两种入口都不得扩大其获准的数据范围。
- 用户可在飞书 Bot 聊天中提出文档或电子表格需求；在飞书规则允许且创建、发送成功得到确认后，产品建立相应的飞书文档或飞书电子表格并发送给该用户。
- 通过 JumpServer SSH 入口时，用户在自己的服务器用户目录中运行 Claude；MCP 应自动加载，用户无需手工配置数据查询连接。
- 用户只能在已获准的数据范围内得到结果；无权、数据无法确认或服务不可用时，产品明确说明限制，不猜测、不伪造完成。
- 用户能够理解请求是在处理、等待外部依赖、需要补充信息、需要人工处理还是已经失败。
- 用户之间不共享会话、数据范围或交付物；关键授权变化可追溯。

## 外部依赖边界

| 依赖 | 它是权威来源 | 本项目不得做什么 |
|---|---|---|
| MCP | 数据查询能力、访问控制和查询结果语义 | 绕过、扩大或伪造授权结论；无法确认时给出确定数据结论。 |
| Claude Code + 百炼 | AI 任务执行、模型和工具的有效能力 | 承诺模型必然正确或可用；将模型输出伪装成未经验证的业务事实。 |
| 飞书 | 身份、消息、卡片、会话、飞书文档、飞书电子表格及交付规则 | 假定不存在的交互、会话、创建或发送语义；绕开平台权限创建或交付内容，或未获创建、发送确认便声称已交付。 |
| JumpServer | SSH 登录、服务器访问及用户目录隔离规则 | 绕开访问控制、共享或冒用用户目录与身份，或假定未获确认的登录、隔离或会话语义。 |

依赖异常时：未收到依赖确认不是成功；重试不得重复申请、授权或交付；用户只接收业务化、脱敏的说明。

## 不提供

- 绕过 MCP 授权、直接暴露生产数据源、令牌或认证材料。
- 向普通用户开放模型配置、内部路径或运行凭据。
- 未经明确规则与门禁的自动扩权、生产变更或高风险外部动作。
