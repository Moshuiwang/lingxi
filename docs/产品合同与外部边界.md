# 产品合同与外部边界

> 状态：现行。产品负责人于 2026-07-25 至 2026-07-26 在 [GitHub Issue #7](https://github.com/Moshuiwang/lingxi/issues/7) 对应任务中确认首期规则。本文记录 Lingxi 长期、稳定的目标体验与产品边界，不代表相应能力已经上线；实际可用能力以[当前能力](当前能力.md)为准，需求进度以 GitHub Issue / Project 为准。

## 产品是什么

Lingxi 是企业内部受控的 AI 业务分析服务。首期面向所有内部用户：未开通用户可以在飞书确认开通，数据库中已有明确有效权限的用户可以问数。用户通过飞书私聊提出问题，在 Lingxi 数据库中已经确定且当前有效的数据权限范围内获得分析结果，并可接收飞书文档、飞书电子表格或其他允许交付的产物。

飞书私聊和 JumpServer 高级工作台都属于首期范围。飞书私聊是默认入口，不受公司内部局域网限制；需要持续、深度分析且已经另行获批高级工作台的用户，只能在公司内部局域网通过 JumpServer 进入自己的用户环境并运行 Claude。高级工作台只是更重的使用方式，不增加数据权限，也不能绕过飞书入口的权限限制。

Lingxi 不替代银河、MCP、模型平台、飞书或 JumpServer，而是在这些平台提供的有效能力之上，形成自动准入、受控问数、连续对话和结果交付的完整用户体验。

## 用户与入口

| 角色 | 要完成的事 | Lingxi 提供的体验 |
|---|---|---|
| 未开通业务用户 | 了解 Lingxi 并决定是否开始开通 | 无论发送什么内容，都先收到产品介绍和开通确认提示；只有回复“确认”才开始自动开通。 |
| 已开通业务用户 | 问数、追问、理解趋势并取得交付物 | 开通成功后的下一条消息才进入正常问数；正常情况下无需填写权限申请或等待人工审批。 |
| 异常待核对用户 | 在身份或数据库权限记录无法唯一确认时继续开通 | 看到“正在人工核对”，创建过程暂停；管理员确认后再继续，不会被误报成功。 |
| 管理员 | 处理重名、未查到、信息缺失等异常 | 收到异常原因和必要的脱敏信息，人工确认正确数据库权限记录或终止创建。 |
| 高级工作台用户 | 持续、深度或需要个人环境的分析 | 通过飞书之外的邮件或其他既定方式向管理员单独申请；获批后在公司内部局域网通过 JumpServer 进入自己的环境，沿用同一数据范围。 |
| 运维管理员 | 保持服务和入口可用 | 在受控流程中处理环境、外部依赖和可用性异常，不代替业务权限判断。 |

## 首次对话与自动准入

用户尚未开通时，无论发送什么内容，Lingxi 都只回复统一欢迎语。欢迎语说明机器人是什么、能够做什么、权限边界和“回复‘确认’开始开通”。除精确的“确认”外，其他内容不进入业务对话、不触发问数，也不作为开通后的首个问题保存；系统继续回复同一欢迎语。

用户回复“确认”后，系统才自动执行以下流程：

1. 从飞书取得当前用户的中文姓名，以及开通、投递和后续核对所必需的 `open_id`、`user_id`、`union_id`、部门、租户等信息。
2. 建立统一用户记录，关联该用户的飞书身份、银河来源信息、数据库权限记录和 Lingxi 内部状态。
3. 产品负责人提供的银河用户数据已经通过受控流程进入 Lingxi 数据库后，用飞书中的中文姓名与数据库中当前有效的用户权限记录进行匹配。
4. 只有在姓名唯一命中且权限记录完整时，才自动确认用户身份；用户的公司和职能范围直接采用该数据库记录，不由用户自行选择。
5. 系统自动完成准入和用户环境创建，将数据库确认的权限通过飞书多维表格发布给 MCP，并确认权限实际生效。全部完成后，用户才进入问数体验。

收到“确认”后立即开始匹配和开通过程，不要求首批名单中的用户事先逐人完成身份核对，也不把预核对白名单作为上线门槛。正常路径不设置人工审批，也不要求用户填写公司、职能或申请理由；首次开通过程可以包含自动核验、用户环境创建、权限发布和可用性确认，只有异常才转人工处理。自动处理不产生或扩大数据库中不存在的权限；飞书多维表格只传递数据库已经确认的权限，不能反向创建、修改或扩大用户权限。

开通成功后，系统明确告诉用户可以开始提问，并展示当前可用的公司和职能范围；系统不自动执行开通前发送的任何内容。用户需要重新发送自己的第一个业务问题，后续才进入正常问数流程。

## 匹配异常与人工处理

以下情况属于身份或权限名单异常：

- 中文姓名未在数据库的当前有效权限记录中查到；
- 中文姓名匹配到多条记录；
- 飞书必要信息、数据库权限记录、公司或职能范围缺失或无法确认；
- 数据库权限状态不可用、过期或结果无法判定。

出现异常时：

- 立即暂停该用户的创建过程，不继续问数，不发布不确定权限，也不部分宣告成功；
- 向用户说明正在人工核对，无需用户理解内部系统或自行选择权限；
- 向管理员发送异常原因和处理所需的脱敏信息；
- 自用户进入“正在人工核对”起，一个工作日内至少向用户提供一次明确进展或最终结论；这是服务承诺，不要求 Lingxi 自动催办或自动处理人工核对；
- 管理员确认唯一正确的数据库权限记录后，系统从暂停点继续；
- 无法确认或管理员决定终止创建时，用户收到明确的未开通结果、脱敏原因和可采取的下一步，不会永久停留在“正在核对”；
- 不允许模糊匹配、按相似姓名猜测，或用管理员权限替代用户权限完成开通。

环境创建、权限发布或可用性确认未获得明确成功结果时，不重新进入身份核对。系统暂停在相应步骤并通知运维管理员；运维先核对实际状态，再从尚未确认完成的步骤安全恢复。不得盲目重跑整个流程，避免重复创建环境、重复发布权限或重复通知用户。恢复成功后通知用户可以使用；最终无法恢复时通知用户尚未开通，并说明由谁继续处理。

## 统一用户记录与权限变化

Lingxi 数据库必须建立统一的 `user` 用户表，以一条用户记录关联三类信息：

- **飞书信息**：中文姓名、`open_id`、`user_id`、`union_id`、部门、租户及后续投递所需状态；
- **权限信息**：匹配到的数据库权限记录、中文姓名、公司和职能范围，以及权限版本或核对时间；
- **Lingxi 信息**：内部用户标识、准入状态、用户环境状态、飞书多维表格发布状态、MCP 生效状态、启用或停用状态。

只保存完成身份关联、权限判断、服务和审计所必需的信息。飞书短期令牌、数据库认证材料、MCP 令牌明文及其他凭据不得进入用户表、日志、Issue、文档或用户交付物。

银河提供首期用户和权限的上游业务数据；数据经过受控流程进入 Lingxi 数据库后，数据库中的当前有效记录是运行时权限、公司和职能范围、启停状态的唯一权威。

- 新增权限只有在数据库记录更新、飞书多维表格发布完成且 MCP 实际可用得到明确确认后，才向用户宣告生效。
- 权限收回、用户离职或账号停用一经数据库确认，立即禁止相应范围的新查询和新交付，不等待新会话。
- 正在执行的任务如涉及刚被收回的范围，应停止并告诉用户权限已经变化；不得继续使用旧权限完成结果。
- 调岗时只收回明确失效的范围，不影响仍有效的公司和职能；恢复账号时不自动恢复曾被收回的权限。
- 每次权限变化都通知用户本人，说明本次变化和当前仍可使用的范围；状态无法确认时暂停相关服务并转人工核对。

## 问数与多轮对话

- 收到可执行的问题后，Lingxi 立即给该条飞书消息添加一个表情，表示已经收到；表情添加失败不影响任务继续执行。
- 同一用户在当前对话中连续提问时，Lingxi 保留该对话上下文，支持基于上一轮结果继续追问。
- 不同用户之间不共享对话、数据范围或交付物。
- 飞书私聊主窗口和每个由用户主动创建的飞书原生话题分别形成独立对话；不同话题可以并发执行，彼此不共享上下文。
- 同一话题同一时间只执行一个任务。任务仍在运行时，除 `/stop` 外的后续消息只收到“当前任务仍在处理中”的提示；该消息不进入对话历史、不排队，也不会在当前任务结束后自动提交。
- 用户在当前话题发送 `/stop` 时，Lingxi 停止该话题仍在运行的后续处理并明确回复停止阶段和已产生的结果；其他话题的任务不受影响。已经成功创建或发送的消息、文档、表格或图片不自动撤回。
- 用户在私聊主窗口或某个飞书话题中输入 `/new` 时，立即清空当前所在对话的上下文；后续消息在同一位置以新上下文继续，其他话题不受影响。
- 用户再次发消息时，如果距离当前对话的上一条消息已经超过两小时，系统自动开启新对话。
- 新对话不携带旧对话上下文，但继续使用该用户当前有效的身份、公司和职能范围，无需重新创建用户或重新准入。
- 系统明确告诉用户已经开启新对话，不让用户误以为旧上下文仍然有效。
- 用户问题不清楚、范围存在歧义或数据无法确认时，系统通过追问澄清，不自行猜测。

## 问数结果的可信标准

- 数据结果必须让用户看清本次采用的公司、指标、时间范围、数据最新时间，以及关键数字或趋势。
- 公司、指标或时间范围存在歧义时先追问；不能把相近指标、相近公司或猜测结果当作用户所问内容。
- 数据不存在、权限不足、数据延迟或外部结果不完整时，明确区分并说明下一步，不把空结果或不确定结果标为完成。
- 用户经过一至三轮澄清后，应获得可用答案、明确失败说明或正确的权限拒绝；持续追问但无法收敛不能视为成功。
- 关键数字错误、指标口径错误、越权或泄露、三轮内既未收敛也未正确拒绝，均属于不能上线或继续放量的阻断问题。

## 结果与交付

- 普通分析结果优先通过流式卡片展示。卡片标题使用公司、指标、时间范围等业务主题；状态区只展示“正在处理”和低频耗时，回答区逐步展示用户可见内容；完成时明确显示完成和总耗时。
- 流式卡片创建、更新或关闭失败时，在同一私聊或同一飞书话题用普通文本补发完整结果，不把回复散到其他位置。
- 完成态必须包含可见结果、明确的澄清问题或可理解的失败说明；内部 Agent 名称、过程日志和技术状态不占据用户结果主体。
- 用户要求文档时，优先创建并只交付一个飞书文档链接；不把内部 Markdown 文件作为默认交付物。
- 用户要求表格时，优先创建并交付飞书电子表格。
- 用户要求图片时，应在飞书中直接可见、可打开或可下载，不暴露服务器路径。
- 交付只有在飞书确认创建和发送成功后才能宣告完成；送达状态不确定时明确说明并要求核对，不自动重复创建或重发。
- 用户只能收到在本人当前公司和职能权限范围内、为本人任务生成且允许交付的产物；不得发送其他用户文件、内部配置或认证材料。
- 首期只把交付物发送给当前用户，不由 Lingxi 直接发送给其他个人或群聊。用户可以在飞书中自行决定是否分享；若未来由 Lingxi 扩大接收人范围，必须重新核对接收人的数据权限。

## 数据保留与删除

- 当前会话上下文在用户输入 `/new` 重置当前所在对话，或超过两小时自动开启新会话后，不再带入后续问答。
- Lingxi 后台保存的原始聊天和用户可见结果默认保留三十天，用于用户找回、问题排查和质量复核；到期后删除或脱敏。该周期不删除飞书聊天记录，飞书侧记录按飞书及公司规则保留。
- 最小技术审计记录默认保留九十天。公司内部审计在获得相应授权后，可以审计完整聊天记录、完整业务内容及其中的敏感内容；审计访问、用途和留存按公司审计制度管理并可追溯。
- 已交付的飞书文档和电子表格是用户取得的正式产物，不由 Lingxi 在三十天后自动删除，由用户按照飞书和公司规则管理。
- 一次性交付区和内部中间文件在交付完成、失败或送达状态不明后按最短必要时间清理，不作为长期用户资产。
- 用户被彻底删除后，停止服务并删除仍可识别的运行数据；依法或依公司制度必须保留的审计内容应先脱敏。

## 审核、审计与持续优化方向

Lingxi 的开通、问数、权限判断、任务执行和飞书交付构成面向用户的主链路。审核、审计与持续优化采用独立治理能力，不接管用户问数或反向决定用户权限；首期不承诺自动审核、实时风险拦截或审核工作台。

Lingxi 应稳定记录能够关联用户、话题、任务、权限版本、MCP 查询、交付、停止或失败及人工核对结论的审计事实，供后续独立治理项目使用。公司内部审计在获得相应授权后可以复核完整聊天和敏感业务内容。治理工作以发现问题、归类原因、形成改进项和复核效果为闭环，但不得扩大用户的数据权限或改变用户的正常问数体验。详见[审核审计与持续优化治理边界决策](决策记录/2026-07-26-审核审计与持续优化治理边界.md)。

## 系统与外部依赖边界

| 系统或依赖 | 在产品中的职责 | Lingxi 不得做什么 |
|---|---|---|
| 飞书 | 当前会话中的用户身份信息、部门与租户信息，以及消息、卡片、会话和交付规则 | 假定不存在的信息或交付结果；未获得必要信息时继续自动创建用户。 |
| 银河 | 首期用户和权限的上游业务数据 | 未经受控流程直接改变运行时权限；让用户自行扩大范围；对未查到或重名记录进行猜测。 |
| Lingxi 数据库 | 用户权限、公司和职能范围、启停状态的唯一权威来源 | 让用户自行扩大范围；对未查到或重名记录进行猜测；用任何下游副本反向覆盖数据库权限。 |
| 飞书多维表格 | 将数据库已确认的用户权限发布给 MCP 的下游通道 | 把表格内容当作权限权威；由表格反向创建、修改或扩大数据库权限。 |
| MCP | 在已成功发布并确认生效的公司和职能权限范围内，决定可查询的数据源、数据粒度、查询能力和结果语义 | 绕过或扩大数据库确定的公司和职能范围；发布状态不明时继续查询；无法确认时给出确定数据结论。 |
| Claude Code + 百炼 | 当前 AI 任务执行、模型和工具的有效能力 | 承诺模型必然正确或可用；将模型输出伪装成未经验证的业务事实。 |
| JumpServer | 独立于飞书开通链路的高级工作台登录、服务器访问及用户环境隔离规则 | 把高级工作台作为更高权限入口；共享或冒用用户环境与身份；要求飞书会话与高级工作台共享上下文。 |
| 独立审计与治理能力（可由 `bi-agent-audit` 承载） | 接收 Lingxi 审计事实，支持风险复核、质量分析和持续优化 | 反向决定用户权限、接管 Lingxi 的开通或业务查询主链路，或改变正常用户问数体验。 |

数据库记录、飞书多维表格发布结果与 MCP 实际生效状态不一致，或任何一步没有给出明确成功结果时，都不能视为权限已经可用。系统暂停查询并说明正在处理，不从下游结果猜测或反写权限。自动重试不得造成重复建档、重复授权、重复创建环境或重复交付。

## 不提供

- Codex 飞书对话、多 Agent 自助选择或普通用户自行修改模型配置。
- 群聊中的自由业务问数；受控管理群只处理明确的管理动作。
- 用户自行申请、选择或扩大数据库当前有效记录之外的公司和职能范围。
- 在公司和职能权限之外再由 Lingxi 增加一套数据源或下钻粒度限制；首期可查询范围由 MCP 实际提供能力决定。
- 绕过权限数据库或 MCP，直接暴露生产数据源、令牌、认证材料或内部路径。
- 用 JumpServer 高级工作台绕过飞书入口或数据库权限。
- 在公司内部局域网之外使用 JumpServer 高级工作台。
- 未经明确规则与门禁的自动扩权、生产变更、自动部署或高风险外部动作。
