# 产品合同与外部边界

> 状态：现行。产品负责人于 2026-07-25 至 2026-07-26 在 [GitHub Issue #7](https://github.com/Moshuiwang/lingxi/issues/7) 对应任务中确认首期用户规则，并在 [GitHub Issue #9](https://github.com/Moshuiwang/lingxi/issues/9) 对应任务中确认首期管理员入口。本文是 Lingxi 长期目标体验与产品边界的唯一规则正文；[长期决策记录](决策记录/README.md)只说明每条规则为什么这样定，不重复规则本身。本文不代表相应能力已经上线；实际可用能力以[当前能力](当前能力.md)为准，需求进度以 GitHub Issue / Project 为准。

## 产品是什么

Lingxi 是企业内部受控的 AI 业务分析服务。首期面向所有内部用户：未开通用户可以在飞书完成开通，数据库中已有明确有效权限记录且对应 MCP 权限已经确认同步完成的用户可以问数。用户通过飞书私聊提出问题，在外部 MCP 按该用户当前生效权限实际提供的数据范围内获得分析结果，并可接收飞书文档、飞书电子表格或其他允许交付的产物。

飞书私聊和 JumpServer 高级工作台都属于首期范围。飞书私聊是默认入口，不受公司内部局域网限制；需要持续、深度分析且已经另行获批高级工作台的用户，只能在公司内部局域网通过 JumpServer 进入自己的用户环境并运行 Claude。高级工作台只是更重的使用方式，不增加数据权限，也不能绕过飞书入口的权限限制。

Lingxi 不替代银河、MCP、模型平台、飞书或 JumpServer，而是在这些平台提供的有效能力之上，形成自动准入、受控问数、连续对话和结果交付的完整用户体验。

## 用户与入口

| 角色 | 要完成的事 | Lingxi 提供的体验 |
|---|---|---|
| 未开通业务用户 | 了解 Lingxi 并决定是否开始开通 | 无论发送什么内容，都先收到产品介绍卡片；只有用户主动确认才开始开通。 |
| 已开通业务用户 | 问数、追问、理解趋势并取得交付物 | 开通成功后的下一条消息才进入正常问数；正常情况下无需填写权限申请或等待人工审批。 |
| 数据库中没有权限的用户 | 知道自己为什么用不了、下一步找谁 | 收到明确的“当前没有数据权限”结论和申请指引，不进入等待状态。 |
| 异常待核对用户 | 在身份或数据库权限记录无法唯一确认时继续开通 | 看到“正在人工核对”，创建过程暂停；管理员确认后再继续，不会被误报成功。 |
| 管理员 | 处理重名、记录不完整、权限变化和账号异常 | 驾驭经批准的 AI Agent 查询待办、用户和权限；高风险动作在本人飞书私聊确认后才执行。 |
| 高级工作台用户 | 持续、深度或需要个人环境的分析 | 通过飞书之外的邮件或其他既定方式向管理员单独申请；获批后在公司内部局域网通过 JumpServer 进入自己的环境，沿用同一数据范围。 |
| 运维管理员 | 保持服务和入口可用 | 在受控流程中处理环境、外部依赖和可用性异常，不代替业务权限判断。 |

## 首次对话与自动准入

普通员工使用 Lingxi 时不需要点击身份授权卡片，也不需要完成浏览器 OAuth。系统根据已由专用组织授权同步的关联企业、部门和员工资料，自动匹配银河当前有效权限记录并继续开通。

- 未开通用户发来的业务内容不进入问数、不保存也不回显；系统直接启动自动匹配与开通，并向用户展示可理解的进度或最终结果。
- 未找到权限记录时，用户直接得到“当前没有数据查询权限，请联系 BI 同事开通银河权限”的结论；重名、资料不完整或状态不确定时转人工核对。
- 只有名为“四达文档会议助手”的专用授权用户需要收到一次组织资料授权卡片。该授权只用于读取关联企业、部门和员工资料，不能替代任何普通员工的身份或权限确认。

### 开通流程

普通员工首次使用时，系统自动执行以下流程，并展示当前进行到哪一步、每一步是否成功：

1. 使用“四达文档会议助手”已经授权并持续刷新的用户 token，同步其可见关联企业、部门和员工资料；普通员工不参与此授权步骤。
2. 普通员工私聊事件提供应用侧的发送者 `open_id`；系统只在同一应用语义下用该标识定位专用授权同步的员工资料，再取得姓名、`user_id`、`union_id`、部门和租户用于身份关联与后续投递。绝不把“四达文档会议助手”的授权身份当作员工身份。手机号、邮箱、职务、职级和工号不是权限匹配前提。
3. 建立统一用户记录，此时只关联该员工的飞书身份和 Lingxi 内部状态；数据库权限记录要等匹配确认后才写入，不得先占位再回填。
4. 产品负责人提供的银河用户数据已经通过受控流程进入 Lingxi 数据库后，用员工姓名与数据库中当前有效的用户权限记录进行匹配。
5. 只有在姓名唯一命中且权限记录完整时，才自动确认用户身份；用户的公司和职能范围直接采用该数据库记录，不由用户自行选择。
6. 系统自动完成准入和用户环境创建，为用户创建专属飞书云盘目录，并将数据库确认的权限发布到飞书多维表格。发布完成后进入“权限正在同步”，此时用户尚未开通成功，也不能进入正常问数。
7. Lingxi 立即通过问数 MCP 校验一次该用户的权限，之后每三分钟校验一次，最多等待十五分钟。只有明确确认该用户应有的公司和职能权限已经同步且可以问数后，才宣告开通成功。

流式展示的开通过程既让用户知道系统正在做什么、还要等多久，也让开通失败时可以直接定位到卡在哪一步；展示内容使用用户可理解的表述，不暴露内部标识、令牌或服务器路径。

权限同步期间，卡片明确显示“权限正在同步，预计最多需要十五分钟”，用户无需重复开通。十五分钟后仍未确认成功时，停止自动等待，转交管理员处理，并告诉用户“权限同步未完成，已转交处理，无需重复开通”；后续确认成功后再主动通知用户可以开始使用。服务在线、其他用户可以问数或权限已经写入飞书多维表格，都不能代替对当前用户的同步确认。

普通员工首次使用时立即开始匹配和开通过程，不要求首批名单中的用户事先逐人完成身份核对，也不把预核对白名单作为上线门槛。正常路径不设置人工审批、卡片授权或用户填写公司、职能、申请理由；首次开通过程可以包含自动核验、用户环境创建、权限发布和可用性确认，只有异常才转人工处理。自动处理不产生或扩大数据库中不存在的权限；飞书多维表格只传递数据库已经确认的权限，不能反向创建、修改或扩大用户权限。

### 开通成功后

只有当前用户的 MCP 权限同步已经明确验证通过，系统才告诉用户开通成功、可以开始提问，并展示当前可用的公司和职能范围。用户在开通前发送的内容一律丢弃：不执行、不保存、不回显、不作为建议再提供给用户。用户需要自己发送第一个业务问题，之后才进入正常问数流程。

成功卡片不提供预置的业务示例问题或可点击建议。用户的第一个问题完全由用户自己发起；卡片可以提示“不知道从哪里开始，可以直接问我‘你能查什么？’”。

## 匹配结果与人工处理

姓名匹配有三种结果，分别对应不同的用户体验，不能混为一类：

| 匹配结果 | 系统动作 | 用户看到 |
|---|---|---|
| 数据库当前有效权限记录中唯一命中且记录完整 | 继续自动开通 | 流式开通进度，最终“可以开始使用”和当前公司、职能范围。 |
| 数据库当前有效权限记录中查不到该姓名 | 结束本次开通，不创建用户环境、不发布权限、不生成人工待办 | 明确结论：当前没有数据查询权限，需要先联系 BI 同事开通相应的银河权限。 |
| 匹配到多条记录，或记录、飞书必要信息、公司职能范围缺失、状态不可判定 | 暂停创建过程并转人工核对 | “正在人工核对”，并在完成后收到最终结论。 |

“查不到”是首期的常见正常结果，不是异常：内部用户中本来就只有一部分在银河拥有数据权限。这类用户必须直接得到可行动的结论，不进入等待，也不占用人工核对资源。

出现真正的异常时：

- 立即暂停该用户的创建过程，不继续问数，不发布不确定权限，也不部分宣告成功；
- 向用户说明正在人工核对，无需用户理解内部系统或自行选择权限；
- 在受控管理群通知管理员出现新待办，只展示定位问题所需的脱敏摘要和待办标识，不在群内提供处理按钮或管理命令；
- 自用户进入“正在人工核对”起，一个工作日内至少向用户提供一次明确进展或最终结论；这是由管理员人工守护的服务承诺。Lingxi 只负责向用户说明承诺并把新待办通知管理员，不建设任务认领、倒计时提醒、逾期升级或自动更新用户进展等机制，也不自动处理人工核对；
- 管理员确认唯一正确的数据库权限记录后，系统从暂停点继续；
- 无法确认或管理员决定终止创建时，用户收到明确的未开通结果、脱敏原因和可采取的下一步，不会永久停留在“正在核对”；
- 不允许模糊匹配、按相似姓名猜测，或用管理员权限替代用户权限完成开通。

环境创建、权限发布或 MCP 权限同步确认未获得明确成功结果时，不重新进入身份核对。系统暂停在相应步骤并通知运维管理员；运维先核对实际状态，再从尚未确认完成的步骤安全恢复。不得盲目重跑整个流程，避免重复创建环境、重复发布权限或重复通知用户。恢复并确认当前用户可以问数后才通知用户可以使用；最终无法恢复时通知用户尚未开通，并说明由谁继续处理。

## 管理员处理入口与安全确认

首期管理员通过经批准的 AI Agent 使用 Lingxi 管理能力，不建设完整网页管理后台，也不在飞书群聊中提供审批流程、管理命令或可执行的管理卡片。受控管理群只用于通知出现新待办、处理进展或最终结果；管理员在自己的 AI Agent 中完成查询、比较和操作准备。

管理 AI Agent 通过独立的 Lingxi 管理 MCP 使用受控能力。管理员是否有权查询或准备操作，以管理 MCP 当前认证的个人身份和角色为准，Lingxi 不重复维护或逐次校验另一份管理员名单。管理 MCP 身份必须与唯一的本人飞书身份绑定，确认卡接收人不能临时选择或替换。

管理 MCP 与业务用户问数使用的问数 MCP 职责分离，并提供三类可以分别授予的角色：

- **权限管理员**可以查询待处理异常、用户身份关联、当前公司和职能权限及准入状态，并准备选择唯一正确数据库记录并继续开通、终止开通、收回权限、停用、恢复或从当前运行环境删除用户；
- **运维管理员**可以查询用户环境、权限发布与 MCP 权限同步状态，并准备从尚未确认完成的步骤安全恢复或重试；
- **超级管理员**可以新增或移除权限管理员、运维管理员和其他超级管理员；同一个人可以被分别授予多个角色。若系统中已经没有超级管理员，普通管理入口暂停角色维护，由持有服务器 Root 权限的 Ops 运维工程师通过受控恢复流程，把一个身份已经核实并绑定飞书的现有用户恢复为超级管理员，并留下恢复对象、操作者、时间和结果的审计证据；
- 管理 MCP 只提供范围明确的管理能力，不提供任意数据库查询、任意字段修改、直接执行系统命令或绕过既有权限规则的通用工具；
- 查询不到目标用户时返回明确的“不存在”结果，不猜测相似姓名、不自动改查其他用户，也不产生写操作；
- 管理 MCP 按当前角色只展示和允许相应能力：权限管理员不能执行运维恢复，运维管理员不能替代业务身份与权限判断，只有超级管理员可以改变管理员角色；
- AI Agent 可以帮助管理员理解异常、比较候选记录和说明影响，但不能自行认定用户身份、扩大权限或直接完成高风险动作。

只读查询由管理 MCP 按当前认证身份和角色直接授权并返回；查询范围以处理当前管理职责所必需的信息为限。任何会改变用户身份关联、准入状态、数据权限、账号状态、用户环境、发布状态或管理员角色的动作，都必须先形成一项不可直接执行的待确认操作。

待确认操作发送到发起管理员本人的飞书私聊，卡片只承担最终确认，不承担搜索、比较、审批流或复杂信息填写：

- 卡片明确展示目标用户、当前状态、准备执行的动作、执行后的用户影响，以及「确认执行」「取消」两个动作；
- 卡片只发送到管理 MCP 身份所绑定的本人飞书账号，不能改发他人；卡片发送失败时本次操作不执行，不根据失败原因推断人员状态；
- 只有发起该操作且管理 MCP 当前角色仍有权执行的本人可以确认；管理群成员身份、卡片链接或 AI Agent 会话本身都不能代替个人授权；
- 管理员确认时重新读取目标对象、权限版本和管理 MCP 当前角色；卡片过期、角色已经被收回、目标状态已经变化、当前角色已无权执行、确认结果不明或审计无法写入时一律不执行，并要求管理员重新查询；
- 同一项待确认操作最多成功执行一次。重复点击、重复回调或多个 Agent 重复提交只能返回已有结果，不能重复改变用户状态；
- 执行完成、失败或取消后，原卡片更新为不可再次操作的最终状态；相关用户按产品合同收到可以使用、尚未开通或权限变化的最终通知。

每次管理查询和操作都记录管理员身份、当时角色、所用管理入口、目标对象、查询或动作类型、操作前状态、拟执行影响、卡片确认或取消、操作后状态、执行结果和时间。管理员角色的新增和移除同样记录变更前后角色。对敏感数据只记录完成审计所需的范围，不在审计中保存凭据、完整令牌或无关个人信息。写操作的审计记录无法可靠保存时，用户状态不得改变。

这套管理入口只处理异常和管理动作，不把正常自动开通改回人工审批。现有 BI AI Agent 中已经实现的用户查询、权限收回、账号停用与恢复、用户删除、关闭待处理和权限发布重试可作为实现参考；其旧申请审批流程、审批群命令和群内操作卡片不属于 Lingxi 的产品规则。

## 统一用户记录与权限变化

Lingxi 数据库必须建立统一的 `user` 用户表，以一条用户记录关联三类信息：

- **飞书信息**：姓名、`open_id`、`user_id`、`union_id`、部门、租户、专属云盘目录及后续投递所需状态；
- **权限信息**：匹配到的数据库权限记录、姓名、公司和职能范围，以及权限版本或核对时间；
- **Lingxi 信息**：内部用户标识、准入状态、用户环境状态、飞书多维表格发布状态、MCP 权限同步确认状态、启用或停用状态。

只保存完成身份关联、权限判断、服务和审计所必需的信息。飞书短期令牌、数据库认证材料、MCP 令牌明文及其他凭据不得进入用户表、日志、Issue、文档或用户交付物。

银河提供首期用户和权限的上游业务数据；数据经过受控流程进入 Lingxi 数据库后，数据库中的当前有效记录是 Lingxi 判断用户准入、记录公司和职能、控制启停以及向飞书多维表格发布什么内容的唯一权威。实际问数时可见和可查询的数据范围由外部 MCP 决定。

- 每次查询开始前重新读取数据库中的用户启停和服务状态，已停用用户不能继续使用 Lingxi；Lingxi 不根据数据库权限记录再次过滤 MCP 查询或结果。
- Lingxi 负责把数据库中的权限变化正确发布到飞书多维表格，并通过问数 MCP 验证当前用户应有的公司和职能权限已经同步且可以问数；未确认前不向用户宣告开通或权限变化已经生效。
- MCP 按当前用户已经同步生效的权限决定实际可见和可查询的数据范围。Lingxi 不在问数链路中增加另一套逐条数据过滤，但只允许已经完成 MCP 权限同步验证的用户进入问数。
- 用户离职或账号停用一经 Lingxi 感知，即禁止该用户发起新的问数；停用前已经开始的任务继续正常完成和交付，不额外停止或撤回。
- 调岗时只收回明确失效的范围，不影响仍有效的公司和职能；恢复账号时不自动恢复曾被收回的权限。
- 每次权限变化都通知用户本人，说明本次变化和当前仍可使用的范围；状态无法确认时暂停相关服务并转人工核对。

## 问数与多轮对话

本节全部规则只适用于飞书私聊入口，与 JumpServer 高级工作台无关。

- 收到用户在飞书私聊发送的任何消息后，Lingxi 立即给该条消息添加一个表情，只表示已经收到，不表示消息能够执行或任务已经开始。未开通用户的消息、任务忙碌时发送的消息以及 `/stop`、`/new` 等命令也遵循同一规则；表情添加失败不影响后续应有的引导、提示或任务处理。
- 同一用户在当前对话中连续提问时，Lingxi 保留该对话上下文，支持基于上一轮结果继续追问。
- 不同用户之间不共享对话、数据范围或交付物。
- 飞书私聊主窗口和每个由用户主动创建的飞书原生话题分别形成独立对话；不同话题可以并发执行，彼此不共享上下文。
- 同一话题同一时间只执行一个任务。任务仍在运行时，除 `/stop` 外的后续消息（包括 `/new`）只收到“当前任务仍在处理中”的提示；该消息不进入对话历史、不排队，也不会在当前任务结束后自动提交或自动生效。
- 用户在当前话题发送 `/stop` 时，Lingxi 停止该话题仍在运行的后续处理并明确回复停止阶段和已产生的结果；其他话题的任务不受影响。已经成功创建或发送的消息、文档、表格或图片不自动撤回。
- 用户在没有任务运行时输入 `/new`，立即清空当前所在对话的上下文；后续消息在同一位置以新上下文继续，其他话题不受影响。
- 会话是否延续按“上一条任务结束到下一条新任务开始”的间隔判断：间隔超过两小时时，新任务不恢复旧会话，直接以新会话服务用户。任务执行本身耗时多久都不触发新会话。
- 新会话不携带旧会话上下文，但继续使用该用户当前有效的身份、公司和职能范围，无需重新创建用户或重新准入。
- 系统明确告诉用户已经开启新会话，不让用户误以为旧上下文仍然有效。
- 用户问题不清楚、范围存在歧义或数据无法确认时，系统通过追问澄清，不自行猜测。
- 用户可以直接用自然语言询问“你能做什么”“我能查哪些指标”等能力问题，AI Agent 根据问数 MCP 当时实际提供的指标列表和说明回答。不开发 `/help` 命令，不由 Lingxi 维护固定示例问题或另一套能力清单。

## 问数结果的可信标准

- 数据结果必须让用户看清本次采用的公司、指标、时间范围，以及关键数字或趋势。MCP 返回数据最新时间时一并展示；没有返回时正常交付并省略该字段，不提示“数据时间未知”，不拒绝回答。Lingxi 不验证、不推算，也不为 MCP 补充数据新鲜度能力。
- 公司、指标或时间范围存在歧义时先追问；不能把相近指标、相近公司或猜测结果当作用户所问内容。
- 问数阶段只依据 MCP 实际提供的数据和状态回答。MCP 没有向当前用户提供某项数据时，Lingxi 不推断这是权限不足，不判断隐藏的数据或范围是否存在，也不生成“权限拒绝”。
- 只有 MCP 明确提供数据不存在、数据延迟或外部结果不完整的状态时，Lingxi 才向用户区分说明；否则只说明本次未取得可用结果，不把空结果或不确定结果标为完成。
- 用户经过一至三轮澄清后，应获得可用答案或明确失败说明；持续追问但无法收敛不能视为成功。
- 首期“问数质量八十五分”的可执行口径固定为 **20 个真实问数中至少 18 个通过，即最多允许 2 个未通过**。每个问数只按通过或未通过计一次，不设置不同权重；只有提出该问题的真实业务用户确认得到正确、可用的答案才算通过。清楚说明无法回答或未取得结果可以避免误导，不自动构成阻断问题，但该题仍计入最多 2 个未通过；关键数字错误、指标口径错误、跨用户泄露或三轮内既未收敛也未明确失败属于阻断问题，不能用其余题目的通过数抵消。
- 关键数字错误、指标口径错误、Lingxi 自身造成的跨用户会话或交付泄露，以及三轮内既未收敛也未明确失败，均属于不能上线或继续放量的阻断问题。Lingxi 必须在开通前确认 MCP 对当前用户的权限已经同步可用，但不逐条过滤 MCP 返回的数据。

## 结果与交付

### 交付样式

- 普通分析结果优先通过流式卡片展示。卡片标题使用公司、指标、时间范围等业务主题；正文底部状态区同时展示简短的当前动作和低频更新的已耗时间，例如“正在查询数据 · 18 秒”，回答区逐步展示用户可见内容；完成时显示“已完成”和总耗时。不展示预计剩余时间，也不把内部工具调用或过程日志展示给用户。
- 流式卡片创建、更新或关闭失败时，在同一私聊或同一飞书话题用普通文本补发完整结果，不把回复散到其他位置。
- 完成态必须包含可见结果、明确的澄清问题或可理解的失败说明；内部 Agent 名称、过程日志和技术状态不占据用户结果主体。

### 专属云盘目录与产物归属

Lingxi 在开通时为每个用户创建一个专属飞书云盘目录。该目录位于付费租户中 Lingxi 固定机器人的名下，由机器人创建和持有：

- 目录只授予该用户读写权限，不授予任何其他用户；
- 为该用户生成的飞书文档、电子表格和其他允许交付的文件都创建在该目录内；
- 交付物的访问授权必须实际完成，才能宣告交付完成。仅生成链接而未确认授权成功的产物不算交付。

用户的数据权限被收回、调岗或离职后，已经交付到其专属目录的文档仍然可以访问。这是明确接受的取舍：这些产物已经进入用户的工作流程，且飞书的离职流程会对该用户持有权限的全部文档执行统一交接，符合公司治理要求。Lingxi 不额外撤销或删除已交付产物。

### 交付规则

- 用户要求文档时，优先创建并只交付一个飞书文档链接；不把内部 Markdown 文件作为默认交付物。
- 用户要求表格时，优先创建并交付飞书电子表格。
- 用户要求图片时，应在飞书中直接可见、可打开或可下载，不暴露服务器路径。
- 交付只有在飞书确认创建、授权和发送成功后才能宣告完成；送达状态不确定时明确说明并要求核对，不自动重复创建或重发。
- 用户只能通过已经完成当前权限同步验证的 MCP 问数；实际返回的数据范围由 MCP 按该用户当前生效权限控制。Lingxi 只交付为该用户本人任务生成且允许交付的产物，不得发送其他用户文件、内部配置或认证材料。
- 首期只把交付物发送给当前用户，不由 Lingxi 直接发送给其他个人或群聊。用户可以在飞书中自行决定是否分享；若未来由 Lingxi 扩大接收人范围，必须重新核对接收人的数据权限。

## 高级工作台

高级工作台面向需要持续、深度分析或需要个人工作环境的用户，首期由 JumpServer 提供：

- 所有用户默认没有高级工作台。用户通过飞书之外的邮件或其他既定方式向管理员单独申请，审批和结果通知都在飞书开通链路之外完成。
- 用户在公司内部局域网通过 JumpServer 打开一个浏览器中的终端，进入本人专属环境，自行输入命令行进入 Claude CLI。
- 高级工作台面向能够使用命令行的用户。不具备命令行使用能力的用户不开通高级工作台，继续使用飞书私聊入口，不因此损失任何数据范围。
- 高级工作台不增加数据权限，沿用该用户在数据库中当前有效的公司和职能范围。
- 飞书私聊与高级工作台不共享会话和上下文。飞书的话题并发、`/stop`、`/new` 和两小时新会话规则都不适用于高级工作台。
- 高级工作台中产生的正式产物通过统一的交付 Skill 完成交付：该 Skill 复用已配置的飞书通道转换文档，写入该用户的同一专属云盘目录，并把链接发送给用户本人。用户取得产物的路径、归属和访问控制与飞书私聊完全一致。

## 数据保留与删除

- 当前会话上下文在用户输入 `/new` 重置当前所在对话，或按两小时规则开启新会话后，不再带入后续问答。
- Lingxi 后台保存的原始聊天记录、用户可见结果和技术审计记录，连同承载这些内容的任务问题、Agent 会话文件、人工核对详情和待确认操作参数，**最长保留九十天**，用于用户找回、问题排查、质量复核和审计；每份可识别内容自写入起不得晚于九十天删除或不可逆脱敏，不能用按月清理把实际期限延长到九十天以上。该周期不删除飞书聊天记录，飞书侧记录按飞书及公司规则保留。
- 用于故障恢复的数据库备份、WAL 归档和用户目录备份不受上述九十天期限或单用户删除操作影响，按公司的灾备与恢复规则管理；它们不作为 Lingxi 正常问数、用户找回、质量复核或日常审计的数据入口。恢复历史备份可能重新带回备份时已有的用户内容，这是明确接受的灾备取舍。
- 公司内部审计在获得相应授权后，可以在上述九十天内审计完整聊天记录、完整业务内容及其中的敏感内容；审计访问、用途和留存按公司审计制度管理并可追溯。
- 已交付到用户专属云盘目录的飞书文档和电子表格是用户取得的正式产物，不按九十天自动删除，由用户按照飞书和公司规则管理。
- 一次性交付区和内部中间文件在交付完成、失败或送达状态不明后按最短必要时间清理，不作为长期用户资产。
- 用户从当前运行环境删除时，先阻止新的问数和交付，再删除当前环境中的用户身份关联、权限副本、会话文件、任务内容、人工核对详情、待确认操作参数及其他仍可识别的运行数据；只有当前环境中的全部步骤完成后才显示删除成功。该操作不修改数据库备份、WAL 归档或用户目录备份，不能解释为对历史灾备副本的彻底删除。依法或依公司制度必须保留的在线审计内容应先做不可逆脱敏，不能在当前环境继续识别到该用户。

## 审核、审计与持续优化方向

Lingxi 的开通、问数、权限判断、任务执行和飞书交付构成面向用户的主链路。审核、审计与持续优化采用独立治理能力，不接管用户问数或反向决定用户权限；首期不承诺自动审核、实时风险拦截或审核工作台。

Lingxi 应稳定记录能够关联用户、话题、任务、权限版本、问数 MCP 查询、交付、停止或失败，以及管理 MCP 查询、待确认动作、飞书卡片确认和人工处理结论的审计事实，供后续独立治理项目使用。公司内部审计在获得相应授权后可以复核完整聊天和敏感业务内容。治理工作以发现问题、归类原因、形成改进项和复核效果为闭环，但不得扩大用户的数据权限或改变用户的正常问数体验。详见[审核审计与持续优化治理边界决策](决策记录/2026-07-26-审核审计与持续优化治理边界.md)。

## 系统与外部依赖边界

| 系统或依赖 | 在产品中的职责 | Lingxi 不得做什么 |
|---|---|---|
| 飞书 | 专用授权同步的关联组织员工资料、普通员工私聊事件的应用侧身份、业务消息与交付，以及管理员私聊确认卡片和受控管理群通知 | 把专用授权用户当成员工身份；假定不存在的信息或交付结果；未获得必要信息时继续自动创建用户；把群成员身份、卡片链接或消息来源直接当作管理员授权。 |
| 飞书云盘 | 承载每个用户的专属目录和正式交付产物 | 把产物创建在缺少访问控制的位置；在未确认授权成功时宣告交付完成。 |
| 银河 | 首期用户和权限的上游业务数据 | 未经受控流程直接改变 Lingxi 的准入、权限记录或发布内容；让用户自行扩大范围；对未查到或重名记录进行猜测。 |
| Lingxi 数据库 | Lingxi 用户准入、公司和职能记录、启停状态以及向飞书多维表格发布内容的唯一权威来源 | 让用户自行扩大 Lingxi 记录或发布内容；对未查到或重名记录进行猜测；用任何下游副本反向覆盖数据库记录。 |
| 飞书多维表格 | 将数据库已确认的用户权限发布给 MCP 的下游通道 | 把表格内容当作权限权威；由表格反向创建、修改或扩大数据库权限。 |

| 经批准的管理 AI Agent | 帮助经管理 MCP 当前角色授权的管理员查询、比较、解释异常并准备管理动作 | 把模型判断当作最终身份或权限结论；绕过飞书个人确认直接执行高风险动作。 |
| Lingxi 管理 MCP | 认证管理员个人身份并绑定唯一本人飞书身份，按权限管理员、运维管理员和超级管理员角色提供范围明确的查询与待确认动作，并返回可审计结果 | 提供任意数据库或系统访问；接受共享身份；向普通管理入口暴露 Root 恢复能力；在目标状态、当前角色、本人卡片确认或审计不明确时改变状态。 |
| Claude Code + 百炼 | 当前 AI 任务执行、模型和工具的有效能力；其 Agent SDK、MCP、Skills、审计采集和百炼兼容端点必须先通过一条最小真实链路，才允许开始依赖该链路的业务实现 | 在开工门禁未通过时继续实现并把兼容性问题推迟到上线前；承诺模型必然正确或可用；将模型输出伪装成未经验证的业务事实。 |
| JumpServer | 独立于飞书开通链路的高级工作台登录、服务器访问及用户环境隔离规则 | 把高级工作台作为更高权限入口；共享或冒用用户环境与身份；要求飞书会话与高级工作台共享上下文。 |
| 独立审计与治理能力（可由 `bi-agent-audit` 承载） | 接收 Lingxi 审计事实，支持风险复核、质量分析和持续优化 | 反向决定用户权限、接管 Lingxi 的开通或业务查询主链路，或改变正常用户问数体验。 |

数据库记录与飞书多维表格发布结果不一致，或 Lingxi 自身任一步骤没有给出明确成功结果时，都不能视为 Lingxi 侧发布已经完成。发布完成后仍须取得当前用户 MCP 权限同步成功且可以问数的明确结果，才能宣告开通成功；十五分钟内未确认则转人工处理。Lingxi 不从下游结果反写或扩大数据库权限，也不复制 MCP 的逐条数据过滤。自动重试和校验不得造成重复建档、重复授权、重复创建环境或重复交付。

## 不提供

- Codex 飞书对话、多 Agent 自助选择或普通用户自行修改模型配置。
- 群聊中的自由业务问数；受控管理群只发送管理待办和结果通知，不提供审批、管理命令或可执行操作。
- 完整网页管理后台，以及由 AI Agent、管理 MCP 或群聊消息直接执行未经管理员本人飞书卡片确认的高风险动作。
- 管理 MCP 中的任意数据库查询、任意字段修改、通用系统命令或共享管理员身份。
- 用户自行申请、选择或扩大数据库当前有效记录之外的公司和职能范围。
- 在公司和职能权限之外再由 Lingxi 增加一套数据源或下钻粒度限制；首期可查询范围由 MCP 实际提供能力决定。
- 绕过权限数据库或 MCP，直接暴露生产数据源、令牌、认证材料或内部路径。
- 用 JumpServer 高级工作台绕过飞书入口或数据库权限。
- 在公司内部局域网之外使用 JumpServer 高级工作台。
- 未经明确规则与门禁的自动扩权、生产变更、自动部署或高风险外部动作。
