# 决策：管理员职责集定稿与银河体系外权限动作的边界

> 状态：现行
> 决定日期：2026-08-24
> 来源：GitHub [Issue #139](https://github.com/Moshuiwang/lingxi/issues/139) 的职责清单讨论（What 层 v1/v2 与逐条复核评论），产品负责人 2026-08-24 逐条裁定；旧系统 bi-ai-agent 管理功能只读扫描（2026-08-24）为输入之一。
>
> 规则正文见[产品合同与外部边界](../产品合同与外部边界.md)「管理员处理入口与安全确认」；本文只说明为什么这样定。入口机制（AI Agent + 管理 MCP + 本人飞书卡片确认）不在本次调整范围，仍以[2026-07-26 决策记录](2026-07-26-管理员AI-Agent与飞书确认边界.md)为准。

## 决定要点

- **管理员职责集定稿（MVP 核心五项）**：查询用户状态（配套「用户自查」产品候选以压量）；停用/恢复（日报驱动、刻意不自动化）；花名册日报处置；运行告警响应；追溯与审计查询（同一查询面回答「发生了什么」与「谁对谁做过什么」）。
- **砍除**：独立的「终止开通」动作（停用即终止且防重触发）；十五分钟转运维单列项（迟到就绪自动恢复已覆盖）；提示词维护移出管理员清单（属产品调优）。
- **推迟/按需**：删除用户工具（首例走 Ops 受控执行卡）；管理员任免工具（角色模型保留，工具待 ≥2 名真实管理员）；开通链恢复工具与发布重试工具（真实形状由内测遥测定义）。
- **银河体系外权限动作按方向四分**（产品负责人 2026-08-24 采纳编排者建议组合）：
  1. 数据质量上报：入职责清单（纯上报，不违架构）；
  2. 单用户立即重同步：入职责清单（同步从每日变可按需，权威仍是银河）；
  3. 本地抑制（只减不加）：采纳，带三个强制条件——带原因+本人卡片确认、生效期间持续出现在审计与日报、银河修正后解除或定期复核；
  4. 本地开通/扩权：**不做**。
- **归属**：指标映射表维护、内测采集开关=产品负责人本人；专用授权凭据维护=Ops；成本/用量观察并入独立审计治理线（与审计本质同一条数据流）；安全事件复核维持治理线。

## 为什么

**先定「做什么」再定「怎么做」。**职责集从三个证据源反推：产品合同的权威分配、Trace #203 七天真实运行中实际发生的人工介入点、旧系统实际承担过的职责。逐项做必要性测试后，合同原有分配里有多项经不起推敲：「终止开通」没有独立语义；手工「收回单项权限」会被每日银河同步覆盖，除非制造第二权威——这正是旧系统（权限权威=审批流本身）与本系统（权限权威=上游同步）的结构差异，照抄旧系统职责会引入架构矛盾。

**管理员的真实痛点用不违架构的工具优先解决。**「看到不合理权限无从动手」的多数场景是「银河已改、每日同步未跟上」——单用户立即重同步直接消解它，不需要任何权威变更。剩余场景中确需人为干预的方向只有「减」：本地抑制在数据方向上失败安全（只会更少不会更多），代价是与银河的显性分歧，因此三个强制条件的目的都是防止抑制层退化为静默的影子权限系统。

**不做本地开通/扩权，是责任归属问题而非架构洁癖。**一旦 Lingxi 管理员能在银河之外放开数据访问，「谁批准他看这些数据」的答案就从一个有流程的上游系统变成某个管理员的个人判断，审计链在此断裂、合规责任整体转移。替代路径（证据齐备的转银河上报 + 改完立即重同步）覆盖了正当需求。

**极低频动作不预建产品代码。**删除用户与管理员任免均为合同义务，但频率不配自助工具；旧系统「不可逆删除与普通收回同等交互摩擦」的实测缺陷说明，为低频危险动作草率建工具比不建更危险。

## 不采用的选择及原因

- **本地开通/扩权（含「临时授权+自动过期」的最小形态）**：审计归属断裂与合规责任转移，编排者明确不推荐，产品负责人 2026-08-24 裁定不做；若未来出现真实场景，按复审条件重估。
- **把手工收回单项权限保留为管理员动作**：与每日上游同步互相覆盖，要么无效要么制造第二权威；由「本地抑制」以明确的分歧登记语义取代。
- **自动停用离职/换人账号**：花名册数据质量（2026-08-24 实测 37 个重复人员 ID）会让自动化误伤，维持日报+人工判断（#34 方案 C 既定选择）。

## 复审或替代条件

- 抑制项数量持续增长或长期不解除——说明上游修正通道不畅，应重估同步机制而非继续堆抑制；
- 单用户重同步使用频次高——说明每日同步节奏不满足业务，重估同步频率；
- 出现「必须在银河之外授予访问」的真实业务场景——重启四分法第 4 条评估，且必须连同审计归属与合规责任设计一起做；
- 真实管理员达到两人以上——启动任免工具与角色模型实现；
- 删除用户出现第二例真实请求——产品化删除流程。
