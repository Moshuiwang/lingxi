# 长期决策记录

这里记录已经由产品负责人接受、且在相关 Issue 关闭后仍会影响产品的选择。它不是收集意见的地方：尚未决定的选项、讨论过程和投票仍在 GitHub Issue。

## 与产品合同的分工

**规则正文只写在[产品合同与外部边界](../产品合同与外部边界.md)，决策记录不复制它。**

| 问题 | 去哪里找 |
| --- | --- |
| 产品现在的规则是什么、用户会看到什么 | 产品合同 |
| 为什么定成这样、当时否决了哪些选择、什么条件下要重新评估 | 决策记录 |

决策记录中的「决定要点」只用一句话概括每项决定，帮助读者不打开合同也能知道这份记录管的是什么；具体行为、边界条件和文案要求一律以合同为准。两处不一致时，以产品合同为准，并同步修正决策记录。

这样分工是因为：同一段规则维护在两个文件里，迟早会改一处漏一处，形成两个同等有效但内容不同的版本。

## 何时建立记录

仅在以下情况建立一份记录：

- 选择改变或明确了用户体验、业务规则、权限、安全或外部依赖的长期口径；并且
- 未来实施、运营或新成员需要知道“为什么按这个规则做”。

纯实现取舍、一次性排障和已被否决的方案不建记录，保留在 Issue / PR 即可。

## 文件与状态

文件名使用 `YYYY-MM-DD-主题.md`。每份记录只使用下列状态之一：

- `现行`：当前仍适用。
- `已替代`：在正文首段链接替代它的记录，并删除原规则正文，只保留“它曾经解决什么问题”“为什么被替代”“仍然有效的结论”。
- `已撤销`：说明撤销原因与生效范围。

一项决策若同时改变产品承诺或已确认能力，必须同步更新[产品合同与外部边界](../产品合同与外部边界.md)或[当前能力](../当前能力.md)；决策记录不能替代这两份面向全体读者的总览。
