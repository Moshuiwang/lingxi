# 决策：问数可信、交付与数据保留边界

> 状态：现行
> 决定日期：2026-07-26（同日补充专属云盘目录与九十天保留期；2026-07-27 明确九十天是正常运行内容的最长保留上限，灾备副本不受该期限或单用户删除影响；2026-08-13 补充飞书问数结果投递正文的短期保留、平台接收与用户已读的区分，并暂停已被外部事实否定的机器人专属目录与自动离职交接口径）
> 来源：[GitHub Issue #7](https://github.com/Moshuiwang/lingxi/issues/7)；[GitHub Issue #14](https://github.com/Moshuiwang/lingxi/issues/14)；[GitHub Issue #97](https://github.com/Moshuiwang/lingxi/issues/97)；[GitHub Issue #140](https://github.com/Moshuiwang/lingxi/issues/140)；[GitHub Issue #141](https://github.com/Moshuiwang/lingxi/issues/141)；[GitHub Issue #151](https://github.com/Moshuiwang/lingxi/issues/151)；产品负责人于 2026-07-27 确认正常运行中的用户可识别内容最长不超过九十天，数据库备份、WAL 归档和用户目录备份不受九十天期限或单用户删除影响，并于 2026-08-13 授权 #97 探针、确认飞书问数正文的短期保留与诚实终态
>
> 规则正文见[产品合同与外部边界](../产品合同与外部边界.md)的「问数结果的可信标准」「结果与交付」「数据保留与删除」。本文只说明为什么这样定。

## 要解决的长期问题

Lingxi 需要明确怎样才算给出了可信结果、交付物存放在哪里、谁能打开它，以及对话、审计和用户产物分别保留多久。否则用户可能收到没有数据的“完成”、无法核对的数字、重复产物，或者一份含权限数据的文档因为默认可见性设置而被组织内任何人打开。

## 决定要点

- **可信结果必须可核对**：说明公司、指标、时间范围和关键数字；有歧义先追问；空结果和不确定结果不算完成；一至三轮内必须收敛为可用答案或明确失败。
- **数据最新时间有则展示、无则省略**：MCP 返回时展示，没有返回时正常交付，不提示“数据时间未知”，也不拒绝回答；Lingxi 不验证、不推算或补充 MCP 的数据新鲜度能力。
- **问数阶段不判断权限拒绝**：MCP 没有向当前用户提供的数据对 Lingxi 不可见，Lingxi 不推断缺少什么权限，也不确认隐藏的数据或范围是否存在。
- **机器人专属目录方案当前失败关闭**：规范已否定自动离职交接，并且文件夹跨租户授权、链接范围和“仅本人”仍未被 #97 真实验证；最终承载方案、保留和清理责任由 #140 决定。
- **授权成功是交付完成的前置条件**，不是只要生成了链接就算交付。
- **产物只发给当前用户**，送达不确定时不自动重发。
- **权限收回、停用或离职后的正式产物访问、保留、清理和交接等待 #140 最终决定**；不得继续声称飞书会自动交接机器人所有的对象。
- **原始聊天、技术审计记录及其载体最长保留九十天；飞书问数安全结果正文采用更短的投递期**：相应交付形态已经真实验证，且最终结果获得平台接收确认后，立即从当前运行环境清理；待投递、失败、不明或交付形态尚未证明清理后仍可访问的正文最长保留二十四小时，低敏投递事实最长保留九十天。
- **平台接收不等于用户已读**；未确认送达的任务不得写成用户取得结果，正文到期后释放话题、保留诚实终态，只在用户下一次主动发来飞书消息时提示重新提问，不主动推送，也不自动重跑或重发原答案。
- **数据库备份、WAL 归档和用户目录备份不受九十天期限或单用户删除操作影响**，按公司的灾备与恢复规则管理，且不作为正常问数、找回、质量复核或日常审计入口；恢复历史备份可能重新带回备份时已有的用户内容。
- **正式产物的保留、清理、用户处置和离职交接不得继续沿用旧假设**；由 #140 在真实证据后形成新决定。

## 为什么这样定

**原目录方案为什么被暂停。** 当时选择机器人专属目录，是希望把访问控制从“每份产物都要做对”收敛成“一次目录授权”。#97 的 L1 事实表明，这条路径不能自证文件夹链接范围与“仅本人”，而且机器人所有的目录不会进入关联租户员工的离职交接；继续执行会形成无明确责任人和清理期的长期数据面。#97 只验证外部能力，#140 决定是采用可验证的目录主体、改为逐份授权，还是缩小范围。

**旧的自动离职交接理由已经失效。** 飞书按所有权而非协作者权限处理离职交接；机器人持有、关联租户员工仅为协作者的对象不会自动交接，所有权也不能转给关联组织员工。最终方案必须显式规定停用、离职、删除和权限变化后的访问、保留、清理或交接，不能再把责任交给不存在的平台流程。

**九十天是最长上限，不是最低保留期。** 原本设想聊天三十天、审计九十天，但这会产生一个无法成立的组合：审计承诺可以复核“完整聊天记录”，而聊天正文在第三十天就已删除，第三十一天到第九十天之间没有可复核的内容。需要完整复核的内容可以保留到九十天，但任何可识别内容都不能因为按月分区或清理延迟而超过九十天；更短清理不影响用户找回和审计承诺时可以采用。

**飞书问数结果正文采用短期例外。** 只有相应卡片或文本形态经过真实验证，确认正文清理后仍能由目标用户从同一飞书会话访问，飞书会话才可作为已送达答案的找回入口；这时不需要 Lingxi 再保存一份最长九十天的敏感结果副本；未确认送达的正文只为重启恢复和确定性降级短期存在。二十四小时覆盖受控恢复窗口，超过该窗口继续保留只会增加敏感内容暴露面，而且原答案已经可能失去时效。因此到期后删除正文、诚实记为用户未取得结果并要求重新提问；审计继续保留关联任务、时间、通道、外部标识和失败分类，但不承诺从 Lingxi 后台恢复已清理的结果正文。

**平台接受与人类阅读必须分开。** 飞书 API 的确定成功能证明 Lingxi 已把结果提供到指定会话，不能证明用户实际看过。首期用平台接收作为送达和正文清理的可执行边界；没有真实阅读回执时，产品和审计都不使用“用户已读”。

**灾备副本是明确例外。** 数据库备份、WAL 归档和用户目录备份服务于故障恢复，不参与正常产品体验，也不作为九十天内的内容查询或审计入口；其保存时间由公司的灾备规则决定，不跟随运行库和在线文件的九十天清理，也不随单用户删除操作修改。恢复旧备份可能重新带回历史用户内容，这是为了保留灾备能力而明确接受的取舍。因此产品只承诺“从当前运行环境删除”，不承诺从全部历史灾备副本彻底删除。

**送达不确定时不自动重发。** 自动重发可能产生多个内容不一致的产物，用户无法判断哪一份是最终版本，这比一次明确的“请核对”更糟。

**MCP 不可见不等于 Lingxi 可以判断权限不足。** MCP 已经按用户权限限定可见数据，Claude 或 Codex 只能看到 MCP 实际返回的内容。没有返回的数据可能不存在、不可见或暂时不可用；除非 MCP 明确给出状态，Lingxi 不自行归因，也不制造一条实际上无法可靠判断的“权限拒绝”体验。

**数据最新时间不是 Lingxi 的交付门槛。** MCP 能提供时，展示它可以帮助用户理解数据时效；MCP 不提供时，Lingxi 没有可靠来源自行计算。用“数据时间未知”制造额外提示或拒绝交付都不能增加真实信息，因此首期直接省略。

## 对用户和边界的影响

- 用户能判断结果查询了什么、为什么成功或失败；MCP 提供数据最新时间时还能判断数据是否新鲜。用户不会把空答案或猜测当成可信结论。
- 用户不会收到模型猜测的“你没有某项权限”，也不会因为拒绝文案获知自己不可见的数据或组织范围。
- 正式产物路径在 #140 最终决定前失败关闭；用户不会收到归属、权限、清理或离职责任无法验证的机器人目录链接。
- 用户默认只收到自己的产物，不会因为系统自动转发而扩大数据范围。
- 用户看到的处理与交付样式在私聊和话题中保持一致，失败兜底也不会跳出当前话题。
- 正常运行中的输入聊天与审计载体最长九十天；飞书问数结果正文只保留到已验证交付形态的平台接收确认或二十四小时上限，低敏投递事实最长九十天。用户只从经真实验证仍可访问的飞书会话形态找回已送达答案，Lingxi 不提供已清理正文的后台恢复；正式产物的归属与生命周期等待 #140 决定，灾备副本按公司的灾备规则管理。

## 不采用的选择及原因

- **只要模型返回文字就标为完成**：文字可能没有数据、口径错误或无法核对。
- **根据 MCP 没有返回数据来推断权限不足**：Lingxi 看不到被 MCP 隐藏的范围，无法可靠区分无权、无数据或其他不可见原因。
- **未经逐份权威回读就采用单产物授权**：任何一次遗漏都是数据泄露；若 #140 选择该方案，必须把每份创建、权限、链接范围、发送与清理读回纳入完成条件。
- **依赖飞书自动交接机器人名下产物**：离职交接按所有权执行且跨租户所有权不能转给员工，这条平台流程不存在。
- **对已经验证可从飞书会话找回的交付形态，仍在 Lingxi 后台保留九十天结果正文**：重复保存会无谓扩大敏感结果暴露面；未验证形态不得套用这条理由提前清理。
- **未确认送达的结果正文保留九十天**：二十四小时后原答案可能已经失去时效；继续保存不能证明用户取得结果，也不应成为自动重发依据。
- **送达不确定时自动重发**：可能产生多个内容不一致的产物，让用户无法判断最终版本。
- **默认向同事或群聊发送结果**：接收人的数据权限尚未核对，可能扩大数据范围。
- **让机器人名下产物无限期保留且不设 Owner**：形成无 UI 入口、无用户处置能力、离职不交接的长期数据面。
- **把审计系统当作用户权限或问数主链路**：审计需要独立复核事实，但不能反向扩大权限或接管业务决策。

## 复审或替代条件

- 公司安全、法务或合规制度规定不同的保留周期；
- 公司审计或合规制度规定不同的审计访问、用途或留存规则；
- 飞书云盘的目录权限模型或离职交接流程发生变化；
- 产品提供用户可见的历史会话、恢复或删除入口；
- 飞书不再能作为已送达问数结果的用户找回入口，或二十四小时无法覆盖真实可恢复投递窗口；
- Lingxi 支持向多人或群聊受控交付；
- 数据来源、指标口径或结果核验机制发生变化。
