# 决策：问数可信、交付与数据保留边界

> 状态：现行
> 决定日期：2026-07-26
> 来源：[GitHub Issue #7](https://github.com/Moshuiwang/lingxi/issues/7)；产品负责人于 2026-07-26 确认首期可信、交付与保留口径

## 要解决的长期问题

Lingxi 需要明确怎样才算给出了可信结果、交付物可以发给谁，以及对话、审计和用户产物分别保留多久。否则用户可能收到没有数据的“完成”、无法核对的数字、重复产物，或在不知情的情况下扩大数据接收范围。

## 已接受的规则

- 数据结果必须说明公司、指标、时间范围、数据最新时间和关键数字或趋势；存在歧义时先追问，不用猜测补全。
- 数据不存在、权限不足、数据延迟和服务结果不完整必须明确区分；空结果或没有用户可见正文不能标为完成。
- 一至三轮内应给出可用答案、明确失败说明或正确权限拒绝。关键数字错误、指标口径错误、越权泄露或三轮不收敛均为阻断问题。
- 首期交付物只发送给当前用户：文档只交付一个飞书文档链接，表格优先使用飞书电子表格，图片必须在飞书中可见、可打开或可下载，不暴露服务器路径。
- 收到可执行问题后先给原消息添加表情，随后使用“业务主题标题、短状态区、逐步出现的回答区和明确完成耗时”的流式卡片；卡片失败时在同一私聊或同一话题用普通文本补发完整结果。
- 送达状态不确定时不自动重复创建或重发；用户可以在飞书中自行分享，Lingxi 不直接扩大到其他个人或群聊。未来若由 Lingxi 扩大接收人范围，必须重新核对接收人权限。
- 在数据库已经确定的公司和职能范围内，可查询的数据源、数据粒度和下钻程度完全由 MCP 实际能力决定；Lingxi 不额外增加独立的数据粒度或明细限制。
- `/new` 重置当前所在私聊或话题的上下文，其他话题不受影响；重置后的对话和超过两小时自动开启的新会话都不继承旧上下文。Lingxi 后台保存的原始聊天和用户可见结果默认保留三十天，到期删除或脱敏；该周期不删除飞书聊天记录，飞书侧记录按飞书及公司规则保留。
- 最小技术审计记录默认保留九十天。公司内部审计在获得相应授权后，可以审计完整聊天记录、完整业务内容及其中的敏感内容；审计访问、用途和留存按公司审计制度管理并可追溯。
- 已交付的飞书文档和电子表格由用户按照飞书和公司规则管理，不按三十天自动删除；一次性中间文件按最短必要时间清理。
- 用户被彻底删除后，删除仍可识别的运行数据；必须保留的审计内容按公司制度脱敏保留。

## 对用户和边界的影响

- 用户能判断结果查询了什么、数据是否新鲜、为什么成功或失败，不会把空答案或猜测当成可信结论。
- 用户默认只收到自己的产物，不会因为系统自动转发而扩大数据范围。
- 用户看到的处理与交付样式在私聊和话题中保持一致，失败兜底也不会跳出当前话题。
- 会话内容、审计证据和正式产物采用不同保留规则；公司内部审计对完整业务事实的访问与留存按公司审计制度管理。

## 不采用的选择及原因

- **只要模型返回文字就标为完成**：文字可能没有数据、口径错误或无法核对。
- **送达不确定时自动重发**：可能产生多个内容不一致的产物，让用户无法判断最终版本。
- **默认向同事或群聊发送结果**：接收人的数据权限尚未核对，可能扩大数据范围。
- **三十天后自动删除已交付飞书产物**：正式产物已经进入用户工作流程，自动删除会造成不可预期的数据丢失。
- **把审计系统当作用户权限或问数主链路**：审计需要独立复核事实，但不能反向扩大权限或接管业务决策。

## 复审或替代条件

- 公司安全、法务或合规制度规定不同的保留周期；
- 产品提供用户可见的历史会话、恢复或删除入口；
- Lingxi 支持向多人或群聊受控交付；
- 数据来源、指标口径或结果核验机制发生变化。
- 公司审计或合规制度规定不同的审计访问、用途或留存规则。
