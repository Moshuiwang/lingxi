# 决策：在测试库保留飞书关联组织完整资料快照

> 补注（2026-08-23）：本记录提及的实现资产 `scripts/sync_feishu_org_snapshot.py` 与 `migrations/testing/005` 已随 #146 清退批移除（快照职责由 #250 的常驻 `OrgSnapshotSyncDuty` 承接）；本记录的决策本身不受影响。

> 状态：现行
> 决定日期：2026-08-05
> 来源：产品负责人在当前任务中明确要求写入测试库；实现见 `migrations/testing/005_create_feishu_org_snapshot.sql`（2026-08-05 随 #16 正式化移入 testing/） 与 `scripts/sync_feishu_org_snapshot.py`。
>
> 本决定只适用于 `biai-stage` / `lingxi-test` 测试库，不改变正式员工开通、生产数据库或用户可见产品承诺。

## 要解决的问题

此前关联组织遍历只在内存中读取完整员工资料，测试结果只保留计数、字段名和脱敏前缀，无法直接回读某个成员的三类飞书 ID。产品负责人需要在测试库中保留本次完整快照，供后续字段核对和开发验证使用。

## 决定要点

- 为每次同步建立独立的租户、部门、成员和同步批次快照表，不写入 `app_user`。
- 保存飞书关联组织接口返回的全部业务字段和原始 JSON 响应，包括 `open_id`、`user_id`、`union_id`、组织关系、姓名、头像、状态及接口实际返回的可选资料。
- 永不保存 App Secret、OAuth access token、refresh token、授权码或数据库连接凭据；续期凭据仍由原有加密凭据表按轮换规则管理。
- 一轮遍历必须先完成两条身份路径的集合与三类 ID 完整性校验，再以单个数据库事务提交；失败不产生可用的半轮快照。
- 测试快照默认保存 90 天，由 `expires_at` 作为回收入口；不将测试快照当作正式权限或员工开通数据源。

## 本次验证结果

2026-08-05 的首次完整快照已写入测试库：8 个关联租户、279 个部门、712 名成员、712 条成员详情；三类 ID 均为 712/712。人数与 2026-07-29 的历史快照（710 人）不同，因此历史数字只作为历史证据，当前测试库快照以同步批次回读为准。

## 为什么这样定

完整原始资料需要可回读，但把它混入 `app_user` 会把测试目录快照误当成正式业务用户，且会影响正式权限、删除和生命周期规则。独立批次表可以把测试资料与正式用户状态隔离，并用批次级级联删除恢复到写入前状态。

## 恢复与边界

回滚时按具体 `sync_run_id` 删除该批次，子表通过外键级联删除；不删除或修改 `app_user`、权限记录及续期凭据。若要延长保留期、写入生产库或让正式开通读取该快照，必须重新做产品和安全决策。
