# 决策：按中文姓名自动准入并采用银河权限范围

> 状态：已替代
> 决定日期：2026-07-25
> 替代日期：2026-07-26
> 来源：[GitHub Issue #7](https://github.com/Moshuiwang/lingxi/issues/7)

**本决策已被 [自动准入以数据库权限为准并通过多维表格发布](2026-07-26-自动准入与数据库权限发布边界.md) 完整替代，不再作为实现、验收或用户承诺依据。**

原规则正文已删除，避免与现行规则并存造成误读。现行规则见[产品合同与外部边界](../产品合同与外部边界.md)。

## 它曾经解决什么问题

Lingxi 首次面对一名飞书用户时，需要确认该用户是谁、可以访问哪些公司和职能，以及正常用户是否仍要填写申请并等待人工审批。当时飞书与银河分别保存不同的用户信息，需要在不猜测身份、不扩大既有权限的前提下把两边关联成一个可持续使用的用户。

## 为什么被替代

原决策把**银河导出的权限名单直接作为运行时授权依据**。2026-07-26 确认这条链路不成立：任何上游业务数据都必须先经受控流程进入 Lingxi 生产数据库，运行时只认数据库中的当前有效记录；飞书多维表格是数据库向 MCP 发布权限的下游通道，不是权限来源。

替代决策同时补齐了原决策没有覆盖的部分：开通过程中必需的用户授权步骤、开通进度的可见性，以及“数据库中查不到该用户”应作为正常终态而非人工核对异常。

## 仍然有效的结论

以下判断在替代决策中被保留，仍然成立：

- 不做模糊姓名匹配，也不自动在同名记录中选择一条；
- 正常路径不要求用户填写权限申请或等待人工审批；
- 人工处理只能确认正确记录或终止创建，不得借此扩大权限；
- 身份确认后，环境创建或权限发布结果不明确时转由运维核对，不重新判断身份，也不盲目重跑整个流程；
- 不把工作邮箱作为飞书实时反查条件——已验证中心应用无法通过该方式核对关联组织成员。
