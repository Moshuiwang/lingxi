# 决策：问答留存语料不到期、明文落库

状态：现行。决定日期：2026-09-13。来源：[Issue #664](https://github.com/Moshuiwang/lingxi/issues/664)「已生效裁定」段；[Issue #768](https://github.com/Moshuiwang/lingxi/issues/768) §二 裁定 8；Trace [#770](https://github.com/Moshuiwang/lingxi/issues/770) 已裁定事项 L-7（[合同正文](../traces/770-2.5.0三批次/合同.md)）。规则正文见[产品合同与外部边界](../产品合同与外部边界.md)「数据保留与删除」的第三条例外，以及「交付样式」「数据保留与删除」两处对「未经安全处理的模型片段不得写入持久介质」的唯一例外限定；本文只说明为什么这样定。实现进度只看 #664。

## 要解决的问题

服务端看不到自己答了什么。2026-09-07 金丝雀首聊后逐层实测：数据库只存会话指针与用户问题，回答正文没有对应列；Agent 会话工作区随任务结束即散；飞书卡片正文不可经平台接口回读。回答只存在于用户自己的飞书客户端里，团队无法回答「这一次答得对不对、同类问题历史上答成什么样、改动之后答得更好还是更差」——Agent 自演化没有输入。

## 决定要点

- **全留**：每一次真实问数留下用户问题原文、回答，以及产生它的工具调用详情（入参与结果摘要）。
- **不到期**：不设保留上限；「不到期」不等于「不清理」，容量滚动与失效清理的判据由 #664 的实现定义并写回合同。
- **明文落库**：不做静态加密，保住按关键词检索的能力。
- **两者都存**：回答同时留用户实收的安全正文与模型原文——前者是用户看到的事实，后者是评价模型本身与安全处理的依据；模型原文副本不得回流到投递、展示或日志。
- **独立正式通道**：另建正式留存表，不复用内测采集通道，也不并入执行层审计。
- **窄读取角色加每次读取审计**：只有为此设立的窄读取角色可读，每一次读取与导出各留一行不含正文的审计；凭据形状的内容照常过滤、不留存。

## 为什么这样定

产品负责人明确以 Agent 自演化为目的推进。语料的价值在于原文与完整上下文：删掉工具调用就看不出「取了什么数」，删掉模型原文就看不出「安全处理改了什么」，到期删除则让跨版本比较失去基线。代价是生产会长期保留真实用户的问题原文与回答正文——这是数据保留范围的实质扩大，产品负责人接受这一隐私面的扩大，但数据安全底线一条不减：凭据形状过滤、读取先鉴权、每次读取与导出留审计、正文不进日志 / Issue / PR / 聊天、导出物落地即受控。

## 不采用的选择及代价

- **复用内测采集通道**：它的语义是内测期的临时观察，自带九十天到期与「生产恒空」的结构性关卡，与长期语料的目的相反；改造它等于让同一条通道同时承担两种相反的保留承诺。
- **沿用九十天**：自演化要跨版本、跨月份比较同类问题的回答，九十天内只看得到最近一个版本的表现。
- **静态加密**：按现有令牌加密的先例落库后，按关键词检索得另建一套解密检索路径，成本与暴露面都不比「明文加窄读取角色加读取审计」更优。
- **只存安全正文**：安全正文是投影后的结果，看不出安全处理删掉了什么、模型原本答了什么，评价模型与评价安全处理会混在一起。

## 与已有选择的关系

- [问数可信、交付与数据保留边界](2026-07-26-问数可信交付与数据保留边界.md)中「原始聊天与技术审计记录最长保留九十天」与「未经安全处理的模型片段不得写入任何持久介质」两条被本记录**部分取代**：只对留存语料通道让位，其余内容的九十天规则、会话保留与清除规则、二十四小时投递上限不变。
- [审核审计与持续优化治理边界](2026-07-26-审核审计与持续优化治理边界.md)不变：留存语料通道的读取受同样的审计授权、用途与追溯要求约束。
- 本记录不裁、由实现工作项提请产品负责人裁定的：窄读取角色的具体判据与授权载体（D-3）、独立留存表的表结构与模块归属、生产三道结构性关卡的处置（D-7；若改写硬关，必须补一条等价门禁）、用户从当前运行环境删除时该用户语料的处置。

## 复审条件

- 公司隐私、合规或审计制度对真实问答原文的保留提出不同要求；
- 语料用途从 Agent 自演化改变或扩大（例如用于对外训练、向用户提供历史查看）；
- 留存容量超出预算，或容量滚动判据在真实运行中证明不可执行。
