# 决策：用户之间的操作系统级隔离本轮不做，设为 JumpServer 高级工作台的硬前置

> 状态：现行（2026-08-28 批注：JumpServer 高级工作台已被裁定取消，见[取消 JumpServer 高级工作台决策](2026-08-28-取消JumpServer高级工作台.md)——本文「设为 JumpServer 硬前置」失去对象、复审条件第 1 条不再可能触发；其余约束继续有效：用户间不被越权读取当前唯一依赖执行层工具白名单，给 Agent 增加任何读文件或执行命令能力的工具前必须回到本决策）
> 决定日期：2026-08-19
> 来源：产品负责人在本机 Claude Code 会话中裁定，随 [Issue #203](https://github.com/Moshuiwang/lingxi/issues/203) 的执行批次登记
>
> 相关设计正文见[架构设计 5.3 用户隔离](../技术设计/架构设计.md)。令牌落盘那一侧的裁定（worker → 问数 MCP 的逐用户令牌写进用户环境配置）留痕见 [Issue #203](https://github.com/Moshuiwang/lingxi/issues/203)，其长期正文随首次开通链一并合入。本文只说明为什么这样定。

## 要解决的长期问题

[架构设计 5.3](../技术设计/架构设计.md) 要求「每个用户一个 Linux 账号 + 一个家目录，worker 以该用户身份启动 Agent SDK 子进程，文件权限即隔离边界」。**这道边界至今没有实现**：`internal_user_id → uid` 的映射、宿主机账号分配与 worker 的 uid 切换都不存在，用户环境目录的属主是运行进程本身。

它在 2026-08-17 之后变得更要紧：产品负责人当日裁定 worker → 问数 MCP 的逐用户令牌**沿用旧系统老路，把 Bearer 明文写进用户环境的 `.mcp.json`**。于是每个用户目录里都有一份只属于他自己的凭据，而目录之间没有操作系统级的隔离墙。

## 决定要点

- **本轮（首次开通链 Epic D）不实现 uid 分配与 worker 降权**，如实登记为已知边界，不当作已具备的能力。
- **该项设为 JumpServer 高级工作台的硬前置**：那条入口开工的第一件事就是它，不得在隔离未落地时上线。
- 在隔离落地之前，**用户之间不被 Agent 越权读取所依赖的是「执行层工具白名单只含一个只读问数工具」这一层**，不是文件权限。因此**给 Agent 增加任何具备读文件或执行命令能力的工具，必须先回到本决策**。
- 用户环境落盘那一侧既有的补偿纪律（根目录 `0750`、家目录 `0700`、配置 `0440`、不跟随符号链接、原子替换、日志脱敏）保持不变，不因本决策放松。

## 为什么这样定

- **它保护的入口本轮不存在**。能让「读到别人的 `.mcp.json`」变成可达路径的是 JumpServer——用户在同一台机器上拿到 shell；而 JumpServer 明确不在本轮范围。Agent 侧则受工具白名单限制，没有任何读文件或执行命令的能力。
- **代价与本轮收益不成比例**。实现它需要给 worker 容器新增 `CAP_SETUID`/`CAP_SETGID` 与 `--userns=host`、由宿主机统一分配账号与 uid、并定义账号的建立、删除与离职语义。这是新增的宿主机权限面与一套长期运维对象，属于[长期执行计划](https://github.com/Moshuiwang/lingxi/issues/203)明写的「需要重新批准范围」的变更。
- **不靠记性靠登记**：本仓库已多次出现「只活在注释或口头约定里的约束等于没有约束」。因此本决策把它写成长期记录并挂到 JumpServer 入口的前置上，而不是记在某一条 Issue 评论里。

## 对用户和边界的影响

- 对当前用户无可见影响：本轮不上 JumpServer，用户只经飞书私聊使用。
- 对安全边界：**用户之间在操作系统层没有隔离**，这一事实必须如实出现在能力与风险登记中，不得表述为「已按架构设计隔离」。
- 对运维：不新增宿主机账号、不新增容器 capability，部署面与本轮之前一致。

## 不采用的选择及原因

- **本轮就实现 uid 与降权**：见上「代价与本轮收益不成比例」。
- **改为在应用层做目录隔离**（例如让子进程只挂载自己那一份配置）：能缩小暴露面，但它不是操作系统级隔离，会让「已经隔离了」这句话变得似是而非；本决策宁可把缺口写清楚，也不要一个看起来像隔离的替代品。

## 复审或替代条件

出现以下任一情况必须回到本决策重新判断，不得沿用：

1. JumpServer 高级工作台进入实施范围；
2. 执行层工具白名单新增任何具备读文件、写文件或执行命令能力的工具；
3. 用户环境目录中出现除 `.mcp.json` 以外的凭据或敏感产物；
4. 同一宿主机上出现 Lingxi 之外、可登录到用户环境目录的第三方进程。

> **2026-08-19 补记**：worker 按用户读取 `.mcp.json` 的读侧（`adapters/user_mcp_config.py`，Epic D 闸⑥）落地后，外部独立审查对读侧点出同一族问题（lstat→open 之间的 TOCTOU、未拒绝硬链接、未验证权限位/属主/扩展 ACL）。判定与本决策一致：明确接受、不在本轮处理，复审条件逐字沿用上面这四条。登记在该模块「已知边界」一节，与写侧（`adapters/user_environment.py` 的「已知边界」一节，同样接受 ACL/硬链接同族问题）互相链接到本文件。
