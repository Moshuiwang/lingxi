# 决策：用户记忆为显式登记式，不存数据值

> 状态：现行
> 决定日期：2026-08-28
> 来源：产品负责人 2026-08-28 确认窗口批准 [Trace #373 开工合同](https://github.com/Moshuiwang/lingxi/issues/373)先行裁定 D1（裁定留痕见 #373 首条评论）；实现与受控验收见 [Issue #357](https://github.com/Moshuiwang/lingxi/issues/357)（PR #398 等，L4a 证据在 #373 S-H3-4 与 H4 冒烟评论）。
>
> 本文只说明为什么这样定、放弃了什么、什么条件下要重新评估；具体行为与文案以产品合同及 #357 回写为准。

## 要解决的长期问题

用户在问数对话中反复重复同样的术语解释（「大黄=尼日利亚 GMV」）、口径偏好和惯例模板。系统要在多大范围内替用户记住这些，同时不引入数据泄漏面、不让「系统悄悄学了什么」变成不可审计的黑箱。

## 决定要点

- 记忆**只来自用户显式登记**（`/memory remember`），系统不自动学习、不从对话中隐式提取；
- 范围限三类：**术语映射、口径偏好、惯例模板**；
- **不存任何数据值**（查询结果、数字、表格内容一律不进记忆）；
- 按用户隔离存储于 Lingxi 库；用户可查（`/memory list`）可清（`/memory forget`）；
- 停用/删除/权限变化触发清除，复用既有交付内容清除钩子；
- 注入点为 worker 每任务系统提示词侧（每任务直查 DB + fail-open，取数失败不阻塞问数——#373 执行中自裁 D-H3-a）。

## 为什么这样定

- **可审计性优先**：显式登记使「系统知道什么」对用户完全透明，`/memory list` 即全量；自动学习则把记忆内容变成模型行为的副产物，无法向用户或审计者交代来源。
- **不存数据值**把记忆面与数据权限面彻底分开：记忆里只有用户自己的表达习惯，没有任何需要按银河权限裁剪的内容，权限变化时的清除语义因此简单（全清即安全）。
- fail-open 取数：记忆是增强不是门禁，取不到时降级为无记忆执行，不能让记忆库故障挡住问数主路径。

## 放弃了什么

- 自动学习/隐式提取（透明性与审计代价不可控）；
- 存数据值的「结果缓存」式记忆（引入第二个需要权限裁剪的数据面）；
- 合同层面承诺自动学习（合同回写只登记已实现的显式登记边界）。

## 重新评估条件

- 内测用户反馈显式登记负担过重、明确要求自动学习时，作为独立产品选择重新裁定（连同审计与清除语义一起设计）；
- 记忆类型三类不够用时，新增类型按「不存数据值」红线逐类评估。
