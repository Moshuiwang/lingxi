# 浏览器验收操作指南

状态：首版操作方法，依据 [Issue #636](https://github.com/Moshuiwang/lingxi/issues/636)。仅固化验收手段，不新增产品承诺。证据等级以[验证与门禁](../技术设计/验证与门禁.md)为准。

## 入口与适用范围

适用于提供浏览器自动化工具、已有授权登录态的本地验收任务。开发提交请求，验收代理通过飞书真实用户入口发送并读取结果。工具由执行环境提供，仓库不保存凭据、不启动另一个机器人长连接；无工具、无登录态或不支持当前标签时记为 BLOCKED。

内置浏览器可用不等于任何子代理或定时任务都能访问它。当前执行者必须实际发现目标标签；禁止用其他账号、另行登录或 API 伪造入站代替。按工具自身文档初始化，以下脚本示例只适用于其暴露的 CUA/Playwright 接口，不是独立 Node 脚本。

## 执行前检查

1. 核对请求版本、受测部署版本、账号别名、机器人、允许副作用及截止条件。正式验收必须绑定实际部署；部署未知时只能出探索记录，不能给候选验收通过结论。
2. 环境负责人确认服务就绪。测试环境未启动时不发送、不空等，不擅自启动被其他任务停止的实例。浏览器能打开不是机器人健康证明。
3. 默认 Bot-Test；仅明确获准的生产只读冒烟可使用 Bot-Prod，不因 stage 不可用自动改测生产。运行中版本改变则本次证据不再覆盖新候选。
4. 一个浏览器同一时刻一个操作人。若用户接管，停止操作；先检查输入框是否有草稿，保留原草稿，不覆盖、不发送。

## 账号与机器人选择

在当前已登录页面发现账号切换入口和置顶会话，不能只凭头像、序号、上次 URL 或聊天历史识别身份。具体姓名、组织与租户映射由受限测试请求提供，公开报告用业务用户/管理员别名。

当前飞书页面已验证的定位方式（DOM 改版后重新发现）：

| 目标 | 选择方式 | 完成条件 |
|---|---|---|
| 当前身份 | `.navHeader_avatar` 打开资料菜单 | 姓名和组织均与请求一致，核对后收起菜单 |
| 账号切换 | `.user-auth-list_itemBox`，当前项带 `.user-auth-list_itemBox-active` | 等导航和消息区加载，再读资料确认身份 |
| 机器人 | 置顶 `region` 的 `scrollable content` 内按完整名称精确选择 | 聊天标题和输入框接收对象均吻合 |

已发现且恰好只有两个账号时，非 active 项可用于切到另一个；账号数增加或身份不明确时停止该捷径。正式机器人显示 `BI Plus`，测试机器人显示 `BI-Plus-测试用机器人`，每次仍须实时核对。

账号切换与会话切换允许分别等待最多 30 秒（执行预算，不是产品 SLA），按页面实际就绪提前结束；跨域加载期间重新获取定位器。资料菜单打开时第一次点击会话可能只关闭菜单，必须先收起再选择。工具报超时也先独立回读，不盲目重按。

## 每轮输入输出与计时

每轮记录 UTC 时间及毫秒差值：开始准备、账号就绪、聊天就绪、输入完成、发送前、发出确认、首次回应、最终结果、核对完成、报告回读完成。未观测到的时间写 null，不能填 0 或推算成精确时刻。

- 准备时间包括宽裕的账号/会话等待；不混入服务响应时间。
- 用户等待从发送前到首次回应/最终结果分别计算；表情、排队提示、正文终态分别标记，不能把表情当最终结果。
- 记录每次观察区间，浏览器时间是“首次观察到”，不是后台事件时间。工具内部计时不含派发到工具开始之前的开销；整条 case 还须记录领取到报告交回的时间。
- 关联新输入消息 ID、新输出消息 ID、所在会话及回复引用。同一请求重试增加 attempt，不覆盖失败记录。发送结果不明时先回读；已发未回复不得自动补发。
- 只读取本次消息；新挂载的旧历史、侧栏摘要、自己刚发出的文字不算机器人回应。首次结果之后继续等对应卡片的最终状态，不能全页搜索“已完成”。
- 服务处理、排队、MCP 和投递分段需要后台同号时间线；仅有浏览器证据时保留为合计，不能猜测根因。

## 可复用脚本步骤

以下是在已核对身份、机器人和空白输入框后执行的片段。`tab` 来自执行工具当前文档的标签发现步骤。先读输入，再发送一次；每个动作后按工具要求取得最新状态。

```javascript
const editor = tab.playwright.locator('div[contenteditable="true"]');
if (await editor.count() !== 1) throw new Error('输入框不唯一');
const draft = await editor.locator('[data-string="true"]').allTextContents({});
if (draft.join('').replace(/\u200b/g, '').trim()) throw new Error('存在草稿');
const startedAt = Date.now();
const oldIds = await tab.playwright.locator('.js-message-item[id]')
  .evaluateAll(es => es.map(e => e.id));
if (!oldIds.length || oldIds.some(id => !/^\d+$/.test(id))) {
  throw new Error('消息基线未就绪');
}
await editor.pressSequentially('/admin help');
await editor.locator('[data-string="true"]').filter({hasText:'/admin help'})
  .waitFor({state:'visible', timeoutMs:3000});
const input = await editor.locator('[data-string="true"]').allTextContents({});
if (input.join('').replace(/\u200b/g, '') !== '/admin help') {
  throw new Error('输入不一致，停止发送并检查草稿');
}
const sendAt = Date.now();
await editor.press('Enter');
await tab.getAXState({emit:false});
const fresh = '.js-message-item[id]' + oldIds.map(id => `:not([id="${id}"])`).join('');
await tab.playwright.locator(fresh).filter({hasText:'当前角色：'}).first()
  .waitFor({state:'visible', timeoutMs:5000});
const observedAt = Date.now();
const messages = await tab.playwright.locator(fresh)
  .evaluateAll(es => es.map(e => ({id:e.id, text:e.innerText})));
// 接下来核对消息发言方、引用和正文；messages 是待判证据，不自动等于 PASS。
nodeRepl.write({startedAt, sendAt, observedAt, messages});
```

这段只覆盖帮助样例：无回复时等待会抛出超时，停止并回读，不能重跑整个片段。若需要继续观察，保留 oldIds/sendAt，在请求的绝对截止时间前只重试读取；单次等待控制在工具允许上限内，不能借由循环延长总预算。真实权限、数据和交付用例需要各自的终态/回源断言，不能套用“当前角色”条件。

富文本框不能把占位文字当草稿；通用 fill 在实测中出现状态不同步，优先用键盘事件和文字回读。CDP 可用于页面诊断，但不直接篡改页面来制造通过结果，不抓取凭据。截图只用于布局、显示异常及脱敏后的失败证据。

## 首批用例

这里只增加执行配方，不复制产品规则，不翻转既有矩阵状态。一次帮助通过不能代表整行断言通过。

| Case | 输入/操作 | 预期及证据范围 |
|---|---|---|
| B00 | 两个已授权账号各选两机器人，不发送 | 姓名/组织、聊天标题和接收框一致；验收工具前置，无新增产品断言 |
| A01 | 管理员 `/admin help` | 新回复含帮助和角色；只验证 [V-管理-26](../技术设计/验收矩阵-接入与管理.md) 的帮助入口，不证明注入防线或审计 |
| Q01 | 明确公司、指标、绝对日期的单次问数 | 公司/指标/单位/日期符合请求，关键数字与独立基准相符；依据[可信标准](../产品合同与外部边界.md#问数结果的可信标准)，基准缺失记数值未核验 |
| Q02 | 接 Q01，明确追问某维度 | 沿用正确上下文，不混其他用户/话题；依据[会话分册](../技术设计/验收矩阵-会话与执行.md)，认领时选择相应 V-会话 行 |
| D01 | 将已核对结果整理为文档 | 链接可打开、正文一致、本人权限正确；依据[交付分册](../技术设计/验收矩阵-交付与投递.md)，建档成功提示不能代替打开和权限回读 |
| S01 | 将已核对结果整理为电子表格 | 表头、行数和关键单元格正确，打开及权限回读；依据同一交付分册 |

Q01/Q02/D01/S01 在请求 READY 前填明具体 V-*、输入和基准；目前是待实例化配方，不是已执行清单。首批不包括停用、扩权、删除或故障注入；这些必须另行明确对象、副作用、审批和恢复方案。

## 请求与结果交接

沿用 Issue/PR，不建新平台；开发完成部署后发布请求，验收代理领取并写 RUNNING。当前为人工唤起执行，没有自动监听或全天候可用承诺。开发终端不是唯一收件箱，报告不会自动注入其他开发会话。

请求最少字段：`request_id`、`revision`、来源工作项、候选 SHA、部署制品、环境、账号别名、机器人、case/断言、精确输入、预期/独立基准引用、允许副作用、等待预算、清理责任。缺项时 BLOCKED；探索记录可声明部署未知，但不得标记发布验收 PASS。

结果模板（每 case/attempt 一份）：

```text
request_id / revision / case_id / attempt:
执行者与模型 / 环境 / 账号别名 / 机器人:
候选 SHA / 实际部署 / 版本核对时间:
状态: PASS | FAIL | BLOCKED | NOT_RUN
开始 / 账号就绪 / 聊天就绪 / 输入完成 / 发送前 / 发出确认:
首次回应 / 最终结果 / 核对完成 / 报告回读完成:
输入、输出与消息关联的受限证据引用:
预期 / 实际 / 逐项结论 / 未核验项:
准备 / 首响应 / 最终响应 / 核对报告 / 总时间:
异常、恢复与清理:
证据层级及不能支持的结论:
```

同一请求版本仅一个执行者，领取写有效期；到期或中断接手前先核对是否已经发送。重试另记 attempt，部署变化需新 revision。提交后读回报告。公开 Issue/PR 只放脱敏状态和差异；业务数据、姓名邮箱、聊天截图及内部地址不公开，受限证据须能由指定接手者访问，不能只给另一台机器的本地路径。

## 首版证据与限制

2026-09-06 已观察到四个账号/机器人组合可切换；脚本帮助请求收到新回复，复用样例单次工具内约 3.54 秒（不含报告）；服务停止时无回复。它们是方法探索样本，未绑定部署 SHA，不据此升级产品当前能力、矩阵状态或响应 SLA。完整原始业务内容不入仓库，脱敏交接演练见 #636。

收口时清理自建标签、进程和临时 worktree；原有用户标签保留。需要保留的测试产物登记用途、清理责任和方法，不自动删除用户聊天或既有产物。
