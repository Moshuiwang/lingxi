# 浏览器验收案例库

状态：首版，依据 [Issue #641](https://github.com/Moshuiwang/lingxi/issues/641)（BA-001 首跑，[#640](https://github.com/Moshuiwang/lingxi/issues/640)）。收录**跑过并验证有效**的浏览器实测用例，供下次请求直接引用而不必从零设计。方法与格式正文见[浏览器验收指南](浏览器验收.md)；本文件不复制该指南的操作细则，只登记具体 case 的判定要点。

沿用[浏览器验收指南「适用判据」](浏览器验收.md#适用判据什么时候必须用浏览器实测)：引用本库任一 case 前，先确认它确实需要飞书真实验真，不要把已能用接口或数据库只读回源验证的部分也占浏览器实测预算——下表逐条标注了这一点。

## N01：先行关卡（建议所有浏览器实测请求都先跑）

验证工具自身是否会把旧回复误判为新回复，成本约 3 秒，收益是「工具会不会说谎」有答案。BA-001 首跑靠这一条抓到真实假 PASS 缺陷（同一会话上一条 `/admin help` 旧回复仍在页面上，N01 不发新消息、断言替换为指定不存在文案，等待器如实报 `matchCount=0` 超时，没有把旧回复判成新回复）。

## 引用须知

- 表中「取证方法」是判定成立所需的**最小组合**，不是必须全上；引用时按当前请求实际可用的证据通道裁剪。
- 「已知耗时」是浏览器观察上界，包含工具自身开销，不是后台精确处理时延；不能直接当 SLA 使用。
- A02、A03 已按 [#641](https://github.com/Moshuiwang/lingxi/issues/641) 的判据复核为「本可只读回源」，保留在本库仅供追溯该次实测的完整证据链，**新请求不应再为这两类断言申请浏览器实测**。
- 新增已验证用例时，追加一行并标注来源 request_id；不覆盖已有行的历史结论。
