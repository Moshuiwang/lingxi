> 原配套的 MVP 联合验收执行卡（一次性资产）已于 2026-08-23 执行完毕并随 2026-08-24 维护批退场，存档见 [git 历史](https://github.com/Moshuiwang/lingxi/blob/256a905c5f370ab8c13f77c11a2cb6416badd6b2/docs/参考证据/MVP联合验收执行卡.md)；本单是可复用资产，后续验收窗口配新执行卡使用——执行卡回答"按什么顺序、谁操作、多长时间、失败怎么办"，本单回答"完整员工路径里有哪些点必须逐一确认，一个都不能漏"。

>
> ## ⚠ 2026-08-20 裁定：本轮正向旅程**预期停在「等待同步」**，不是缺陷
>
> 产品负责人 2026-08-20 **接受 Epic D 验收降级**：本轮正向旅程**只验到「权限已发布、等待同步」为止**，「**开通完成**」这个终态**留到硬切（[#263](https://github.com/Moshuiwang/lingxi/issues/263)）之后**再验。
>
> 原因（回源事实）：就绪判据是「用该用户自己的令牌对问数 MCP 跑一次 `list_metrics`、可见指标数大于零」，而 MCP **每 15 分钟从正式权限表拉数据**；本轮**不会**真的往正式表写 Lingxi 的行（旧系统仍在写，需先硬切）。
>
> **因此 A3（开通完成文案）、B4（`list_metrics` 就绪）、B5（同步节奏）、C1（开通后正常问数）这几行本轮必然勾不上——这是已批准的范围收缩，不是新发现的缺陷。** 不要据此排查，也不要强行凑数勾选；在证据记录里按「本轮不覆盖，待 #263 后复验」登记。
>
> 其余各行（负向匹配、超时/故障分支、幂等、正文生命周期、并发与隔离）**不受此降级影响，照常逐行勾选**。

## 范围与不覆盖

- **覆盖**：飞书私聊入口的完整员工可见路径——开通、匹配两个出口、权限发布与同步、问数与多轮对话、结果投递与正文生命周期、Epic E 新增的并发/隔离/重连/重投验收点。
- **不覆盖**：管理员通过 AI Agent 的管理路径（不在 #161 的联合验收授权范围内，另有独立验收合同）、JumpServer 高级工作台（同上）。
- **正式产物（飞书文档/表格/图片）当前失败关闭，等待 [#140](https://github.com/Moshuiwang/lingxi/issues/140)**：本单只验证"失败关闭且不阻塞普通问数正文"这一中间态，不宣称、不验证正式产物已可交付。
- 本单不含任何真实账号标识、内部主机名或内部路由；三个测试身份一律使用化名 **P1**（产品负责人本人企业账号，正向）、**B**（专用授权主体本体，设计性负向）、**N1**（产品负责人个人租户账号，负向）。

## 使用方法

1. 每一行独立勾选；勾选前必须已经拿到该行要求的证据（Issue/PR 评论链接、脱敏截图或数据库回读片段），不得凭记忆勾选。
2. 「观测通道」列出该行断言可用的三个候选通道（页面观察 / 平台 API 回读 / 服务端结构化日志），按 #147 现行方法的「用户可见断言双通道观测」要求**任取其二**且结论一致才可勾选；只做到一个通道时，在证据记录里写明"单通道，另一通道原因"，不得直接勾选为通过，需升级产品负责人裁定并记为「证据对应性问题」而非直接判失败。
3. 「断言」列给出可追溯的 `V-*` 编号或产品合同章节，供事后复核；本单不复制断言正文，正文见[产品验收矩阵](../技术设计/验收矩阵.md)与[产品合同与外部边界](../产品合同与外部边界.md)。
4. 任何一行出现与预期不符的现象，立即停止该分组的后续行、按执行卡对应阶段的「失败怎么办」处理，不得跳过继续勾后面的行再回头补。
5. 本单每一行默认由**编排者**在受控环境操作，仅当明确标注人员化名（P1/B/N1）时才需要产品负责人亲自动手；未标注的行编排者可以提前独立完成，不占用产品负责人的窗口时间。
