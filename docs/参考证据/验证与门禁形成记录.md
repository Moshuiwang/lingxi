# 验证与门禁形成记录

> 状态：历史依据，最后整理于 2026-08-06。本文只解释现行门禁为什么形成，不定义当前规则，不证明当前提交已经通过任何断言。

现行断言、证据层级和执行要求只看[验证与门禁](../技术设计/验证与门禁.md)；已经具备和仍未验证的能力只看[当前能力](../当前能力.md)。本文中的日期、版本、数量和提交状态都是当时快照，使用前必须重新核对。

## 为什么门禁必须属于仓库

- [PR #12](https://github.com/Moshuiwang/lingxi/pull/12) 自审发现，“同一话题只跑一个任务”曾被实现成对主键 `id` 再建唯一索引。该索引没有新增约束，第二个任务仍可能覆盖第一个；问题只因当次代理临时运行真实 PostgreSQL 才暴露，当时没有仓库规则要求这样做。
- `scripts/ci/verify_repository.sh` 曾因本机缺少 `shellcheck` 而使两名代理先后只运行部分检查。后来确认 `shellcheck-py` 可在无 root 环境安装，也由此形成“缺工具必须明确失败、报告版本、本机与 CI 不得静默分叉”的要求。

两件事说明：验证不能依赖某个代理刚好想到什么；稳定检查必须进入仓库，并在不满足时可靠变红。

## L4a 与最小真实执行链路

初稿曾把 L4 整体交给真人执行。为避免把可自动化验证变成人工等待，后来拆成代理驱动的 L4a 和确实需要真人的 L4b；二者都使用真实外部系统，证据强度不因执行者不同而降低。

2026-07-28 的 [Issue #23](https://github.com/Moshuiwang/lingxi/issues/23) 在 `biai-stage` 验证了 Agent SDK + 百炼的最小真实链路：

| 探针 | 当时结果 |
|---|---|
| 真实百炼端点启动和恢复会话，取得非空正文与唯一终止结果 | 40/40 回合成立；39 个正式回合正文与结果哈希一致 |
| 测试身份调用真实只读 MCP | 40 回合共取得 189 次工具调用与回执，覆盖 4 个只读工具 |
| 隔离 cwd、只读 Skill、无用户环境凭据 | 4 个回合实际加载 Skill |
| `PreToolUse`、`PostToolUse`、`PostToolUseFailure` 与 `Stop` | 常规回合及两次工具抛错补测均取得对应事件 |
| 默认拒绝的越界探针 | 3 次非白名单调用均在执行前被拒，无文件或 cron 副作用 |
| 证据脱敏 | 只保留字段名、计数、长度与哈希，不保存凭据 |

这轮只证明当时组合的机制可行，不自动覆盖后来修改过的执行器、审计归类或当前候选提交。它同时暴露两条长期约束：MCP 正常响应也可能是业务失败，审计必须自行解析回执并合成；只读边界必须由执行层默认拒绝，不能依赖 SDK 工具列表或提示词。

## 断言怎样补齐

- 2026-07-28 普通员工不再经过授权卡片或浏览器 OAuth 后，原来的身份断言随路径作废，`V-身份-01…04` 重新分配。旧同号“已验证”记录因此不能继续引用。
- Issue #29 的独立复查发现过判定绕过无留痕、记账异常带走拒绝、同名回执挂错、跨回合污染、分类随哈希顺序变化和 SDK 绑定零测试等问题，形成 `V-执行-10…16`。
- `V-执行-17` 来自同一类归类问题的第三层：单次调用归类正确，不代表回合合成正确。一次辅助调用成功曾把同回合的业务失败覆盖为 `OBTAINED`，因此混合回合必须保守处理。
- “开通与匹配”初稿漏掉了先占位、模糊匹配、错误生成人工待办和非法状态回退四类拒绝路径，促成每条“不得”规则都要有会变红的否定断言。
- `V-审计-03` 的两个残余缺口曾经产品负责人知情接受：自由文本中的纯字母短秘密无法被长度规则识别；合法形态的未知工具名保留在审计核心。后续 `V-执行-20` 收紧了 worker 出口，但没有假装关闭审计核心缺口。

这些经过只用于解释编号和边界；当前行为以主文的 `V-*` 行为、层级与状态列为准。

## 部署与本机门禁怎样补齐

Issue #29 暴露了三类只存在于散文、没有实际门禁的要求：安全边界依赖的 Agent SDK 与 CLI 未声明版本；门禁使用裸 `python3`，CI 恰好满足而本机可能低于项目下限；测试只覆盖源码目录，无法证明安装制品包含新增模块。由此形成 `V-部署-08/09/10`。

教训是：要求审查者“说明某件事”只会产生一段文字。可自动化的合并要求必须有 `V-*` 编号和实际会变红的 CI 检查，否则仍只是提醒。

本机门禁随后增加了解释器下限检查、ShellCheck 版本输出和真库半开状态守卫。长期目标仍是让新代理用一条命令得到与 CI 同构的结论；尚未完成的容器化入口属于实施工作，不应在历史记录里写成已具备。
