# 研发快速开始

状态：当前开发入口；最后核对：2026-09-05。

适用范围：新代理或新机器第一次进入本仓库，完成环境确认和本机检查。本入口形成依据 [Issue #598](https://github.com/Moshuiwang/lingxi/issues/598)，长期内容维护在仓库文档中；不替代[产品合同与外部边界](产品合同与外部边界.md)、[验证与门禁](技术设计/验证与门禁.md)或[协作约定](协作约定.md)。

## 最短路径

先按 [AGENTS.md](../AGENTS.md) 读取本次任务需要的规则。进入仓库根目录后的首条命令是：

```bash
git status --short --branch
```

先确认当前分支和已有改动，保留已有工作，然后检查：

```bash
bash --version
python3 scripts/dev/gate_spec.py fast
```

仓库脚本要求 Bash ≥ 4.3。第二条命令读取当前 Story Fast 配方；完整 gate 使用 `gate_spec.py gate`。根据输出的 `PYTHON_VERSION` 检查对应解释器，例如输出 `3.12` 时运行 `python3.12 --version`。版本以目标 workflow 为准，不从 `pyproject.toml` 的范围声明推断；入口会选择对应解释器并回读虚拟环境版本。

首次检查明确运行文档层，避免无改动时自动入口直接选择 `full`：

```bash
scripts/dev/check.sh docs
```

确认有代码改动后，再按需要运行 `scripts/dev/check.sh fast` 或 `scripts/dev/check.sh full`。需要了解分类时再用 `scripts/dev/check.sh --print-mode --base main`；无参数入口会按改动自动分层，工作树无改动时会选 `full`。

## 结果能证明什么

| 层级 | 本机入口与 CI 对应 | 结果可以说明 | 不能据此说明 |
| --- | --- | --- | --- |
| `docs` | `scripts/ci/verify_docs.sh`；Story / docs 或 Epic Full / docs | 文档链接和文档门禁通过；不装依赖、不启动数据库或 Docker | 代码、运行时或发布制品通过 |
| `fast` | `scripts/dev/check.sh fast`；Story Fast / code fast | 按 Story workflow 配方完成快速仓库检查；不启动真库、不构建镜像 | 完整 Epic Full、镜像、部署或外部验收通过 |
| `full` | `scripts/dev/check.sh full`；仅 Epic Full / gate | 本机 gate、一次性本地真库和静态部署契约检查通过 | Epic Full 的 extras、image 以及真实外部系统验收通过 |

本机 `full` 只覆盖 Epic Full 的 gate 作业，不能替代完整 CI；现行边界和其他作业见[验证与门禁](技术设计/验证与门禁.md)。

## 依赖从哪里来

不要在本入口维护另一份版本表。`scripts/dev/check.sh` 通过 `scripts/dev/gate_spec.py` 读取 workflow 中的 Python、extras、shellcheck 和真库参数；workflow 改动后下一次运行随检出版本更新。手动准备环境时照当前目标 workflow 的 `setup-python` 和 `pip install` 步骤执行，不自行添加包来让检查变绿。

`full` 可能创建一次性本地依赖，结束后确认已退出；不要把临时实例、虚拟环境缓存或本机检查结果写成产品能力。

## 常见卡点

- Bash 低于 4.3：先切到满足要求的 Bash 后重试。
- Python 与 workflow 的 `python-version` 不一致：换用匹配的解释器。
- `gate_spec.py` 无法解析 workflow 或缺字段：保留原始错误并交回维护者，不手填旧配方。
- 验证过程显示工作树被改写：先读 `git status --short`，确认新增改动来源后再继续。
- CI 只显示总状态时：打开 Actions 的 job 和 summary，看具体失败步骤、逐镜像结果及产物。

## 并行与交接

并行改动先确认使用独立 worktree、文件路径不重叠。交接按[协作约定](协作约定.md)记录阶段、阻塞、负责人、下一步、验证结果和授权终点；不要把聊天中的临时判断当作共享事实。

## 发布结果怎么看

查看 Actions job summary 的逐镜像条目：明确显示“已推送 GHCR”并带回读 digest，才算镜像已推送；显示“未推送、权限不足，仅 CI artifact”时只有备用包，不能按镜像 tag 拉取。`Main Publish` 总绿灯不能单独证明四个镜像都已进入 GHCR。
