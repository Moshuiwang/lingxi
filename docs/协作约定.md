# 协作约定

仅在多人、跨设备、跨 PR 或高风险变更中读取本文件。普通单人、小型改动不适用。

## 共享事实与领取

- 远端 Git、GitHub Issue / PR / Project 和已推送文档是共享事实；本地未提交内容和聊天记录不是交接依据。
- 主实施代理开始前在父 Issue 留言领取，写明代理、分支和计划，并将 Project 状态设为 `In Progress`。同一变更只能有一个主实施代理。
- 其他代理只领取独立子 Issue，或在父 Issue 做研究/审查；不得并行修改同一变更包或同一代码范围。

## 交接与合并

- 交接前提交、推送，并在 Issue 留下已完成项、验证结果、未完成项、风险、下一步和 commit / PR 链接。
- 协作变更的 PR 链接父 Issue；合并后仅在产品承诺、当前能力或长期决策实际改变时更新相应仓库文档。

## GitHub CI 与验收边界

- 面向 `main` 的 Pull Request 和合并后的推送运行统一的 `CI / gate`；协作者在合并前确认它通过。
- 自动 CI 只运行无网络、无业务系统副作用的仓库检查，不读取业务凭据，不调用 MCP、Claude Code + 百炼、飞书或 JumpServer，也不发送用户消息或交付物。
- `CI / gate` 通过只表示改动满足基础合并条件，不代表产品能力已上线、生产入口可用或真实用户已经收到结果。
- 身份、权限、用户隔离、外部依赖和真实交付行为发生变化时，仍须按 PR 模板完成受控人工验证并留下脱敏证据；只有实际验证确认后，才能更新“当前能力”。
- CI 失败时不得把改动作为已完成工作交接；若检查本身异常，应单独说明原因、影响和恢复验证结果。
