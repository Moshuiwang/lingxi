# 固定部署控制包

本目录说明非秘密安装结构。开发完成与真实安装分别验收；没有实际 SSH 策略、三路身份连接、数据库恢复和发布窗口证据时，不宣称可部署。

控制包按候选提交逐文件打包，索引版本为 1，发布清单版本为 2。包摘要在清单外部绑定，索引列出每个文件的来源提交、大小、权限和摘要；不把包自身摘要写进包形成循环。运行环境固定 Linux、Python 3.11 以上、Docker 与 Compose 2.24 以上，宿主只需标准库，不运行 pip 或构建镜像。版本化代码/relay 安装由 root 部署主体执行，受限 relay 主体与之分离。

`control_bundle.py` 的构建入口只接受固定候选的干净文件。安装先完整校验，再写临时目录、同步文件和目录、原子改名为包摘要目录。所有文件只读，原版本保留；当前引用只在获批执行阶段切换。禁止额外文件、链接、重复路径、路径穿越及异常权限。不扫描打包目录，不复制任何私有环境文件。

宿主材料由 Ops 独立安装并维护：私有 0600 主机契约、非秘密配置、计划与批准；服务凭据仍由 Compose 的外部 env_file 消费。部署器不读取、打印或保存凭据值。受限 SSH 主体无 sudo、Docker 组及宿主配置写权限；forced-command 只能指向冻结 Python 和 relay，不能解释原始 SSH 命令。模板中的账号、公钥和绝对路径都必须在安装步骤外部给定，不是示例实际身份。

`lingxi_deploy.py` 只有 plan/apply/status/recover。计划包含完整旧新清单、非秘密配置摘要、固定工具摘要、恢复兼容证据、迁移头、窗口、资源共存预算、通道 UID/映射/协议及安装收据。批准必须绑定计划摘要与受保护宿主契约允许的工作项来源；它是批准引用，不另建认证系统。执行接续用同一部署 ID、同一批准和原窗口。状态目录固定 0700，文件 0600，原子替换并同步；主机锁位置来自宿主契约，不能换状态目录并发执行。

`plan --dry-run` 只在标准输出显示固定材料，不创建目录、下载、落文件或执行 Docker。正式版本选择应在之前通过同包内 `scripts/ci/release_manifest.py resolve --manifest-output` 完成；生产选择拒绝候选版本，旧 schema 必须显式使用 `--allow-legacy` 作历史核对。历史清单不能成为普通新部署目标；缺兼容恢复证明即停止。

部署期间迁移作业有固定名字。未知/失败作业先回读实际迁移头和活动作业，不盲目重新执行；不会降级数据库、删除卷、清业务阶段或修权限。服务停止遵循现有 gateway 20 秒、scheduler 120 秒共同截止；恢复也启动 mvp 的三个常驻服务。观察要求本次连续 15 分钟，中断后重新计时。恢复计划与批准独立，apply 不能自动恢复。

D4 真实 stage 九处中断、D5 同四镜像及同控制包正式提升、D6 独立生产首用均保留。真实环境尚未执行这些操作。
